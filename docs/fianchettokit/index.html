    FianchettoKit¶

    Fianchetto's chess training logic as one Swift package: engine annotation, strength and Elo estimation, drill generation, spaced repetition, portable persistence, game import, and electronic-board handling — built on ChessCore.

    FianchettoKit depends one-way on the ChessCore package (plus BoardKit for the board adapters) and targets iOS 18 / macOS 15, so it is free to use newer APIs and the networking stack.

    The package holds decisions, not platforms. Its only imports are Foundation, ChessCore, and BoardKit with its board adapters — no SwiftUI, no UIKit, no SwiftData, no CloudKit anywhere in the sources. Storage, engine search, and model inference all sit behind protocols the platform shell implements, so the same code runs in the iOS/macOS app, in the Android (Skip/SkipFuse) port, and in a headless process.

    What's in the kit¶

    Persistence¶

    Page What it covers
    Stores & the storage seam the five stat stores — TacticsRatingStore, TacticsPerformanceStore, RepertoireDrillStats, BlunderMasteryStore, TrainProgressCache — and the JSONBlobStore / BlobBackedStore seam they persist through
    Storage, DTOs & authored history the seam in full, game identity and dedup, and the CRDT that merges user-authored notes and board marks across replicas
    Persistence DTOs the Sendable, SwiftData-free value types — PreparedGameData, RepertoireData, GameCollectionData, PersonalTrapData

    Analysis¶

    Page What it covers
    Engine & annotation turning a game into per-move glyphs, quality labels, and an eval array without naming a concrete engine
    Analysis math AccuracyAggregator, procedural endgame generation, StreakMath
    Strength, Elo & accuracy per-game accuracy, the calibrated EloEstimator, the Kalman StrengthTracker, and the account-local projection onto a provider's rating scale
    Maia policy model Maia3Encoding's tensor codec, MaiaBackfillPolicy's scoring rules, and MaiaRankStyle's tiering — the kit owns the policy, the platform shell owns the inference

    Training¶

    Page What it covers
    Tactics, drills & spaced repetition annotated game → puzzle → graded answer → rating → next due date
    Repertoire, openings & traps naming positions, finding preparation gaps, and mining drillable lines out of your own games
    Endgame mining & the endgame trainer procedurally generated archetype positions, plus content-addressed caching of endgames mined from your games
    Review, play & voice the post-game Review derivations, the human-like move sampler, and the spoken-move stack

    Import, export & devices¶

    Page What it covers
    Network clients & game import the Chess.com / Lichess import walks, their resumable checkpoints, and the explorer and tablebase probes
    Network clients the compact API reference for ChessAPIService, LichessExplorer, and TablebaseService
    Library backup & collections the portable JSON export both platforms read and write, its validator, and duplicate-game reconciliation
    Electronic board integration the BLE board catalog, the transport admission policy, and the effect-returning session core

    Running it headless¶

    fianchetto-cli exposes six of these seams as JSON-Lines filters — annotate, estimate, maia, accuracy, project, and track. It links the same FianchettoKit build the app ships, so a number it prints is the number the app would have computed for that input.

    A quick taste¶

    import ChessCore
import FianchettoKit

// Record a tactics attempt against the Elo store (persisted via the seam).
var ratings = TacticsRatingStore.load(from: blobStore)
let delta = ratings.recordAttempt(
    puzzleKey: BlunderMasteryStore.key(fen: fen, correctSAN: "Qxh7"),
    difficulty: .medium,
    outcome: .correct,
    in: blobStore
)
print("rating \(delta >= 0 ? "+" : "")\(Int(delta))")   // "+12"

// Probe the Lichess tablebase for a 7-man endgame.
let result = try await TablebaseService.shared.probe(fen: endgameFEN)
print(result.category, result.bestMove ?? "—")
