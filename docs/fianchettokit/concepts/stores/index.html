    Stores & the Storage Seam¶

    How the five stat stores compute their numbers and how they all persist through FianchettoKit's one-protocol storage seam.

    The seam, recapped¶

    FianchettoKit defines JSONBlobStore (the backend you implement) and BlobBackedStore (what a Codable store conforms to — a single row keyed by a stable blobKey, with load(from:) / save(to:) provided by a protocol extension). A malformed or missing blob falls back to a fresh init().

    Three stores are BlobBackedStore conformers; two are stateless namespaces that read/write a blob directly:

    Store Kind Blob key
    TacticsRatingStore Codable / BlobBackedStore tacticsRating
    TacticsPerformanceStore Codable / BlobBackedStore tacticsPerformance
    RepertoireDrillStats Codable / BlobBackedStore repertoireDrillStats
    BlunderMasteryStore enum namespace blunderMastery
    TrainProgressCache enum namespace trainProgress.<mode>

    TacticsRatingStore — zero-sum Elo¶

    A standard Elo model with K = 32: the user starts at 1400, each puzzle carries its own rating (seeded by PuzzleDifficulty — easy 1200, medium 1500, hard 1800), and a scored attempt moves the user rating by K · (actual − expected) while moving the puzzle's rating by the equal-and-opposite amount.

    expected = 1 / (1 + 10^((puzzleRating − userRating) / 400))
delta    = 32 · (actual − expected)        // actual: correct = 1, wrong = 0
userRating   += delta
puzzleRating −= delta                       // zero-sum

    var ratings = TacticsRatingStore.load(from: blobStore)

let delta = ratings.recordAttempt(
    puzzleKey: key,
    difficulty: .medium,
    outcome: .correct,         // .skipped is a no-op and returns 0
    in: blobStore
)
// `delta` is the user-rating change — use it for the "+12" / "−9" flash.

ratings.displayUserRating       // rounded current rating
ratings.peakUserRating          // best ever — the "personal best" badge
ratings.relativeDifficulty(for: key)   // .veryEasy ... .veryHard, by the rating gap

    History is capped at 200 points; recordRepertoireAttempt(...) rolls up repertoire performance separately.

    TacticsPerformanceStore — per-attempt history¶

    Keeps the full TacticsAttempt history and derives accuracy, streaks (via StreakMath), median solve time, and per-difficulty / per-mode breakdowns. Capped at 3,000 attempts to stay under CloudKit's ~1 MB record limit.

    var perf = TacticsPerformanceStore.load(from: blobStore)
perf.record(attempt, in: blobStore)

perf.accuracy                       // correct / (correct + wrong)
perf.currentStreak                  // StreakMath.current over the outcomes
perf.bestStreak                     // StreakMath.best
perf.medianSolveSeconds             // median over correct attempts (capped 300s)
perf.recentAccuracy(over: 20)       // rolling window
perf.attempts(since: lastWeek)      // oldest first
perf.difficultyBreakdown()          // ["hard": (correct: 12, wrong: 3), ...]
perf.modeBreakdown()                // by extraction mode (punish / blunders / ...)

    A TacticsAttempt records one puzzle attempt:

    public struct TacticsAttempt: Codable, Identifiable, Sendable, Hashable {
    public var id: UUID
    public var puzzleKey: String        // "<fen>:<correctSAN>"
    public var outcome: Outcome         // .correct | .wrong | .skipped
    public var elapsedSeconds: Double
    public var attemptOrdinal: Int      // 1 = first this session
    public var timestamp: Date
    public var extractionMode: String
    public var difficulty: String
}

    BlunderMasteryStore — spaced repetition¶

    A [String: Int] of consecutive-correct counts keyed by "<fen>:<correctSAN>", for quizzing the user to find the correct move from a flagged position. A correct answer bumps the counter; a wrong answer resets it to 0 so the position resurfaces. A position is mastered — and leaves the due queue — at masteryThreshold (3) consecutive correct.

    let key = BlunderMasteryStore.key(fen: fen, correctSAN: "Qxh7#")

BlunderMasteryStore.record(fen: fen, correctSAN: "Qxh7#", correct: true, in: blobStore)
let count = BlunderMasteryStore.mastery(fen: fen, correctSAN: "Qxh7#", in: blobStore)
if BlunderMasteryStore.isMastered(fen: fen, correctSAN: "Qxh7#", in: blobStore) {
    // drop from the due queue
}
let all = BlunderMasteryStore.history(in: blobStore)   // [String: Int]

    RepertoireDrillStats — per-repertoire history¶

    Aggregates DrillAttempt records per repertoire UUID: accuracy, current/best streak (again via StreakMath), and a last-N sparkline.

    var drills = RepertoireDrillStats.load(from: blobStore)
drills.record(
    .init(correct: true, positionKey: position.positionKey),
    in: repertoireID,
    store: blobStore
)

drills.accuracy(for: repertoireID)
drills.currentStreak(for: repertoireID)
drills.bestStreak(for: repertoireID)
drills.recentOutcomes(for: repertoireID, last: 10)   // [Bool], newest last

    TrainProgressCache — a display hint¶

    A per-PracticeMode snapshot (total, due, mastered) so a drill hub can show meaningful counts on a cold launch without recomputing each drill's pool. It is a device-local display hint — the authoritative mastery history is BlunderMasteryStore.

    TrainProgressCache.record(.init(total: 40, due: 12, mastered: 28),
                          for: .tactics, into: blobStore)
let snap = TrainProgressCache.snapshot(for: .tactics, from: blobStore)

    Training modes¶

    PracticeMode keys the Train drills with stable raw values used for routing, deep links, and per-drill progress keys:

    public enum PracticeMode: String, Sendable, CaseIterable, Codable {
    case study = "Study"
    case repertoire = "Repertoire"
    case tactics = "Tactics"
    case combinations = "Combinations"   // multi-move sacrifices mined from annotated personal games
    case traps = "Traps"
    case endgame = "Endgames"
    case punish = "Punish"   // refute opponents' unsound replies from the repertoire
}

    Pure-logic helpers¶

    • OpeningTrap — a drillable knife-edge opening position; its fenAtTrap resolves the position the user is asked to defend by advancing the stored FEN through the opponent's auto-played move.
    • BoardSyncGate (renamed from SquareOffSyncGate 2026-07-03; now a board-agnostic kernel in BoardKit) — the "physical board diverged from the app" transition (clock pause + a one-shot haptic), as a unit-testable value type. Call update(isOutOfSync:clockIsRunning:currentActiveColor:) each tick and act on the returned Action (.none / .pauseClock / .resumeClock(color:)).
