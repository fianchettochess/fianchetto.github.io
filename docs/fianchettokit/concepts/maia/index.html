    Maia policy model¶

    Maia is a human-move-prediction network conditioned on a player's rating. This page covers the three pure files FianchettoKit owns around it: the tensor codec (Maia3Encoding), the backfill policy that decides what gets scored and how the result is persisted (MaiaBackfillPolicy and the free function logSoftmaxAt), and the rank tiering used to color move lists (MaiaRankStyle).

    What lives in the kit¶

    The kit owns every decision; it owns no inference. Model loading and the tensor round-trip stay in the app — MaiaEngine/CoreML on Apple, an ONNX/LiteRT backend on Android — and both call the same encoder, the same qualification gate, and the same envelope codec.

    Type What it does
    Maia3Encoding Position → 768-float token tensor, Move → policy index, raw logits → EngineAnalysis
    MaiaBackfillPolicy game/position eligibility, owner side, opponent conditioning, the Elo grid, the persisted JSON envelope
    MaiaBackfillPolicy.ScoringContext the resolved per-game contract (side, elo_oppo, source, move-list fingerprint)
    MaiaBackfillPolicy.TargetEvidence the decoded 11-point vector the Elo estimator consumes
    MaiaBackfillPolicy.OpponentConditioning which elo_oppo contract a persisted vector was scored under
    logSoftmaxAt(_:idx:) numerically stable log-softmax at one policy index — the per-position accumulation term
    MaiaRankStyle rank → .best / .good / .moderate / .poor display tier

    Maia3Encoding.swift and MaiaBackfillPolicy.swift import Foundation and ChessCore and nothing else; MaiaRankStyle.swift imports only Foundation. There is no CoreML, no SwiftData, and no SwiftUI in this path, so all of it runs headless.

    Maia3Encoding — board encoding¶

    encodeTokens(position:) produces 64 squares × 12 piece planes = 768 floats, one-hot, always from White's perspective. When Black is to move the board is turned around: ranks are flipped and piece colors are swapped. Files are never mirrored.

    isBlack = (position.activeColor == .black)

for rank in 0..<8, file in 0..<8:
    actualRank = isBlack ? (7 - rank) : rank
    piece      = position[Square(file: file, rank: actualRank)]   // skip if empty
    pieceColor = isBlack ? piece.color.opposite : piece.color
    featureIdx = pieceFeatureIndex(piece.type) + (pieceColor == .white ? 0 : 6)
    sqIdx      = rank * 8 + file
    tokens[sqIdx * 12 + featureIdx] = 1.0

pieceFeatureIndex:  pawn 0, knight 1, bishop 2, rook 3, queen 4, king 5
                    (+6 for the side that is black after the perspective swap)

    let tokens = Maia3Encoding.encodeTokens(position: .initial())
tokens.count                              // 768
tokens.filter { $0 == 1.0 }.count         // 32 — one per piece on the board

    Exactly one feature is set per occupied square, so the number of 1.0 entries is the piece count: 32 for the starting position.

    Maia3Encoding — the policy map¶

    The policy head is 4352 wide: 4096 from-to pairs plus 256 promotion slots.

    Move kind Index Range
    Regular fromSq * 64 + toSq 0–4095
    Promotion 4096 + fromFile * 32 + toFile * 4 + promoIndex 4096–4351 
    isBlack  = (activeColor == .black)
fromRank = isBlack ? (7 - move.from.rank) : move.from.rank
toRank   = isBlack ? (7 - move.to.rank)   : move.to.rank

if move.promotion == nil:
    fromSq = fromRank * 8 + move.from.file
    toSq   = toRank   * 8 + move.to.file
    index  = fromSq * 64 + toSq
else:
    index  = 4096 + move.from.file * 32 + move.to.file * 4 + promotionIndex

promotionIndex:  queen 0, rook 1, bishop 2, knight 3   (anything else → 0)

    Worked example — e2e4 as White. e2 is file 4, rank 1, so fromSq = 1 * 8 + 4 = 12; e4 is file 4, rank 3, so toSq = 3 * 8 + 4 = 28; the index is 12 * 64 + 28 = 796.

    let e2e4 = Move(from: Square(algebraic: "e2")!, to: Square(algebraic: "e4")!, piece: .pawn)
Maia3Encoding.policyIndex(for: e2e4, activeColor: .white)   // 796

    The promotion branch ignores the mirrored ranks

    fromRank and toRank are computed for both branches, but the promotion index is built from files only. A promotion therefore lands on the same index whichever side plays it — promotions are already rank-determined (7 → 8 after mirroring), so the rank carries no information here.

    Maia3Encoding — decoding the output¶

    decodeOutput(moveLogits:valueLogits:position:topK:) turns raw head outputs into a ChessCore EngineAnalysis. It throws in two cases:

    Condition Thrown
    moveLogits.count < 4352 EngineError.predictionFailed("Missing or invalid policy output. Size: \(count)")
    the position has no legal moves EngineError.noLegalMoves

    The value head is optional and is only read when valueLogits is non-nil with at least 3 entries. Its three logits are [loss, draw, win] from the side-to-move's perspective, and the decoder always emits white-POV:

    e0, e1, e2 = exp(Double(v0)), exp(Double(v1)), exp(Double(v2))   // Double: Android
sum        = e0 + e1 + e2                                        // lacks the Float
stmLoss, drawProb, stmWin = e0/sum, e1/sum, e2/sum               // exp overload

activeColor == .black  →  .winDrawLoss(win: stmLoss, draw: drawProb, loss: stmWin)
otherwise              →  .winDrawLoss(win: stmWin,  draw: drawProb, loss: stmLoss)

    The policy is softmaxed over the legal moves only, not over all 4352 outputs, with the usual max subtraction for stability:

    legal   = MoveGenerator.legalMoves(for: position)         // decodeOutput throws if empty
logits  = [ policyLogits[policyIndex(m)] for m in legal ] // indices past the array end are skipped
maxL    = max(logits)
p_i     = exp(l_i - maxL) / Σ_j exp(l_j - maxL)

sort descending by p, take prefix(topK)

    Each survivor becomes an EngineAnalysis.ScoredMove(move:notation:probability:) with SAN from MoveGenerator.algebraicNotation(for:in:).

    var logits = [Float](repeating: 0, count: 4352)
logits[796] = 10                                      // e2e4

let analysis = try Maia3Encoding.decodeOutput(
    moveLogits: logits,
    valueLogits: nil,
    position: .initial(),
    topK: 3
)
analysis.topMoves.first?.notation                     // "e4"
analysis.topMoves.first?.probability                  // softmax over the 20 legal moves

    logSoftmaxAt — the accumulation term¶

    public func logSoftmaxAt(_ logits: [Float], idx: Int) -> Double?

    A free function (not a member of either enum). It is the single term the backfill sums: the log-probability the network assigned to the move the player actually made.

    guard 0 <= idx < logits.count                     else nil
maxValue = logits[0];  guard maxValue.isFinite    else nil
for value in logits:  guard value.isFinite else nil;  maxValue = max(maxValue, value)

exponentialSum = Σ exp(Double(value) - Double(maxValue))
result         = Double(logits[idx]) - (Double(maxValue) + log(exponentialSum))
guard result.isFinite                             else nil

    It returns nil in three situations: an out-of-range index, any non-finite logit anywhere in the array, and a non-finite result. These iOS finite-validation semantics are the canonical ones — Android previously returned -Double.infinity for out-of-range indices and did not validate the logits at all, which turned a broken inference into a plausible-looking very negative number.

    One nil aborts the whole vector

    Callers propagate nil as a throw and discard all 11 grid points. Zeroing or skipping a single term would bias exactly one Elo point of the sweep relative to the other ten, and — worse — would produce a structurally valid envelope that never requeues. Failing the whole game leaves it eligible for a retry.

    The backfill contract¶

    Constant Value
    eloGrid [600, 800, 1000, 1200, 1400, 1600, 1800, 2000, 2200, 2400, 2600]
    expectedVectorLength eloGrid.count — 11
    neutralOpponentElo 1_500 (Float)
    trainedOpponentEloRange 400...3_200
    targetEvidenceContractID "maia3-v4.1-owner-moves-elo-sweep-v1"
    targetEvidenceSchemaVersion 1

    eloGrid is not a literal in the policy: it is read at runtime from EloCalibrationData.v41ensembleModel(forRawTC: TimeControlClass.blitz.rawValue)?.eloGrid so the policy cannot drift from the calibration artifact it feeds. The literal array above is the fallback if that model is somehow unavailable.

    targetEvidenceContractID binds persisted evidence to a model and a serving contract. Bump it whenever the model's outputs, the Elo grid, the move scope, or the conditioning semantics change — every stored envelope then fails validation and requeues by itself. The current Apple .mlpackage component hashes and the Android ONNX hash are pinned against this same value in ModelContracts/maia-target-evidence-assets.registry; updating a hash there without bumping the contract is safe only for byte-level repackaging whose numerical equivalence was established explicitly.

    Which games get scored¶

    isCandidateForBackfill = statisticsEnabled && hasAnnotationEvals && !hasMaiaVector
isEligibleForBackfill  = isCandidateForBackfill && isEligible(tc:)

    isCandidateForBackfill(statisticsEnabled:hasAnnotationEvals:hasMaiaVector:) is the cheap pre-check the scheduler runs before parsing PGN tags; isEligibleForBackfill(statisticsEnabled:hasAnnotationEvals:hasMaiaVector:tc:) is the same thing once the time-control tag has been classified.

    statisticsEnabled is the user-facing "Include in My Stats" collection toggle — persisted as includeInOpeningBook on Apple and includeInStats on Android. Maia vectors refine only the statistics projection, so an opted-out collection must never consume model inference on either platform.

    Time control isEligible(tc:) Estimator route
    .bullet true v4.1 ensemble (with Maia)
    .blitz true v4.1 ensemble
    .rapid true v4.1 ensemble
    .classical true v4.1 ensemble — Maia contributes +115.6 Elo in the fit
    .correspondence false v2 binned median, no Maia refinement

    Which positions get scored¶

    qualifiesForInference(plyIndex:legalMoveCount:)  ==  plyIndex >= 8 && legalMoveCount > 2

    That is an exact mirror of the training collector's gate in collect_ensemble_corpus.py (if ply >= skip_plies and legal > 2: with skip_plies = 8): skip the first eight half-moves, which are mostly memorized book, and skip near-forced positions, where any model looks like any human. plyIndex is 0-indexed — ply 0 is the position before White's first move — and the legal count comes from MoveGenerator.legalMoves(for:).count, which is strict-legal and matches python-chess.

    Two walks apply the gate over a parsed main line:

    // Every qualifying position in the game.
MaiaBackfillPolicy.qualifyingPositions(from: parsed.moves)

// Only positions where the account owner is to move — the shape the training
// corpus used (one record per player).
MaiaBackfillPolicy.qualifyingPositions(from: parsed.moves, playerColor: .white)

    Both return [(plyIndex: Int, move: Move, positionBefore: Position)] in ply order. The owner-only overload exists because scoring both sides would mix the opponent's playing style into the cached vector; the fitted coefficients assume one player's moves.

    Golden fixtures

    Ruy Lopez, Morphy Defence — 1. e4 e5 2. Nf3 Nc6 3. Bb5 a6 4. Ba4 Nf6 5. O-O Be7 6. Re1 b5 7. Bb3 d6 8. c3 O-O (16 plies) yields 8 qualifying positions at plies 8–15 with legal-move counts [27, 30, 25, 30, 25, 30, 27, 33]. The White-only walk returns plies [8, 10, 12, 14], Black-only [9, 11, 13, 15]. Scholar's mate (1. e4 e5 2. Qh5 Nc6 3. Bc4 Nf6 4. Qxf7#, 7 plies) yields zero — every ply is below the threshold.

    Owner side and opponent conditioning¶

    scoringContext(white:black:username:source:moveText:tagsJSON:whiteElo:blackElo:) resolves everything needed to score one game, or returns nil if the game is out of domain.

    1. Domain gate (from tagsJSON via GameTagCodec.decode):
      SetUp != "1"  AND  FEN tag empty  AND  Variant empty or "standard"
2. Owner side:  PieceColor.ofUser(white:black:username:)
      nil when the username matches neither player, or both → return nil
3. Opponent Elo + conditioning:
      exactOpponentElo = (playerColor == .white) ? blackElo : whiteElo
      canonicalSource  = OnlineGameSourceIdentity.canonical(source)
                         ?? (trimmed+lowercased source, or "unknown" if empty)

      if canonicalSource == "lichess"
         && exactOpponentElo != nil
         && (400...3_200).contains(exactOpponentElo):
             opponentElo = Float(exactOpponentElo);  conditioning = .exactLichess
      else:
             opponentElo = 1_500;                    conditioning = .neutralLichessPrior

    The rating-scale argument is the whole reason for the branch. Maia's elo_oppo input was trained on Lichess ratings; a Chess.com rating of 1650 is not the same strength as a Lichess 1650, and feeding it in would silently shift the conditioning. The neutral 1500 prior is deliberately explicit and stays until a provider calibration can map other scales onto Maia's domain.

    ScoringContext field Meaning
    playerColor which side is the account owner
    opponentElo the elo_oppo value to feed the model
    ownerUsername trimmed + lowercased
    source canonicalized ("lichess", "chesscom", else lowercased or "unknown")
    opponentConditioning .exactLichess or .neutralLichessPrior
    inputFingerprint 64 hex characters binding the evidence to the exact move list

    The fingerprint is a PortableSHA256.Hasher fed length-prefixed UTF-8 in a fixed order:

    tokens      = PGNParser.tokenize(PreparedGameData.normalizeForParsing(moveText))
mainLineSAN = PGNParser.flatMoves(from: tokens)

update(lengthPrefixedUTF8: targetEvidenceContractID)
update(lengthPrefixedUTF8: playerColor == .white ? "white" : "black")
for san in mainLineSAN: update(lengthPrefixedUTF8: san)
hexDigest()                                    // 64 hex characters

    Length prefixing means no concatenation of adjacent SAN tokens can collide, and including the contract ID means a contract bump changes every fingerprint.

    Driving a sweep¶

    The scorer is app-side, but its shape is fixed by this policy: encode each qualifying owner position once, then sweep elo_self across the 11 grid points with elo_oppo held at the context's value.

    let parsed = PGNParser.mainLineSnapshot(fromMoveText: moveText)

guard let context = MaiaBackfillPolicy.scoringContext(
    white: game.white,
    black: game.black,
    username: account.username,
    source: collection.source,
    moveText: moveText,
    tagsJSON: game.tagsJSON,
    whiteElo: whiteElo,
    blackElo: blackElo
) else { return }                       // out of domain, or ambiguous account

let qualifying = MaiaBackfillPolicy.qualifyingPositions(
    from: parsed.moves,
    playerColor: context.playerColor
)
guard !qualifying.isEmpty else {
    // Terminal receipt: valid game, but no owner move survives the filters.
    persist(MaiaBackfillPolicy.encodeNoQualifyingOwnerMoves(context: context))
    return
}

// Encode once, reuse across all 11 grid points.
let encodings: [(policyIndex: Int, tokens: [Float])] = try qualifying.map { entry in
    let tokens = Maia3Encoding.encodeTokens(position: entry.positionBefore)
    let index = Maia3Encoding.policyIndex(
        for: entry.move,
        activeColor: entry.positionBefore.activeColor
    )
    guard tokens.count == 768, (0..<4352).contains(index) else { throw ScoringError.invalidEncoding }
    return (policyIndex: index, tokens: tokens)
}

var logLikes = [Double](repeating: 0, count: MaiaBackfillPolicy.expectedVectorLength)
for (gridIndex, eloSelf) in MaiaBackfillPolicy.eloGrid.enumerated() {
    for encoding in encodings {
        let logits = try infer(encoding.tokens, Float(eloSelf), context.opponentElo)
        guard let term = logSoftmaxAt(logits, idx: encoding.policyIndex) else {
            throw ScoringError.missingOutput          // abort the whole vector
        }
        logLikes[gridIndex] += term
    }
}

let json = MaiaBackfillPolicy.encodeTargetEvidence(
    logLikes,
    context: context,
    eligibleMoveCount: encodings.count
)

    encodeTargetEvidence(_:context:eligibleMoveCount:) returns nil — refusing to persist — unless the vector has exactly 11 entries, every entry is finite, and eligibleMoveCount > 0.

    Available from the command line: fianchetto-cli maia.

    The evidence envelope¶

    The persisted JSON is a 12-key envelope, not a bare array:

    {
  "schemaVersion": 1,
  "contractID": "maia3-v4.1-owner-moves-elo-sweep-v1",
  "moveScope": "account-owner-only",
  "playerColor": "white",
  "ownerUsername": "magnus",
  "source": "lichess",
  "opponentConditioning": "exact-lichess-opponent",
  "opponentElo": 1873,
  "inputFingerprint": "9f2c…64 hex characters total…1ab7",
  "eligibleMoveCount": 24,
  "logLikes": [-71.2, -64.8, -59.1, -55.0, -52.3, -51.4, -52.9, -55.8, -60.2, -65.7, -72.4],
  "status": "scored"
}

    Structural validation (decodeTargetEvidenceEnvelope, applied before any context check) requires all of:

    • schemaVersion == 1 and contractID == targetEvidenceContractID
    • moveScope == "account-owner-only"
    • playerColor is "white" or "black"
    • ownerUsername non-empty
    • source is already canonical (normalizedEvidenceSource(source) == source)
    • opponentElo finite and > 0
    • inputFingerprint.count == 64
    • every value in logLikes finite

    then a status-dependent shape check, then a conditioning cross-check:

    status Requires
    "scored" (or absent) eligibleMoveCount > 0 and logLikes.count == 11
    "no-qualifying-owner-moves" eligibleMoveCount == 0 and logLikes empty
    opponentConditioning Requires
    "exact-lichess-opponent" source == "lichess"
    "neutral-lichess-1500" opponentElo == 1500

    A missing status is treated as .scored, because the first generation of scored envelopes predates the field and must stay current. The "no-qualifying-owner-moves" receipt — written by encodeNoQualifyingOwnerMoves(context:) — is a terminal answer, not a failure: the game is valid, the no-Maia estimator serves it, and the scheduler stops retrying an inference that cannot succeed after every cooldown and app launch.

    Legacy bare arrays are rejected here

    encodeVector(_:) / decodeVector(_:) still read and write the old unversioned [Double] form for the retired maiaLogLikesJSON field, and decodeVector only accepts arrays of exactly 11 values. The target-evidence path never accepts a bare array. Those old vectors were scored over both players' moves, so a restored pre-fix backup must requeue rather than masquerade as corrected evidence.

    Staleness and merging¶

    Evidence decodes only when the envelope matches the current scoring context on all six binding fields:

    envelopeMatches  ==  playerColor          == context.playerColor
                  && ownerUsername        == context.ownerUsername
                  && source               == context.source
                  && opponentConditioning == context.opponentConditioning
                  && opponentElo          == context.opponentElo
                  && inputFingerprint     == context.inputFingerprint

    A collection rename, a provider change, the owner switching sides, an edited opponent-rating tag, or any change to the move list therefore invalidates the payload and requeues the game.

    Call Accepts
    decodeTargetEvidence(_:expectedContext:) context-matching envelopes with status == .scored → TargetEvidence
    hasResolvedTargetEvidence(_:expectedContext:) context-matching envelopes with either status → Bool
    isCurrentTargetEvidencePayload(_:) structurally valid envelopes, no context available
    preferredTargetEvidence(live:incoming:) live if valid, else incoming if valid, else nil

    preferredTargetEvidence is the merge rule for backup restore (LibraryBackup.swift:201) and duplicate reconciliation (LibraryGameReconciliation.swift:533), where the destination collection's context is not yet known. Live authority wins whenever both sides are structurally valid, because the scheduler later applies the stronger context check and recomputes if the live payload turns out to be stale.

    // Reading it back on the stats path.
guard let context = MaiaBackfillPolicy.scoringContext(
    white: game.white, black: game.black,
    username: candidate.username, source: candidate.source,
    moveText: game.moveText, tagsJSON: game.tagsJSON,
    whiteElo: whiteElo, blackElo: blackElo
) else { return nil }

let evidence = MaiaBackfillPolicy.decodeTargetEvidence(
    game.maiaTargetEvidenceV1JSON,
    expectedContext: context
)

let performance = EloEstimator.estimate(
    evalsJSON: game.annotationEvalsJSON,
    startIsWhite: true,
    color: context.playerColor,
    tc: .blitz,
    maiaEvidence: evidence,        // nil → the no-Maia v4.1 fallback
    termination: tags["Termination"]
)

    That is exactly what StatsKernel does per game before building the Elo history. TargetEvidence carries logLikes, eligibleMoveCount, and opponentConditioning; the shipped coefficients consume the sums, not per-move means, so eligibleMoveCount is diagnostic metadata rather than a divisor. The conditioning case selects the reported serving path — .exactLichess → exactOpponentMaiaEnsemble, .neutralLichessPrior → neutral1500EvidenceExactArtifact.

    MaiaRankStyle¶

    A one-function namespace mapping a Maia MultiPV rank onto a display tier, evaluated in this order:

    rank < 0    → .poor       (played move was outside Maia's top-K)
rank == 0   → .best
rank <= 2   → .good
rank <= 4   → .moderate
otherwise   → .poor
    Tier Rank band App-side color (not in the kit)
    .best 0 Color.green.opacity(0.25)
    .good 1–2 Color.yellow.opacity(0.25)
    .moderate 3–4 Color.orange.opacity(0.25)
    .poor ≥ 5, or −1 Color.red.opacity(0.2) 
    // `playerMoveRank` is the played move's 0-based position in Maia's top-K,
// or −1 when it did not appear at all.
switch MaiaRankStyle.tier(forRank: playerMoveRank) {
case .best:     return Color.green.opacity(0.25)
case .good:     return Color.yellow.opacity(0.25)
case .moderate: return Color.orange.opacity(0.25)
case .poor:     return Color.red.opacity(0.2)
}

    The kit stops at the tier. Color is forbidden in FianchettoKit, so each app owns its own mapping — which is also what lets iOS and Android use their native palettes while agreeing exactly on the bands. The two platforms' previously duplicated private helpers agreed exactly when they were folded into this type.

    Headless usage¶

    fianchetto-cli maia runs the full grid sweep over JSON lines on stdin and emits maia_log_likes, positions_scored, opponent_conditioning, and opponent_elo per game — the same policy calls shown above, with a CoreML transport. It needs the model package.

    Most of this page does not. The encoder, the policy index, both qualification walks, logSoftmaxAt over any logit array you supply, and the whole envelope codec are pure functions with no model dependency, so they can be exercised from a test, a script, or a scratch executable that never loads a network.

    Not implemented today

    The kit surface would support thin maia-encode, maia-qualify, maia-evidence, maia-moves, and maia-decode subcommands — token dumps, qualifying-ply listings, envelope encode/decode/validate, and policy-index lookups — none of which need the model. They are not in commandRegistry yet; see Tools/fianchetto-cli/SUBCOMMANDS.md for what ships.
