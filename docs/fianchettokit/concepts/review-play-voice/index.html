    Review, Play & Voice¶

    The derived state behind the post-game Review pane, the human-like play move sampler, the spoken-move stack, and the presentation kernels the three share. Every type here is a pure function or a value type over ChessCore values — FianchettoKit imports no SwiftUI or UIKit anywhere — so all of it runs in a command-line tool as well as in a view.

    Type What it does
    ReviewSnapshotBuilder every game-tree-derived Review value, from (mainline, eval array, PGN tags)
    ReviewQuizKernel which mainline plies become review-quiz questions
    PlayMoveKernel weighted-random move selection from an engine probability distribution
    GameResultPresentation product wording for ChessCore's terminal GameStates
    CheckmateCelebrationPolicy / CheckmateCelebrationState preference → effects, and a monotonic one-shot trigger record
    SpokenMoveParser / SpokenMoveLexicon / RecognizerProfile utterance → legal-move candidates, table-driven
    VoiceAttemptOwnership (+ token / provenance / result) race guard for asynchronous recognition
    VoiceTranscriptLog / VoiceTranscriptEntry / VoiceOutcome capped transcript log for normalizer tuning
    AccessibilityPhrasing VoiceOver / TalkBack wording
    PgnFilename / PGNResultCode / OTBGameTags export-path helpers
    PieceSet piece-set identity, picker ordering, asset names
    EvalFormat / EvalJSON / DrillLeniency / … the small kernels the rest compose from

    Review snapshot¶

    ReviewSnapshotBuilder is a public nonisolated enum of static functions. Each value it computes was once a SwiftUI computed property on the app's GameReviewView, re-evaluating on every body invalidation — i.e. once per frame while the move list scrolled. Dropping @MainActor was safe because the pipeline never touched main-actor state; the one app-specific input (an @Observable repertoire book) became two portable per-color move maps.

    ReviewSnapshot and the three result types it holds are nested inside the builder, so outside the enum they spell as ReviewSnapshotBuilder.ReviewSnapshot, ReviewSnapshotBuilder.MissedWin, and so on:

    public nonisolated enum ReviewSnapshotBuilder {
    public struct ReviewSnapshot {
        public var perGameAccuracy: AccuracyAggregator.GameAccuracy?
        public var criticalMoments: [MoveNode]
        public var brilliantMoments: [MoveNode]
        public var topSwings: [WinProbabilitySwing]
        public var tablebaseEntryNode: MoveNode?
        public var openingExitNode: MoveNode?
        public var openingExitName: String?
        public var missedWinMoment: MissedWin?
        public var repertoireFit: RepertoireFitResult?
    }
    // MissedWin, WinProbabilitySwing, RepertoireFitResult are nested here too.
}

    ReviewSnapshot.empty is a computed static, not a stored one: the snapshot holds MoveNode references (a non-Sendable class), so a shared mutable global would not be concurrency-safe.

    let snapshot = await ReviewSnapshotBuilder.build(
    mainLine: game.mainLine,                       // [MoveNode]
    annotationEvals: EvalJSON.decode(evalsJSON),   // white-POV centipawns
    loadedTags: game.loadedTags,
    whiteMoves: whiteRepertoireMoves,              // RepertoireBookKernel.RepertoireMoves
    blackMoves: blackRepertoireMoves               // pass [:] when there is no book
)

if let missed = snapshot.missedWinMoment {
    print("Missed win at move \(missed.movedAt) as \(missed.asWhite ? "White" : "Black")")
}

    build(...) runs the stages in a fixed order with await Task.yield() between each, so a long mainline does not monopolize the actor. Every stage is also callable on its own (criticalMoments(in:), topSwings(in:annotationEvals:loadedTags:), …).

    criticalMoments → brilliantMoments → tablebaseEntryNode → missedWinMoment
  → topSwings → perGameAccuracy → openingExit → repertoireFit

    Tag semantics every stage inherits¶

    tag(key, in: tags)     → nil when the tag is absent, empty, or exactly "?"
startsWithWhiteToMove  → true when there is no FEN tag
                       → else Position.fenStartsWithWhite(fen)
                            split fen on " "; fewer than 2 parts → true
                            else parts[1] == "w"

    A [Result "?"] tag therefore suppresses missedWinMoment exactly as a missing tag does, and a black-to-move FEN setup flips mover parity for topSwings and perGameAccuracy.

    The algorithms, with their constants¶

    criticalMoments(in:)   keep moveQuality == .mistake || .blunder
                       sort blunders ahead of non-blunders, then ascending plyIndex
                       prefix(6)
brilliantMoments(in:)  keep annotation == .brilliant || .great; prefix(6) (no sort)
tablebaseEntryNode(in:)
    first node where TablebaseService.pieceCount(for: node.positionAfter) <= 7
    pieceCount = position.board.compactMap { $0 }.count
openingExit(in:)
    walk while OpeningBook.shared.lookup(node.positionAfter) hits; break on the
    first miss; return (last in-book node, entry.name)
    nil when move 1 is already out of book

    Swings use the shared logistic, always oriented to the mover:

    wp(cp) = 1 / (1 + exp(-0.00368208 · cp))          cp is white-POV centipawns

topSwings(in:annotationEvals:loadedTags:)         requires evals.count >= 2
  for i in 0 ..< (evals.count - 1), stopping at mainLine.count:
    moverIsWhite = ((i % 2 == 0) == startsWithWhiteToMove)
    wpBefore = moverIsWhite ? wp(evals[i])     : 1 - wp(evals[i])
    wpAfter  = moverIsWhite ? wp(evals[i + 1]) : 1 - wp(evals[i + 1])
    delta    = (wpAfter - wpBefore) · 100       // win-probability points, 0…100
    → WinProbabilitySwing(node: mainLine[i], delta: abs(delta),
                          directionForMover: delta)
  sort by delta descending, prefix(6)

    delta ranks; directionForMover keeps the sign, so positive is a swing toward the side that moved.

    The missed-win detector tracks each side's peak independently — taking the single largest absolute eval would always surface the eventual winner's converted advantage and hide the other side's earlier, smaller chance:

    missedWinMoment(annotationEvals:loadedTags:)
  require evals.count >= 20 and a present Result tag
  openingPly = 20                              // skip the first 10 full moves
  for i in 20 ..< evals.count:
    if evals[i] > (whitePeak?.cp ?? 0) { whitePeak = (i, evals[i]) }
    if evals[i] < (blackPeak?.cp ?? 0) { blackPeak = (i, evals[i]) }
  admit White's peak when result != "1-0" and 200 <= cp < 5000
  admit Black's peak when result != "0-1" and 200 <= abs(cp) < 5000
  pick the admitted peak with the largest abs(cp)   // a draw can admit both
  movedAt = (peak.index / 2) + 1

    The < 5000 ceiling excludes already-resignable positions (and the ±100 000 mate sentinel); the >= 200 floor excludes ordinary edges. Because each peak seeds at 0, a side that never led after ply 20 produces no peak at all.

    Per-game accuracy combines the two per-side aggregates by sample count, not 50/50 — an odd-ply game gives one side an extra move, and averaging two already-averaged side values made that move vanish from the game figure:

    perGameAccuracy(annotationEvals:loadedTags:)      requires evals.count >= 2
  json  = JSONEncoder().encode(evals)
  white = AccuracyAggregator.accuracy(evalsJSON: json, startIsWhite:, color: .white)
  black = AccuracyAggregator.accuracy(evalsJSON: json, startIsWhite:, color: .black)
  weightedMean(l, lCount, r, rCount) = (l·lCount + r·rCount) / (lCount + rCount)
      a nil side counts as 0 samples; total 0 → nil
  applied to overall, to each AccuracyAggregator.Phase, and to each 5-move bucket
  overallSampleCount = white.overallSampleCount + black.overallSampleCount

    repertoireFit(in:whiteMoves:blackMoves:)
  nil when the mainline is empty, or when BOTH color maps are empty
  plyLimit = min(mainLine.count, 20)               // ~10 moves per side
  color per ply = node.positionBefore.activeColor  // NOT ply parity
  hit = RepertoireBookKernel.isRepertoireMove(node.notation,
            at: node.positionBefore, in: <that color's map>)
  first miss per color → firstDeviation
  nil when whiteHits == 0 && blackHits == 0
  the user's side = more hits; ties go to White (whiteHits >= blackHits)

    Taking the color from positionBefore.activeColor is what makes a FEN-setup game attribute its moves correctly.

    Note

    The eval array is white-POV centipawns with mate encoded as ±100 000 — the same array AccuracyAggregator and the tactics extractor read. Producing one is what fianchetto-cli annotate does; the accuracy formulas over it are available from the command line as fianchetto-cli accuracy.

    Review quiz selection¶

    ReviewQuizKernel decides which plies become quiz questions. It was lifted from the Android review-quiz view, the richer implementation: iOS selected purely on a pre-set node.moveQuality and so produced no quiz at all for batch-annotated library games, which carry evals but no per-node labels. The two branches are mutually exclusive:

    quizMoveQuality(plyIndex k:evalCps:mainLineCount:annotations:startIsWhite:)

  if !annotations.isEmpty                    ← authoritative labels present
      annotations[k] == .blunder → .blunder
      annotations[k] == .mistake → .mistake
      anything else              → nil       ← the eval path is DISABLED entirely

  else                                       ← batch-annotated path
      require evalCps.count == mainLineCount + 1 and k + 1 < evalCps.count
      moverIsWhite = (k % 2 == 0) == startIsWhite
      wpBefore = moverIsWhite ? wp(evalCps[k])     : 1 - wp(evalCps[k])
      wpAfter  = moverIsWhite ? wp(evalCps[k + 1]) : 1 - wp(evalCps[k + 1])
      wpDrop   = max(0, wpBefore - wpAfter)
      AccuracyAggregator.classifyMoveQuality(wpDrop: wpDrop, playedBestMove: false)
      keep only .blunder / .mistake

    classifyMoveQuality is the shared ladder, the same thresholds the annotation pipeline uses on both platforms:

    playedBestMove → .best · >= 0.20 → .blunder · >= 0.10 → .mistake
>= 0.05 → .inaccuracy · >= 0.02 → .good · otherwise → .excellent

    A qualifying ply also needs a best move:

    1. mainLine[k].engineBestMoveUCI, treating "" as absent
2. on the FIRST miss only, lazily build (at most once):
     PGNParser.mainLineSnapshot(
       fromMoveText: PreparedGameData.normalizeForParsing(moveText))
   accept it only when parsed.moves.count == mainLine.count  ← 1:1 alignment guard
3. still empty → drop the ply

    let plies = ReviewQuizKernel.quizablePlies(
    mainLine: game.mainLine,
    evalCps: evals,
    annotations: [:],              // empty → use the eval path
    moveText: prepared.moveText,   // PreparedGameData.moveText
    startIsWhite: true
)
for ply in plies {
    print(ply.index, ply.quality, ply.bestUCI)   // Int, MoveQuality, non-empty UCI
}

// The entry-button "(N)" label is definitionally the same list.
let n = ReviewQuizKernel.quizableCount(
    mainLine: game.mainLine, evalCps: evals, annotations: [:],
    moveText: prepared.moveText
)

    QuizablePly carries only plain value fields (index, quality, bestUCI) so it bridges as a SkipFuse function result. Parsing the UCI into a move, assembling distractors, and the mastery skip stay app-side — the mastery backends differ (SwiftData vs a file-backed JSONBlobStore).

    Play: weighted-random move selection¶

    PlayMoveKernel.weightedRandomMove(from: [EngineAnalysis.ScoredMove], using: &rng)
  moves.isEmpty   → nil
  totalProb = Σ probability
  totalProb <= 0  → moves.first?.move           ← degenerate distribution
  random = Double.random(in: 0 ..< totalProb, using: &rng)
  walk the list subtracting each probability; return the first entry where
      random <= 0
  walk exhausted  → moves.last?.move            ← floating-point residue

    var rng = SystemRandomNumberGenerator()
let move = PlayMoveKernel.weightedRandomMove(from: analysis.topMoves, using: &rng)

// Convenience overload when you don't need to inject one:
let move2 = PlayMoveKernel.weightedRandomMove(from: analysis.topMoves)

    The generic RNG: RandomNumberGenerator parameter is inout for two reasons: a seeded generator makes the sampler deterministic under test, and Skip can substitute Android's generator. The arithmetic — including both fallbacks — is preserved byte-for-byte from the original iOS call site.

    Game end: result wording and celebration¶

    GameState GameResultPresentation.text(for:activeColor:) isDraw
    .checkmate "Checkmate — \(winner) wins", winner = activeColor == .white ? "Black" : "White" false
    .stalemate "Stalemate — Draw" true
    .draw "Draw by 50-move rule" true
    .insufficientMaterial "Draw — insufficient material" true
    .repetition "Draw by threefold repetition" true
    .playing, .check nil false

    The winner is derived from the side to move in the checkmated position, which is why activeColor is a parameter rather than something each caller recomputes.

    CheckmateCelebrationPolicy.Intensity is the persisted preference — off = 0, subtle = 1, standard = 2, festive = 3, and Intensity(storedValue:) coerces any unrecognized stored Int to .standard. decision(storedIntensity:reduceMotion:hapticsEnabled:) resolves it into four independent effects:

    Effect Rule
    showsConfetti intensity.rawValue >= 2 && !reduceMotion
    playsFestiveHaptic intensity == .festive && hapticsEnabled
    showsGrandFanfare intensity == .festive && !reduceMotion
    playsGrandFinale intensity == .festive

    Note

    playsGrandFinale is deliberately not gated on Reduced Motion: it drives the fanfare sound and the connected e-board's LED/beep show, neither of which is screen motion. For the same reason Reduced Motion never silently disables haptics the user turned on independently.

    var celebration = CheckmateCelebrationState()

celebration.celebrateOnce(          // returns the Decision the first time,
    storedIntensity: storedIntensity,   // nil on every later observation
    reduceMotion: reduceMotion,
    hapticsEnabled: hapticsEnabled
)
celebration.confettiTrigger         // monotonic counters a view observes
celebration.festiveHapticTrigger
celebration.grandFanfareTrigger
celebration.resetForNewGame()       // clears hasCelebrated ONLY

    Counters advance with wrapping &+= 1, and only for the effects the decision selected. resetForNewGame() never rewinds a trigger, because resetting an observed trigger to zero is itself a change — and on both platforms that can fire the feedback API it is wired to.

    Voice: the spoken-move stack¶

    SpokenMoveParser has two public functions: normalize(_:profile:) -> [String] and match(_:position:profile:) -> [VoiceMoveCandidate].

    let candidates = SpokenMoveParser.match("night takes e five", position: pos, profile: .apple)

switch candidates.count {
case 0:  reprompt()                        // no match
case 1:  apply(candidates[0].move)         // ready to apply
default: presentDisambiguation(candidates) // candidates.map(\.san)
}

    The result count is the contract: 0 = no match, 1 = apply, >1 = disambiguate. VoiceMoveCandidate is Identifiable by its san, which is also the dedupe key in matching.

    Normalization accumulates; it never chooses¶

    The pipeline emits every plausible reading and lets legality decide. Nine steps:

    1. lowercase + trim, then apply every rawPhraseRewrites row sequentially
2. append the fully space-collapsed form                   "e2 to e4" → "e2toe4"
3. piece-word PREFIX expansion: symbol + rest, capture verbs → "x",
   filler words stripped                                   "knight to c3" → "Nc3"
4. castlePhrases substring hits; bare "castle"/"castles" emits BOTH O-O and O-O-O
5. capture-verb split into exactly 2 parts:
       piece + fileDisambig + "x" + after                  "e takes d5" → "exd5"
6. filler removal on the PADDED pattern " to "             "e2 to e4" → "e2e4"
7. file + rank homophone substitution, appended only when it differs from step 2
8. promotion SUFFIX match → base + "=Q" / "=R" / "=B" / "=N"
9. confusable-letter variants of every candidate accumulated so far

    match then parses each candidate with PGNParser.parseMove, renders SAN via MoveGenerator.algebraicNotation, and dedupes by SAN. Illegal candidates simply fail to parse and vanish, which is what makes over-generating safe.

    The core lexicon is data¶

    SpokenMoveLexicon holds ten ordered tables; core is seeded verbatim from the proven iOS normalizer.

    Table Rows in core
    rawPhraseRewrites (empty)
    pieceWords knight→N, night→N, nite→N, bishop→B, rook→R, rock→R, queen→Q, king→K, pawn→""
    fileHomophones "ay "→a, "bee "→b, "be "→b, "see "→c, "sea "→c, "dee "→d, "de "→d, "gee "→g, "ee "→e, "eff "→f, "aitch "→h
    rankHomophones one/won→1, two/too→2, three/tree→3, four→4, " fore"→" 4", for→4, five→5, six→6, seven→7, eight/ate→8
    captureVerbs ["takes", "take", "captures"] — longest first
    castlePhrases "castle king"→O-O, "short castle"→O-O, "castle queen"→O-O-O, "long castle"→O-O-O
    fillerWords ["to"]
    promotionSuffixes queen→=Q, rook→=R, bishop→=B, knight→=N, night→=N
    fileConfusables (a,c) (c,a) (a,e) (e,a) (b,d) (d,b) (b,e) (e,b) (b,p) (p,b) (d,g) (g,d)
    pieceConfusables (N,K) (K,N) (N,B) (B,N)

    Every row is applied sequentially with replacingOccurrences, so order is load-bearing. Two rows carry the whole weight:

    ("gee ", "g") must precede ("ee ", "e")
    otherwise "gee six" becomes "ge six" before the "gee " row can fire.

(" fore", " 4") — with its LEADING SPACE — must precede ("for", "4")
    without the space "before" → "be4", which the PGN parser reads as b4:
      a spurious match. With it, " fore" is not a substring of "before", so
      "before" survives to the "for" row and becomes the unparseable "be4e".
    "e fore" still works: " fore" is found at index 1 → "e 4".

    The trailing space in every fileHomophones pattern is the partial-word guard ("bee " → b, while "been" is untouched). Confusable expansion is bounded:

    confusable expansion (step 9, internal)
  only candidates with 2 <= count <= 5 (SAN length)
  file slot  = chars.count - 2, and only when that character is a…h
  piece slot = chars[0], and only when it is uppercase
  a COMBINED piece+file swap is also emitted when fileIdx > 0
  each substitution is applied then immediately reverted → single/double swaps only

    RecognizerProfile.lexicon is SpokenMoveLexicon.core.merged(with: overlay), and merged(with:) appends overlay rows after core rows so core ordering stays higher-priority.

    Profile Overlay
    .apple none — an empty SpokenMoveLexicon(); SFSpeechRecognizer is already well-trained on chess vocabulary
    .google rawPhraseRewrites: ("before", "b4"), ("84", "e4") · pieceWords: ("brook", "R")

    That is the design goal: a newly observed mishearing is one table row plus one corpus case, never an engine-code change.

    Voice: attempt ownership¶

    Recognition is asynchronous, cancellable, and can deliver a callback after the position has moved on. VoiceAttemptOwnership is the value type that makes that safe: VoiceAttemptToken (opaque; the raw processSequence: UInt64 is fileprivate and never re-exposed), VoiceAttemptProvenance (token + sessionID + positionProof), and VoiceAttemptResult (a payload permanently paired with its provenance).

    phases:  .recognizing → .awaitingConfirmation → .consumed
                     ↘ .invalidationRequested        (terminal)

begin(token:sessionID:positionProof:)
    admits a token only when it STRICTLY succeeds highestAcceptedToken, then
    supersedes the previous attempt and clears any pending confirmation
acceptsCallback(for:currentSessionID:currentPositionProof:)
    requires activeAttempt == provenance && phase == .recognizing
    a session/position mismatch marks invalidation — PERMANENTLY
registerConfirmation(_:for:currentSessionID:currentPositionProof:)
    gates through acceptsCallback, stores the result, freezes further callbacks
consumeConfirmation(_:currentSessionID:currentPositionProof:)
    compares provenance AND current context, then returns the OWNER-HELD result
    exactly once — not the payload the UI handed back
clear(ifOwnedBy:)   clears only while cleanup still owns the active attempt

    var ownership = VoiceAttemptOwnership<UUID, String, VoiceMoveCandidate>()

guard let attempt = ownership.begin(
    token: VoiceAttemptToken(processSequence: nextSequence()),
    sessionID: sessionID,
    positionProof: position.fen
) else { return }   // a newer attempt already owns recognition

if let presented = ownership.registerConfirmation(
    candidate, for: attempt,
    currentSessionID: sessionID, currentPositionProof: position.fen
), let owned = ownership.consumeConfirmation(
    presented, currentSessionID: sessionID, currentPositionProof: position.fen
) {
    apply(owned.payload)
}

ownership.clear(ifOwnedBy: attempt)   // no-op once a newer attempt took over

    Invalidation on a session or position mismatch is permanent, so returning to a position with an equal FEN cannot revive a stale callback. clear(ifOwnedBy:) is a compare-and-clear, so an old attempt's slow shutdown can never clear a newer recognizer. Token admission is strictly increasing, so the platform adapter must draw tokens from one process-wide monotonic sequence.

    Warning

    VoiceAttemptOwnership is Sendable but deliberately carries no internal lock. Keep one instance inside the platform controller's actor (normally the main actor) and route every callback, cancellation, cleanup, and confirmation through that same isolation domain.

    Voice: transcript log¶

    VoiceTranscriptLog is a BlobBackedStore ring buffer over the same JSONBlobStore seam as the stat stores, so a CLI can supply a file-backed implementation: blobKey = "voiceTranscriptLog", cap = 200, and append(_:) trims the oldest with entries.removeFirst(entries.count - cap).

    var log = VoiceTranscriptLog.load(from: blobStore)
log.append(VoiceTranscriptEntry(
    rawTranscript: transcript,
    alternatives: alternativeTranscripts,
    positionFEN: position.fen,
    outcome: candidates.isEmpty
        ? .noMatch
        : .disambiguation(candidates: candidates.map(\.san)),
    profile: "apple"
))
log.save(to: blobStore)

    VoiceOutcome has a hand-written Codable conformance with a kind discriminator ("matched" / "disambiguation" / "noMatch") plus san or candidates — a stable on-disk shape a tool can read and write directly. The privacy default is deliberate: only failures and disambiguations are logged, and a .matched entry requires caller opt-in. That is exactly what the tuning loop needs — collect the misses, add one lexicon overlay row plus one corpus case, rebuild. Android read-back: adb shell run-as <pkg> cat files/blobs/voiceTranscriptLog.json.

    Accessibility phrasing¶

    AccessibilityPhrasing is the one home for VoiceOver / TalkBack wording. Pure String/Int output, no UI framework, so the transpiled Android views compose the same sentences.

    material(captured:advantage:sideName:)
  fixed order [.queen, .rook, .bishop, .knight, .pawn]; count == 1 uses
  PieceType.displayName, else "\(count) \(displayName)s"; parts joined ", " behind
  the literal "captured "; ", plus \(advantage)" appended ONLY when advantage > 0.
  An empty capture map yields "White: " (the historical iOS wording).
spokenDuration(_:)   negatives clamp to 0; the minutes clause is omitted below 60s
                     → "3 minutes 42 seconds" / "42 seconds"
squareHint(isSelected:isLegalTarget:isOwnPiece:)          first match wins
  isSelected → "Double-tap to deselect" · isLegalTarget → "Double-tap to move here"
  isOwnPiece → "Double-tap to select this piece" · otherwise → ""
signalBarCount(rssi:)  ..< -85 → 1 · -85 ..< -75 → 2 · -75 ..< -60 → 3 · else 4
evalAdvantageWord(whiteProbability:)
  p > 0.52 → "White" · p < 0.48 → "Black" · otherwise → "Even"

    The 0.48–0.52 dead band stops a dead-even position from announcing a side merely because it rounds off center. selectedLabel(_:isSelected:) appends ", selected" — an Android workaround, because .accessibilityAddTraits(.isSelected) crashes the accessibility tree walk there; SkipUI maps that trait to stateDescription("selected"), so the string form is equivalent.

    PGN and export helpers¶

    PgnFilename.make(white:black:date:)
  keep only isLetter || isNumber || "-" || "_" || "."
  PGN date dots → hyphens BEFORE cleaning       "2024.01.15" → "2024-01-15"
  drop a side whose cleaned name is empty       (the "?" placeholder)
  join surviving players with "-vs-", then join to the date with "-"
  stem = raw.prefix(50); empty stem → "game"; append ".pgn"

PGNResultCode.from(_:)                ordered `contains` checks
  "White wins" → "1-0" · "Black wins" → "0-1" · "Draw" → "1/2-1/2"
  nil or unrecognized → "*"

OTBGameTags.make(eventTag:date:result:startFEN:)
  delegates to SavedGameTags.make with placeholder white: "White", black: "Black"
  insertion order Event, Date, White, Black, Result
  SetUp = "1" and FEN added ONLY for a non-nil, non-empty startFEN

    Dropping the empty side is what stops "White-vs--2024-01-15" when one player tag is "?". The conditional SetUp/FEN pair is what lets SAN relative to a non-initial start reload correctly; emitting it unconditionally would pin ordinary games to a redundant start FEN. date must already be yyyy.MM.dd (SavedGameTags.pgnDateString() produces it).

    Piece sets¶

    PieceSet is a String-raw-valued enum with ten cases. The rawValues are the persisted AppStorage keys on both platforms and must never change — iOS writes "pieceSet", Android writes "pref.pieceSet", both defaulting to "cburnett".

    selectableCases is the curated picker list — [.cburnett, .merida, .staunty, .maestro, .leipzig, .mpchess, .inkwell] minus anything in pendingPermission. crownline, scandi, and minimal stay fully wired (cases, assets, export switch, and existing persisted selections all still render) but are omitted to keep the list short; pickerCases(including:) re-adds the current selection when it is one of those, so an existing choice stays visible and labeled instead of rendering as an empty selection.

    pendingPermission is the licensing gate and is currently empty (since the sadsnake1 grant, 2026-07-20). Parking a set there is coupled to a docs/LICENSING.md row and its About credit; flip all three in one commit.

    assetName(for:) special-cases the default set: cburnett → "wK" / "bQ" (the bare historical asset names); every other set → "\(rawValue)_wK".

    Shared utilities¶

    EvalFormat uses integer-only arithmetic — no float String(format:), which SkipFoundation does not reproduce identically — so iOS, macOS, and Android print the same string:

    formatCentipawns(cp:isMate:)
  isMate → "M\(cp)" when cp >= 0, else "-M\(-cp)"
  else   sign = cp >= 0 ? "+" : "-"; a = abs(cp); frac = a % 100 zero-padded to 2
         "\(sign)\(a / 100).\(frac)"       → "+1.34", "-0.21"
formatCentipawnsNoDistance(cp:isMate:)    mates print bare "M" / "-M"
formatEvalDisplay(cp:mateIn:style:)
  a non-nil mateIn forces M-notation REGARDLESS of style; nil cp with no mate → "—"
  style == "winprob" → "\(Int((wp * 100).rounded()))%"
      rounded() is .toNearestOrAwayFromZero — ties round away from zero (0.505 → 51%)
  any other style (including "pawns") → formatCentipawns

    EvalJSON is the codec for the eval blobs that tie the annotation, accuracy, review, and tactics paths together. decode, decodeOptional, and decodeMateDistances return [] for missing or malformed input, so callers can size-check against a parallel array; encode and encodeMateDistances return "[]" on failure.

    Warning

    Mate sentinels must be preserved at ±100 000 — do not pre-clamp them. Downstream mate detection is abs(cp) >= 100_000, and clamping breaks both that check and win-probability. Mate-distance arrays are already white-oriented (positive = White mates in N) and use JSON null for non-mates; the engine-POV → white-POV flip is the caller's job.

    PercentFormat.whole(_:)   non-finite → "—", else String(format: "%.0f%%", v * 100)

    The name parsers are strict on purpose: an arbitrary local or import source must never become an online account merely because it has a nonempty username, a local filename containing / must never be read as an account, and parenthetical names belong to the newer importer, so the legacy path deliberately does not infer them.

    DrillLeniency is the mate-aware partial-credit rule; both evaluations must be in the mover's POV:

    leniencyAccept(bestCp:bestIsMate:playedCp:playedIsMate:marginCp:)
  if bestIsMate:
      guard bestCp > 0                     ← a best move that mates AGAINST the
                                             mover is rejected outright
      return playedIsMate ? (playedCp > 0) : (playedCp >= 500)
  if playedIsMate  → playedCp > 0          ← upgraded to / kept a real mate
  if bestCp >= 500 → playedCp >= 200       ← best already decisive
  else             → playedCp >= bestCp - marginCp    (marginCp typically 50–150)

    An earlier version accepted any playedIsMate, mis-grading a blunder-into-mate as a solve; the playedCp > 0 test is the fix. leniencyVerdict(best:played:marginCp:) returns the three-state DrillProbeVerdict and yields .unavailable when either EngineScoreAdapter.Evaluation is nil — a missing probe is never chess evidence of a wrong move, and .unavailable contributes 0 to completedAttemptDelta.

    Headless surface and CLI mapping¶

    Every type on this page runs with no UI dependency, so all of it is reachable from a command-line tool. What exists today, and what is proposed:

    Area Command-line status
    The eval arrays the Review snapshot consumes produced by fianchetto-cli annotate
    The AccuracyAggregator formulas the review kernels build on — winProbability (both), classifyMoveQuality (quiz kernel), moveAccuracy (reached through accuracy(evalsJSON:startIsWhite:color:)) fianchetto-cli accuracy
    SpokenMoveParser / SpokenMoveLexicon proposed voice subcommand
    ReviewSnapshotBuilder proposed review subcommand
    ReviewQuizKernel proposed quiz subcommand
    PlayMoveKernel with an injected seeded RNG proposed sample subcommand
    Formatter/policy kernels (EvalFormat, GameResultPresentation, CheckmateCelebrationPolicy, PgnFilename, PGNResultCode) proposed golden subcommand

    The proposed commands would follow the JSON-lines contract the implemented ones use — one JSON object per input line on stdin, one per result line on stdout — which suits these types, since each is a pure function over plain values. VoiceTranscriptLog needs nothing more than a file-backed JSONBlobStore to be readable and writable by a tool, and VoiceOutcome's kind-tagged encoding is already a stable on-disk shape.
