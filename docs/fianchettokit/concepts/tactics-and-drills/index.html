    Tactics, drills & spaced repetition¶

    How FianchettoKit turns annotated games into puzzles, grades an answer, scores it into a rating, and decides when to ask again.

    The four layers¶

    The area is four pure stages with an optional engine probe in the middle:

    Layer Types What it does
    Extract TacticsExtractor, TacticsInput, TacticsPuzzle, CombinationMiningKernel, CombinationPuzzleKernel annotated game → puzzles
    Grade DrillStrictness, DrillVerdict, DrillProbeVerdict, CombinationDrillCore played move → verdict
    Score TacticsRatingStore, TacticsPerformanceStore, BlunderMasteryStore verdict → rating / history / mastery
    Schedule DrillSRS, DrillMastery, TrainProgressCache mastery → what to ask next

    Every type on this page imports only Foundation and ChessCore — no SwiftUI, no app lifecycle, no actors — so the whole pipeline runs headless against a JSONBlobStore you supply.

    Puzzle extraction¶

    TacticsInput is the Sendable snapshot of one annotated game: the two player names, the PGN move text, the encoded tags, the username, and three parallel per-position arrays encoded as JSON — annotationEvalsJSON ([Double], white-oriented centipawns), secondBestEvalsJSON ([Double?]), and mateDistancesJSON ([Int?], white-oriented forced-mate distance, null for "not a mate").

    mainLineSnapshot(pliesLimit:) is the single PGN reconstruction boundary — TacticsExtractor, CombinationMiningKernel and personal-endgame extraction all go through it, so custom start positions and ply orientation cannot drift between them. startingPositionFEN projects only the FEN tag out of tagsJSON, because that is the one tag that changes how the move text is interpreted.

    Extraction refuses to run on anything it cannot trust:

    guard user color resolvable from (white, black, username)
guard parsed.moves.count >= 4
guard evals.count == parsed.moves.count + 1
secondBestEvals / mateDistances: used only if count == evals.count,
                                 otherwise replaced by all-nil

    A stale or truncated blob is therefore a no-op, not a crash and not a wrong puzzle.

    Note

    The per-ply eval array these guards check is exactly what the Stockfish annotation path produces. Available from the command line: fianchetto-cli annotate.

    The four extraction modes¶

    public nonisolated enum TacticsExtractionMode: String, Sendable, CaseIterable, Codable {
    case opponentBlunders, userBlunders, criticalPositions, missedMate
}
    Mode displayName Who moved at ply i Qualifies when Puzzle starts
    .opponentBlunders Punish opponent swingForUser >= threshold after the move (positionAfter)
    .userBlunders Improve user swingForUser <= -threshold before the move (positionBefore)
    .criticalPositions Critical either abs(swingForUser) >= threshold before the move
    .missedMate Mates user user's forced mate lost (below) before the move

    prompt carries the long caption ("Your opponent erred — find the punishing move.", "You went wrong here — what should you have played?", …).

    Only .opponentBlunders fills opponentMove; the other three set it to the empty string, because the move played at the puzzle position is the user's previous wrong guess and showing it as context would leak it back to them. contextText reflects that: "After 12…Nxg5" for Punish, versus "Your move 12 — what should you have played?".

    Qualification and answer selection¶

    swingForUser = (color == .white) ? evals[i+1] - evals[i]
                                 : evals[i]   - evals[i+1]
swingLimit   = Double(swingThreshold)          // default 150

.opponentBlunders  !isUserMove && swingForUser >=  swingLimit
.userBlunders       isUserMove && swingForUser <= -swingLimit
.criticalPositions               abs(swingForUser) >= swingLimit
.missedMate         isUserMove
                 && i + 1 < mateDistances.count
                 && favorsUserMate(mateDistances[i])
                 && abs(mateDistances[i] ?? 0) <= mateMaxN     // default 5
                 && !favorsUserMate(mateDistances[i + 1])

    The .missedMate chain relies on && short-circuiting: the bounds check runs before the subscripts. favorsUserMate is false for nil and for 0 (checkmate already on the board), else dist > 0 for White and dist < 0 for Black.

    .opponentBlunders requires i + 1 < mainLine.count, uses node.positionAfter.fen, and takes the answer from the next node's engineBestMoveUCI, falling back to that node's played move and notation. The other three use node.positionBefore.fen and require a non-empty engineBestMoveUCI on the current node — without one the position is skipped entirely, because there is no defensible answer to grade against. Output is sorted by descending abs(evalAfter - evalBefore).

    extractAll(from:modes:mateMaxN:swingThreshold:) pays the PGN walk and the three JSON decodes once for any number of modes. Every requested mode gets a key — an empty array when nothing qualifies — but the early exits (unresolvable user color, a game under four plies, an eval-count mismatch) return an empty dictionary, so callers should still read byMode[mode] ?? [].

    let input = TacticsInput(
    white: "kasparov", black: "topalov",
    moveText: game.moveText,
    tagsJSON: game.tagsJSON,
    annotationEvalsJSON: game.evalsJSON,
    secondBestEvalsJSON: game.secondBestJSON,
    mateDistancesJSON: game.mateDistancesJSON,
    username: "topalov"
)

let byMode = TacticsExtractor.extractAll(
    from: input,
    modes: [.opponentBlunders, .userBlunders, .missedMate],
    mateMaxN: 5,
    swingThreshold: 150
)

for puzzle in byMode[.userBlunders] ?? [] where puzzle.isHighQuality {
    print(puzzle.contextText, puzzle.correctMoveSAN, puzzle.difficulty.rawValue)
}

    Difficulty and quality¶

    The sharpness gap is the engine's best minus second-best at the puzzle position, oriented to whoever is to move there:

    evalIndex     = (mode == .opponentBlunders) ? i + 1 : i
isWhiteToMove = (evalIndex % 2 == 0) == startIsWhite
signedGap     = isWhiteToMove ? evals[evalIndex] - second
                              : second - evals[evalIndex]
bestVsSecondGapCp = max(0, signedGap)     // nil if no second-best stored

    difficulty crosses the swing bands with a 100 cp sharpness threshold. A legacy game with no gap is treated as sharp, so labels do not move until re-annotation:

    swing  = abs(evalAfter - evalBefore)
isSharp = bestVsSecondGapCp.map { $0 >= 100 } ?? true

swing >= 500   →  isSharp ? .easy   : .medium
swing >= 250   →  isSharp ? .medium : .hard
otherwise      →  .hard

    isHighQuality is a stricter, independent label — contested and effectively unique:

    puzzleEvalCp = (mode == .opponentBlunders) ? evalAfter : evalBefore
contested    = abs(puzzleEvalCp) <= 600
isHighQuality = false                        when bestVsSecondGapCp == nil
              = contested && gap >= 100      otherwise

    A nil gap is not high-quality but stays eligible at lower priority, and re-annotation that fills bestVsSecondGapCp upgrades legacy puzzles automatically — nothing needs re-extracting.

    Missed mates in legacy games¶

    Games annotated before the mate-distance array shipped carry the forced mate only as the ±100000 eval marker, with no N. missedMateCandidates(from:) runs only for those games (decodeMateDistances(...).isEmpty) and pinpoints the positions worth re-probing:

    mateMarker = 100_000.0
white:  before >=  100_000  &&  after <   100_000
black:  before <= -100_000  &&  after >  -100_000

    Each MissedMateCandidate carries fen, userColor, moveNumber, gameInfo, storedBestMoveUCI, and plyIndex — the 0-based index into the same array extract uses, so a caller with engine access can confirm N and backfill exactly those positions instead of re-annotating whole games.

    Cache identity¶

    TacticsInput.cacheFingerprint is a hand-rolled FNV-1a with length framing:

    hash  = 14_695_981_039_346_656_037
prime = 1_099_511_628_211

components, in order:
  "tactics-cache-v4", white, black, username, moveText,
  startingPositionFEN, annotationEvalsJSON, secondBestEvalsJSON,
  mateDistancesJSON

per component:  fold 8 little-endian bytes of utf8.count, then every utf8 byte
per byte:       hash ^= byte;  hash &*= prime

    Length framing is what prevents component-boundary collisions such as ["ab", "c"] versus ["a", "bc"]. Swift's Hasher cannot be used here at all: it is process-randomized, and a persisted fingerprint must be stable across launches and across devices.

    CombinationPuzzleStore.corpusFingerprint(ofGameFingerprints:) is the same fold over the sorted per-game fingerprints, with the element count folded first — sorted because library iteration order is not stable under CloudKit merges.

    Grading policy¶

    DrillStrictness drives both the acceptance margin and whether a middle ground exists at all:

    Case marginScale showsCloseEnough requiresExactBestMove
    .lenient 2.0 false false
    .normal 1.0 true false
    .strict 0.3 false true 
    scaledMargin(base) = max(1, Int((Double(base) * marginScale).rounded()))

base margins at the app's call sites:
  Tactics / Traps / Punish  50 cp   → strict 15,  lenient 100
  Study                     80 cp   → strict 24,  lenient 160
  Endgame trainer          150 cp   → strict 45,  lenient 300

    DrillStrictness.from(_:) resolves the stored raw string (key DrillStrictness.appStorageKey, "drillStrictness") and defaults to .normal. requiresExactBestMove is a prohibition, not a threshold: strict grading must not run a smaller-margin probe and then relabel a near-best move as correct.

    DrillVerdict has six cases — checking, correct, closeEnough(expected:played:), wrong(expected:played:), unavailable(message:), done. The load-bearing one is .unavailable: an engine that timed out or returned no score is not evidence that a chess move was wrong. DrillProbeVerdict makes that explicit at the probe boundary:

    let verdict = DrillProbeVerdict(completed: probe.decision)  // Bool? → three states
// true → .accepted, false → .rejected, nil → .unavailable

completed += verdict.completedAttemptDelta   // 1, 1, 0

    Retrying an unavailable probe therefore contributes zero attempts until one completed accepted/rejected result lands.

    Pacing and ownership¶

    .correct                      →   900_000_000 ns  (0.9 s)
.closeEnough, .wrong          → 1_600_000_000 ns  (1.6 s)
.checking, .unavailable, .done, nil → no auto-advance

    After the delay elapses, the transition is committed only if the ticket still matches on both fields:

    let ticket = DrillAutoAdvanceTicket(itemIndex: index, feedbackGeneration: generation)
guard let delay = DrillAutoAdvancePolicy.delayNanoseconds(for: verdict) else { return }
try await Task.sleep(nanoseconds: delay)
guard ticket.isCurrent(itemIndex: currentIndex, feedbackGeneration: currentGeneration)
else { return }

    Cancellation alone is not sufficient — a cancelled task can already be resuming, which is precisely when it would advance past an item the user has moved on from.

    Rating the user¶

    TacticsRatingStore (blob key tacticsRating) is zero-sum Elo with K = 32:

    seed ratings   easy 1200 | medium 1500 | hard 1800
user seed      1400

actual   = (outcome == .correct) ? 1 : 0
expected = 1 / (1 + 10^((puzzleRating − userRating) / 400))
delta    = 32 · (actual − expected)

userRating   += delta
puzzleRating −= delta          // strictly zero-sum
attemptCount += 1
lastUpdated   = mutation.timestamp     // not .now — replay must be deterministic

    A .skipped outcome is dropped before any of this and returns a delta of 0.

    var ratings = TacticsRatingStore.load(from: blobStore)

let delta = ratings.recordAttempt(
    puzzleKey: puzzle.masteryKey,
    difficulty: puzzle.difficulty,
    outcome: .correct,
    in: blobStore
)

ratings.displayUserRating                      // Int(userRating.rounded())
ratings.peakUserRating                         // floored at 1400
ratings.relativeDifficulty(for: puzzle.masteryKey)
ratings.rating(for: puzzle.masteryKey, fallbackDifficulty: puzzle.difficulty)

    gap = puzzleRating − userRating
gap >=  200 → .veryHard      gap >=   75 → .hard
gap >=  −75 → .even          gap >= −200 → .easy
otherwise   → .veryEasy      (nil when the puzzle was never attempted)

peakUserRating = Int(max(1400, max(userRating, maxRecordedPoint)).rounded())

    ratingHistory is capped at 200 points during replay. recordRepertoireAttempt(repertoireIDs:puzzleRating:correct:in:) maintains RepertoirePerformance separately, with avgPuzzleRating as an incremental mean (previousSum = avg · attempts, then divide by the incremented count) and lastSolveAt written only on a correct attempt.

    Attempt history and metrics¶

    TacticsPerformanceStore (blob key tacticsPerformance) keeps [TacticsAttempt], whose puzzleKey follows the same "<fen>:<correctSAN>" convention as BlunderMasteryStore.key(fen:correctSAN:). extractionMode and difficulty are stored as raw Strings deliberately, so the persisted schema does not chase enum cases.

    public static let maxAttempts = 3_000: at roughly 292 B of JSON per attempt the blob crosses CloudKit's ~1 MB record limit near ~3,400 attempts, so 3,000 keeps the worst case around 0.88 MB. Oversized legacy blobs still decode in full and shrink to the cap on the next record.

    accuracy            = correct / (correct + wrong)      // skips excluded; 0 if none
recentAccuracy(over: n) = filter out skips, take last max(0, n), same ratio
currentStreak       = StreakMath.current(outcomes.map { $0 == .correct })
bestStreak          = StreakMath.best(...)
medianSolveSeconds  = median over CORRECT attempts of min(elapsed, 300)
                      (mean of the two middle values on an even count; nil if none)

    The 300 s clamp exists so one abandoned tab cannot skew the median. difficultyBreakdown() and modeBreakdown() return [String: (correct: Int, wrong: Int)], skips excluded.

    Mastery and scheduling¶

    BlunderMasteryStore is a namespace over one blob (blunderMastery) keyed by "\(fen):\(correctSAN)":

    correct → count += 1
wrong   → count  = 0        (an ordered operation, not a blob wipe)
mastered when count >= masteryThreshold (3)

    DrillMastery.counts(_:history:threshold:key:) rolls any item pool up against that map, defaulting threshold to BlunderMasteryStore.masteryThreshold:

    let (total, due, mastered) = DrillMastery.counts(
    puzzles,
    history: BlunderMasteryStore.history(in: blobStore),
    key: \.masteryKey
)
TrainProgressCache.record(.init(total: total, due: due, mastered: mastered),
                          for: .tactics, into: blobStore)

    Warning

    due here means not yet mastered (total - mastered), matching the menus' due/done badges. It is not SRS-time-due. Time-based due-ness lives in DrillSRS.isDue(key:now:), which is a separate store with a separate key space.

    DrillSRS (blob key drillSRS) holds Entry(nextReview:interval:streak:) per key and schedules by doubling:

    correct →  streak += 1;  interval = min(interval * 2, 30)
wrong   →  streak  = 0;  interval = 1
both    →  nextReview = mutation.timestamp + interval days

calendar = Calendar(identifier: .gregorian), timeZone = GMT+0
isDue(key:now:) = true when the key has NO entry, else entry.nextReview <= now

    The calendar is pinned rather than .current so two devices replaying the same ledger land on the same dates. DrillSRS.load(from:migrationStore:) migrates the Android-era "repertoireDrillSRS" key once and immediately re-saves under the canonical key.

    var srs = DrillSRS.load(from: blobStore, migrationStore: legacyStore)
if srs.isDue(key: drillKey) {
    srs.recordCorrect(key: drillKey, to: blobStore)   // or recordWrong(key:to:)
}
srs.entry(for: drillKey)?.interval      // 2, 4, 8, 16, 30, 30 … on successive solves

    The mutation-ledger pattern¶

    TacticsRatingStore, DrillSRS and ConsecutiveCorrectProgress (behind BlunderMasteryStore) share one shape: a materialized baseline plus immutable, UUID-identified operations, so two replicas can union their ledgers instead of one whole-blob write winning. Replay is identical in all three, up to which fences each store carries — only TacticsRatingStore has discardedMutationIDs, clearsLegacyBaseline and resetAt:

    baseline = clearsLegacyBaseline ? Baseline() : (legacyBaseline ?? current state)
lowerFence = max(mutationCompactedAt ?? .distantPast, resetAt ?? .distantPast)

keep mutations where  id ∉ discardedMutationIDs  &&  timestamp > lowerFence
sort ascending by timestamp, tie-broken by id.uuidString
apply in order

compaction (at maxRetainedMutations == 1_000):
    legacyBaseline      = current materialized state
    mutations           = []
    mutationCompactedAt = .now
    clearsLegacyBaseline = nil          // cleared
    reset tombstones      RETAINED

    TacticsPerformanceStore is not ledger-backed — its attempts are the identified records — but its reset(in:) follows the same tombstone discipline, keeping discardedAttemptIDs only for future-dated attempts and covering the rest with resetAt.

    Reset tombstones outlive compaction on purpose. A mutation observed from another replica can carry a future timestamp because that device's clock is skewed; neither resetAt nor the compaction fence can suppress it until the clock catches up, so dropping its exact UUID would let a stale sibling resurrect it on the next merge.

    Warning

    The ledger is bounded and local. It is not a server-acknowledged event log: a concurrent mutation with a badly skewed earlier clock can land on the compacted side of the fence and be lost. It buys convergence for the normal case, not durability guarantees.

    ConsecutiveCorrectProgress.decode(_:) accepts the current envelope first and falls back to a raw [String: Int] map (promoting it to legacyBaseline with an empty ledger); encoded() sets outputFormatting = [.sortedKeys] so the bytes are stable.

    Mining combinations, stage 1¶

    Swing and sharpness cannot tell a one-move fork from a seven-ply combination — both are just a big number. The discriminator is that the solver's material goes negative mid-line and only recovers at the end. Annotation stores no principal variation, only scalars plus one best move, so stage 1 has to decide from the first move alone.

    The worked example in the source (White to move): best is Qxc8, queen takes a rook defended by Rf8. The naive reading is −400 ("queen for a rook"), which is where a human stops; the true exchange value is +100, because a second rook on c1 recaptures. Gating on the true value would discard this position. Gating on the naive value catches it, because what made the move hard to see was never that it loses material — it is that it looks like it does.

    piece values   pawn 100  knight 300  bishop 320  rook 500  queen 900  king 10_000

naiveCaptureValue(move) = 0                                   if not a capture
                        = value(captured) + promotionGain     if the capturer is a KING
                        = value(captured) + promotionGain − value(move.piece)  otherwise

staticExchangeEvaluation(move, in: position)
    = value(captured) + promotionGain − swapOff(target: move.to, in: after)
swapOff(target, in: position)
    = 0 when no legal recapture on target
    = max(0, value(captured) + promotionGain − swapOff(target, in: afterCheapest))

    The king exception is not theoretical. Subtracting the king's nominal 10,000 read every routine Kxf7 as a −9,500 mega-sacrifice, and the first library census returned twelve king recaptures as the twelve highest-scoring candidates across 5,748 games. A king capture is only legal on an undefended square, so nothing recaptures and nothing is risked. swapOff recurses through MoveGenerator.legalMoves(for:) rather than a private attacker list, so pins, discovered defenders and x-ray recaptures come out right for free.

    gates, in order:
  1. the move captures AND see < value(capturedPiece)
  2. naive  <= sacrificeThresholdCp   (−150)
  3. evalCp >= winningThresholdCp     ( 150)
  4. evalCp <= decidedBandCp          ( 900)

    Gate 1 is the swap-off test, and it is the one that kills free-pawn grabs. Qxf2+ where the queen is defended reads naive −800 and SEE +100 — but that +100 equals the pawn taken, so nothing came back: 100 == value(.pawn) fails see < value. Qxc8 passes it at 100 < 500. Testing whether the destination is merely attacked does not distinguish them, because f2 is attacked by a king that cannot legally take.

    score = min(−naiveCp, 900)                     // how bad it LOOKS
      + min(max(0, seeCp − naiveCp), 900) / 2  // the blind-spot gap
      + min(evalCp, 600) / 2                   // winning, not runaway
      + min(sharpnessCp ?? 0, 400) / 2         // uniqueness
      − 500  if foundIt                        // they already played it

    Finding the combination is penalized rather than filtered, so it stays available for review. Results are sorted by descending score.

    // One annotated game, through the shared reconstruction boundary.
let candidates = CombinationMiningKernel.candidates(from: input)

// Or supply positions directly (nil mines both sides — useful for master games).
let both = CombinationMiningKernel.candidates(in: positions, userIsWhite: nil)

for candidate in candidates.prefix(5) {
    print(candidate.engineBestSAN,
          "looks", candidate.naiveCp, "is", candidate.seeCp,
          "score", candidate.score)
}

    Mining combinations, stage 2¶

    validateLine(startingFEN:uciMoves:) walks the principal variation an engine probe returned and judges whether it is teachable:

    openingBalance = material(solver) − material(opponent)      // kings excluded
per move:  balance = material(solver) − material(opponent)
           maxDeficit = min(maxDeficit, balance − openingBalance)
before each OPPONENT move: opponentTurns += 1
           forcedReplies += 1 when legalMoves(position).count <= 2

netGain    = balance − openingBalance
dipped     = maxDeficit <= −150
longEnough = solverMoves >= 3

endsInCheckmate && longEnough  → .combination
!dipped || !longEnough         → .notACombination
netGain >= 0                   → .combination
otherwise                      → .truncated

    Legal forcedness is all a pure kernel can measure and it under-counts: a recapture is usually forced economically while remaining one of thirty legal moves. On the owner's line only 1 of 3 opponent turns is legally forced. Treat forcedReplies / opponentTurns as a quality signal, not a gate — a low ratio means the opponent has real alternatives, so the branch has to be handled before the puzzle is honest.

    Note

    .truncated means "promising, probe deeper" and must not be discarded. The motivating line — Qxc8 Rxc8 Rxc8+ Kh7 Rh8+ Kxh8 Nxf7+ — ends while White is 300 down; the fork's payoff lies two plies past the probe horizon. A validator demanding recovery inside the line would reject the very combination it was built for.

    Building the puzzle tree, stage 3¶

    CombinationPuzzleKernel.buildPuzzle(startFEN:lines:evaluations:policy:…) merges engine lines into a PuzzleNode tree:

    public nonisolated indirect enum PuzzleNode: Sendable, Equatable, Codable {
    case solverToMove(accepted: Set<String>, expected: String,
                      continuations: [String: PuzzleNode])
    case opponentToMove(replies: [String: PuzzleNode], mainReply: String)
    case end
}

    solver node:   accepted = [mainMove] ∪ { uci : bestCp − cp <= 50 }   (dualSolutionToleranceCp)
               continuations built ONLY for moves the supplied lines actually play
opponent node: every supplied reply is scripted
               reach *= policy[fen]?[reply] ?? 1      (no policy ⇒ treated as forced)

demand a branch for an unscripted reply when a policy exists and
    probability                >= 0.05   (minimumHumanProbability)
AND probability * reach        >= 0.05   (minimumBranchFrequency)
with no policy at all, fall back to engine proximity: bestCp − cp <= 100

    The cumulative bar is what makes completeness reachable. A 9-ply line has about four opponent nodes; three plausible replies at each demands 3⁴ branches, and every closure opens more. The local 5% floor alone is combinatorially fatal — measured on the owner's library it withheld 15 of 28 mined puzzles.

    Unscripted-but-plausible replies are emitted as UnresolvedBranch values rather than dropped, sorted by (expectedFrequency, -lossVsBestCp) descending, where expectedFrequency == (humanProbability ?? 1) * reachProbability. A puzzle that quietly omits a reply the opponent can actually play is not a smaller puzzle, it is a wrong one.

    isComplete  = unresolvedBranches.isEmpty                 // a REALISM property
isDrillable = solverMoveCount(root) >= 2
           && everyOpponentNodeHasAReply(root)
           && everyAcceptedSolverMoveHasAContinuation(root)

    Presentation gates on isDrillable, never on isComplete: the drill always plays a scripted reply, so an unresolved branch cannot strand the walk. Gating on completeness withheld 15 of 28 mined puzzles, every one of them walkable.

    scriptedReply(at:) returns mainReply when it is scripted, otherwise replies.keys.sorted().first — sorted, because dictionary order is not stable across processes and two devices drilling the same cached puzzle must see the same line. unresolvedSolverBranches(in:) reports accepted solver moves that still need their own continuation probed: an alternative cannot borrow the expected move's continuation, because unless the two transpose immediately the scripted reply may be illegal in the position the user actually reached.

    let evaluations: [String: NodeEvaluation] = [
    candidate.positionFEN: NodeEvaluation(moveEvals: ["c2c8": 480, "c1c8": 445])
]

guard let puzzle = CombinationPuzzleKernel.buildPuzzle(
    startFEN: candidate.positionFEN,
    lines: probedLines,        // [[String]] of UCI, main line first
    evaluations: evaluations,  // keyed by FEN, mover-POV centipawns
    policy: maiaPolicy         // [FEN: [UCI: probability]]; omit to fall back to eval proximity
) else { return }

puzzle.isDrillable
puzzle.unresolvedBranches.first?.expectedFrequency
CombinationPuzzleKernel.unresolvedSolverBranches(in: puzzle)   // miner work items

    Walking the drill¶

    CombinationDrillCore is a value-typed state machine that owns no board. Every board mutation comes back as an Effect the shell applies synchronously, and every board fact it needs arrives as a BoardSnapshot.

    var core = CombinationDrillCore(puzzle: puzzle)
apply(core.start())                       // [.loadPosition(fen:), .setBoardFlipped(_)]

// On EVERY cursor change — including the ones the drill caused itself.
let effects = core.boardChanged(CombinationDrillCore.BoardSnapshot(
    cursorUCI: cursorUCI,     // the move under the cursor; nil at the start position
    cursorPly: cursorPly,     // its ply index; -1 at the start position
    position: livePosition    // WITH cursorUCI already on the board
))
apply(effects)

core.solved; core.wrongAttempts; core.attempts; core.totalSolverMoves; core.isFinished

    The re-entrancy guard is a ply, not a flag: a board change is an answer only when board.cursorPly == waitingPly + 1. Everything else — the scripted reply landing at waitingPly, a take-back returning the cursor to waitingPly, loadPosition resetting it to −1, the user browsing the move list — grades nothing. waitingPly is written when the core decides, before the shell has applied anything, which is what makes the guard order-independent.

    Effect is the complete vocabulary: loadPosition(fen:), setBoardFlipped(Bool), takeBack(TakeBackReason), playReply(uci:move:), completed(solved:attempts:). It is Equatable so a golden test can assert the exact array — "exactly one take-back for one wrong move" is only assertable as an array. playReply carries both the tree's UCI and the already-parsed Move, so the shell's applier has no failure path.

    Shipped bug Structural property that now makes it unrepresentable
    Undo cascade: a take-back re-fired the check and scored the opponent's reply as another miss A wrong answer leaves node and waitingPly untouched, so the take-back's echo lands at waitingPly, not waitingPly + 1
    Uncommitted consequence: the solver's move was scored before its reply was known playable Scoring sits downstream of scriptedReply + uciToMove + advance; nothing below those guards runs without a parsed Move
    Completion stomped: finish() ran, then the caller overwrote .complete with .toMove Completion is decided in the same branch that scores, one branch, one return — no later statement exists to stomp it

    TakeBackReason.wrongMove is scored as a miss; .replyUnplayable (malformed tree, two solver nodes in a row, an unparseable scripted reply, or a missing continuation for it) is neither scored nor counted.

    Caching mined pools¶

    Mining one combination costs hundreds of engine probes plus a Maia pass per opponent node, so CombinationPuzzleStore (blob key combinationPuzzles) caches the output on the same blob substrate as every other store.

    currentSchemaVersion       = 3
currentDerivationContractID = "combination-puzzle-miner-v1|maia3-policy-serving-v2"
hasCurrentDerivation        = schemaVersion == 3 && derivationContractID == the above

stalenessReason(against: fingerprint):
    !hasCurrentDerivation           → .producerContract   (WITHHOLDS the pool)
    corpusFingerprint != fingerprint → .corpus            (warn only)
    otherwise                        → nil

    Producer incompatibility outranks corpus drift deliberately: a foreign producer contract means the bytes cannot be trusted at all, so drillable, partiallyCoveredCount and unusableCount all return empty/0. Corpus drift only means the pool may omit newer games, which is worth a warning and a re-mine offer, not a blackout. Schema 3 retires every schema-2 pool, because those may have been mined before exact-Float16 model inputs and probe-v2 health validation made Maia serving fail closed.

    The accounting is deliberately honest — "60 candidates, 9 puzzles" is the real shape of this feature:

    Field Meaning
    candidatesFound stage-1 candidates the run saw, before the score floor and cap
    discarded candidates that probed into a non-combination or past the horizon
    partiallyCoveredCount drillable puzzles that do not answer every plausible reply
    unusableCount puzzles.count - drillable.count — genuinely withheld 
    var pool = CombinationPuzzleStore.load(from: blobStore)
let fingerprint = CombinationPuzzleStore.corpusFingerprint(
    ofGameFingerprints: games.map(\.cacheFingerprint)
)

switch pool.stalenessReason(against: fingerprint) {
case .producerContract: break            // serve nothing; require a re-mine
case .corpus:           break            // serve, but offer a re-mine
case nil:               break
}

pool.adopt(puzzles: mined, corpusFingerprint: fingerprint,
           candidatesFound: 60, discarded: 51, at: .now)
pool.save(to: blobStore)

    Train hub bookkeeping¶

    PracticeMode's raw values are load-bearing — routing, deep-link tokens, and the per-drill progress key all use them:

    public nonisolated enum PracticeMode: String, Sendable, CaseIterable, Codable {
    case study = "Study"
    case repertoire = "Repertoire"      // the app displays this as "Openings"
    case tactics = "Tactics"
    case combinations = "Combinations"
    case traps = "Traps"
    case endgame = "Endgames"           // note the plural raw value
    case punish = "Punish"
}

    TrainProgressCache writes Snapshot(total:due:mastered:) under "trainProgress.\(mode.rawValue)". record(_:for:into:) no-ops when the decoded stored snapshot already equals the new one — every drill menu records its counts from its store's remote-change handler, and on CloudKit-mirrored backends the write itself posts another remote-change notification, so without the guard the handler → record → save → notification cycle is self-sustaining for as long as the pane is mounted. It compares decoded values, never raw JSON, because encoder key order is not a stable contract. For .study, total carries the mistake count and due/mastered are 0.

    Running it headless¶

    Everything above persists through the two-method seam, so a file-backed implementation is enough to run the full pipeline from a script:

    struct FileBlobStore: JSONBlobStore {
    let directory: URL

    func loadJSON(forKey key: String) -> String? {
        try? String(contentsOf: directory.appendingPathComponent("\(key).json"),
                    encoding: .utf8)
    }

    func saveJSON(_ json: String, forKey key: String) {
        try? json.write(to: directory.appendingPathComponent("\(key).json"),
                        atomically: true, encoding: .utf8)
    }
}

let blobStore = FileBlobStore(directory: workingDirectory)
var ratings = TacticsRatingStore.load(from: blobStore)
var perf = TacticsPerformanceStore.load(from: blobStore)

for puzzle in TacticsExtractor.extract(from: input, mode: .opponentBlunders) {
    let outcome: TacticsAttempt.Outcome = solve(puzzle) ? .correct : .wrong
    ratings.recordAttempt(puzzleKey: puzzle.masteryKey,
                          difficulty: puzzle.difficulty,
                          outcome: outcome,
                          in: blobStore)
    perf.record(TacticsAttempt(puzzleKey: puzzle.masteryKey,
                               outcome: outcome,
                               elapsedSeconds: elapsed,
                               attemptOrdinal: 1,
                               extractionMode: puzzle.mode.rawValue,
                               difficulty: puzzle.difficulty.rawValue),
                in: blobStore)
    BlunderMasteryStore.record(fen: puzzle.fen,
                               correctSAN: puzzle.correctMoveSAN,
                               correct: outcome == .correct,
                               in: blobStore)
}
