    Library backup & collections¶

    One portable JSON export format that the Apple app and the Android (Skip/SkipFuse) port both read and write, plus the shared kernels that validate it, stream it out in bounded memory, collapse duplicate games, and decide when a soft-deleted collection's rows may physically go away.

    Everything on this page is Foundation + ChessCore. There is no UI, no SwiftData, and no CloudKit dependency, so a command-line tool can run the same validator the app runs before it touches a user's library.

    Where the pieces live¶

    File What it owns
    LibraryBackup.swift the portable value model, LibraryBackupCategories, LibraryBackupAncillaryOverlay, and LibraryBackupCodec (config + the whole validation boundary)
    LibraryBackupAuthoredAdapter.swift the one canonical authored-history view: identity candidates, ownership, row canonicalization, the two reconciler plans
    LibraryBackupReplayableSource.swift actor-confined streaming input and LibraryBackup.Game.replaySemanticFingerprint
    LibraryBackupStreamingEncoder.swift incremental encode, ValidatedStream, StreamingError, byte accounting
    LibraryBackupSettingPolicy.swift the 40-key curated setting registry, its domains, and RatingChartWindow
    LibraryGameReconciliation.swift lossless collapse of duplicate physical game rows
    CollectionLifecycle.swift / CollectionCleanupPolicy.swift soft-deletion generations and the resumable cleanup state machine
    CollectionOwnerResolver.swift "whose archive is this?" from an explicit username or by inference

    The prose specification of the file itself is docs/BACKUP_FORMAT.md in the repo; the types below are what that document tracks.

    The portable value model¶

    LibraryBackup is the top-level Codable value. currentSchemaVersion is 1.

    Row type Carries
    Collection name, source, username, lastSyncDate, includeInOpeningBook, orderIndex, dateCreated, games
    Game the persisted, non-derived fields of a stored game (see below)
    Game.Enrichment the authored/engine-derived payload that may enrich an already-present game
    PersonalTrapRow fen, correctMoveUCI, userActualMoveUCI, gapCp, halfMoveIndex, sourceGameID, sourceOpeningName, detectedAt
    TrapScanRecord sourceGameID, trapsFound, scannedAt, optional canonical manifestJSON
    Repertoire / RepertoireMoveRow header (color, repertoireID, anchorFEN, anchorLineSAN) and its moves (positionKey, san, comment, auditDismissed, annotation)
    AuditCacheRow / PunishCacheRow one cached audit/punish generation per color, keyed by colorRaw + fingerprint
    SyncedBlobRow the single-row-per-logical-key projection of the CloudKit-synced JSON blob store (key, dataJSON, updatedAt, replicaID)
    SyncedBlobConflictRow a lossless sidecar holding the alternate payloads for one duplicated blob key; the chosen active value stays in syncedBlobs
    SettingRow / SettingValue one curated preference and its typed value (bool / int / string)

    Three rules make this shape survivable across two platforms and several app versions:

    date is a string. LibraryBackup.Game.date is the PGN yyyy.MM.dd field, not an ISO-8601 Date. It stays opaque; nothing in the codec parses it.

    Additive fields are optionals, never a schema bump. repertoires is [Repertoire]? and auditCaches, punishCaches, syncedBlobs, syncedBlobConflicts and settings are optionals defaulted to nil, so a backup written before those sections existed still decodes. The same applies inside rows: annotationMateDistancesJSON, annotationProvenanceJSON, boardArrowsJSON, consensusJSON, maiaLogLikesJSON and maiaTargetEvidenceV1JSON on Game, anchorLineSAN on Repertoire, annotation on RepertoireMoveRow.

    exportedAt is truncated at construction. Both LibraryBackup.init and LibraryBackupAncillaryOverlay.init push the date through canonicalExportDate, so the in-memory value matches what the ISO-8601 encoding can actually carry and signed byte metadata cannot claim precision the payload does not have.

    canonicalExportDate(d) = Date(timeIntervalSince1970: d.timeIntervalSince1970.rounded(.down))

    Enrichment overlay¶

    Game.Enrichment exists so a restore can add analysis and notes to a game that is already present without disturbing its PGN identity. overlayingNonEmpty(from:) is the merge:

    live.overlayingNonEmpty(from: backup)

  every String / String? field:  a non-empty incoming value wins;
                                 nil or empty NEVER erases live data

  annotationProvenanceJSON:      replaced by the backup's value only when the
                                 backup carries a non-empty annotationEvalsJSON
                                 or secondBestEvalsJSON — otherwise a
                                 provenance-less older backup would misattribute
                                 the live engine's numbers

  maiaTargetEvidenceV1JSON:      MaiaBackfillPolicy.preferredTargetEvidence(
                                     live:incoming:)   — resolved by policy,
                                 not by emptiness

    Available from the command line: fianchetto-cli maia produces the same target-evidence vector the backup carries in maiaTargetEvidenceV1JSON.

    Categories are a wire contract¶

    LibraryBackupCategories is an OptionSet naming the selective import/export categories. Persisted restore journals store its rawValue, so the bit assignments must never diverge by platform:

    .games 1 << 0   .repertoires 1 << 1   .traps    1 << 2
.caches 1 << 3  .progress    1 << 4   .settings 1 << 5
.all = the union of all six

    SettingValue's hand-written Codable¶

    Swift synthesizes Codable for an associated-value enum as a single-key object with the payload nested under _0. SettingValue hand-writes exactly that shape rather than relying on synthesis:

    {"string": {"_0": "blue"}}

    Skip/SkipFuse transpilation of a synthesized associated-value enum Codable is a portability risk, and the "obvious" flat form {"string":"blue"} would fail to decode on iOS. The decoder probes for bool, then int, then string, and throws DecodingError.dataCorrupted when none is present.

    The codec¶

    LibraryBackupCodec is the single source of truth for encoder/decoder configuration and for the entire validation boundary.

    makeEncoder():  outputFormatting     = [.withoutEscapingSlashes, .sortedKeys]
                dateEncodingStrategy = .iso8601
makeDecoder():  dateDecodingStrategy = .iso8601

    .sortedKeys is load-bearing. Without it swift-foundation emits object keys in hash-seed-dependent order that varies across processes — and, on the macOS 15 runner's older Foundation, across encode() calls within one process. Any consumer that treats the encoded bytes' SHA-256 as a payload identity (backup publication dedup and retention do) would see an unchanged library as "changed" on re-encode. Canonical key order makes that hash a true content identity.

    Note

    Sorted keys are a guarantee about what this encoder writes, not a requirement on what a reader may assume. Object key order is deliberately not part of the portable contract — parse by key, and compare documents semantically rather than byte-for-byte across implementations.

    Entry point Use
    decodeSupported(_:) decode a complete backup and enforce the whole boundary
    decodeSupportedWithAuthoredProjection(_:) the same, returning a ValidatedDecode that carries the authored projection
    encodeSupported(_:) validate, then encode, then re-check the payload ceiling
    validateSupported(_:) enforce the boundary on an already-decoded value
    decodeSupportedAncillaryOverlay(_:) / encodeSupportedAncillaryOverlay(_:) / validateSupportedAncillaryOverlay(_:) the game-free overlay equivalents
    authoredLogicalGameIDs(in:) every authored logical ID the backup's game rows safely own
    maxPayloadBytes the pre-decode byte ceiling, 512 * 1024 * 1024

    A bare JSONDecoder is never a safe entry point. Swift's Codable intentionally ignores unknown fields, so a future-schema backup would appear to restore successfully while silently dropping everything the reader does not know about — which is exactly what the schema gate below exists to prevent.

    Validation, layer by layer¶

    1. Schema gate¶

    schemaVersion <  1                        → ValidationError.invalidSchema(found:)
schemaVersion >  currentSchemaVersion (1) → ValidationError.unsupportedSchema(found:supported:)

    2. Payload ceiling¶

    maxPayloadBytes = 512 * 1024 * 1024 (536,870,912). It is checked before JSONDecoder runs in both decode paths, after encoding in both encode paths, and incrementally during streaming. An unbounded document would otherwise let a malformed multi-gigabyte file multiply its footprint inside the decoder and terminate the process.

    3. Resource ceilings¶

    Every one of these throws resourceLimitExceeded(section:limit:). Running totals use addingReportingOverflow and reject on overflow rather than wrapping.

    Section Limit
    collections 4,096
    games 250,000 across the whole backup
    collection.games 100,000 in any one collection
    repertoires 10,000
    auditCaches, punishCaches 10,000 each
    repertoireMoves 500,000 summed across repertoires
    personalTraps, trapScanRecords 250,000 each
    syncedBlobs 1,000,000
    syncedBlobConflicts 500,000
    syncedBlobAlternates 1,000,000 aggregate
    syncedBlobAlternatesPerKey 63 for a compact-head key, 10,000 otherwise
    settings 512
    syncedBlob 16 MiB per dataJSON (primary rows and alternates alike)

    The per-key alternate limit is chosen by record kind:

    perKeyLimit = AuthoredBlobRecordCodec.kind(of: conflict.key) == .compactHead
    ? AuthoredBlobRecordCodec.maximumCompactHeadAlternates   // 64 - 1 = 63
    : 10_000

    A sidecar excludes the active row, which is why the compact-head sidecar ceiling is one below maximumCompactHeadCandidates (64).

    4. Field-size classes¶

    small fields ≤ 65,536 UTF-8 bytes
  collection name / source / username     → invalidCollection(index:field: "metadata")
  game gameID                             → invalidGame(..., field: "identity")
  game white, black, date, event, result,
       opening, tagsJSON                  → invalidGame(..., field: "metadataSize")

large fields ≤ 8,388,608 bytes (8 MiB)
  moveText, annotationEvalsJSON, secondBestEvalsJSON, userNotes,
  annotationMateDistancesJSON, annotationProvenanceJSON, boardArrowsJSON,
  consensusJSON, maiaLogLikesJSON, maiaTargetEvidenceV1JSON
                                          → invalidGame(..., field: "payloadSize")

blob fields ≤ 16,777,216 bytes (16 MiB)
  every syncedBlobs[].dataJSON and every conflict alternate dataJSON
                                          → resourceLimitExceeded(section: "syncedBlob",
                                                                  limit: 16777216)

also: collection.orderIndex >= 0 and game.orderIndex >= 0

    Empty identity strings are deliberately tolerated — older stores contain unnamed collections and empty game IDs, which import adapters repair with their canonical fallbacks.

    The same per-game pass enforces two authored-identity invariants:

    userNotes must pass AuthoredNotesValue.validatePersistenceRepresentation
                                    → invalidGame(..., field: "userNotesRepresentation")

marker = AuthoredGameIdentity.marker(in: game.tagsJSON)
  throws                            → invalidGame(..., field: "authoredIdentityMarker")
  present:
    seed = GameDedup.authoredIdentityKey(
               white:, black:, date:, result:, event:, opening:,
               moveText:, tagsJSON:,
               strippingDerivedAnnotations:
                   PreparedGameData.computeIsAnnotated(
                       evalsJSON: game.annotationEvalsJSON,
                       moveText: game.moveText))
    markerBySeed[seed] exists and differs
                                    → invalidGame(..., field: "authoredIdentityMarkerConflict")

    5. Chess semantics¶

    Non-authored semantic validation runs in this order, and every check is real chess rather than a shape assertion:

    Rows Checks
    personalTraps fen parses as a Position; both correctMoveUCI and userActualMoveUCI are legal in that position (UCIParser.uciToMove); gapCp >= 0; halfMoveIndex >= 0
    trapScanRecords trapsFound >= 0 and manifestState != .malformed
    repertoires color is exactly "white" or "black"; every non-nil repertoireID is unique; anchorFEN parses
    anchorLineSAN a non-empty line requires an anchor, and its whitespace-split SAN replayed from Position.initial() (PGNParser.parseMove + MoveGenerator.applyMoveUnchecked) must end on the anchor's positionKey
    repertoire moves positionKey parses as a FEN, san parses in that position, and a present annotation is a valid MoveAnnotation(rawValue:)
    auditCaches, punishCaches colorRaw is "white"/"black" and at most one row per color
    syncedBlobs keys non-empty and unique
    syncedBlobConflicts key non-empty and unique, alternates non-empty, and a primary row with the same key exists in syncedBlobs
    settings key non-empty and unique, and LibraryBackupSettingPolicy.accepts(row)

    The ValidationError vocabulary¶

    The typed cases are a triage guide — each one names the section, the index, and where relevant the failing field.

    Case Reached by
    payloadTooLarge(limit:) pre-decode, post-encode, or a streaming chunk
    resourceLimitExceeded(section:limit:) any count or blob-size ceiling
    invalidSchema(found:) / unsupportedSchema(found:supported:) the schema gate
    invalidCollection(index:field:) collection metadata size or negative orderIndex
    invalidGame(collectionIndex:gameIndex:field:) identity, metadataSize, payloadSize, userNotesRepresentation, authoredIdentityMarker, authoredIdentityMarkerConflict
    invalidPersonalTrap(index:field:) fen, correctMoveUCI, userActualMoveUCI, numericRange
    invalidTrapScanRecord(index:) negative count or a malformed manifest
    invalidRepertoireColor(index:color:), duplicateRepertoireID(_:), invalidRepertoireAnchor(index:), invalidRepertoireAnchorLine(index:), invalidRepertoireMove(repertoireIndex:moveIndex:field:) the repertoire pass
    invalidAuditCache(index:), invalidPunishCache(index:) bad color or a second row for one color
    duplicateSyncedBlobKey(_:), invalidSyncedBlobConflict(key:) blob key uniqueness and sidecar/primary pairing
    invalidAuthoredBlob(key:), orphanedAuthoredBlob(logicalGameID:) the authored adapter and the reconciler (below)
    duplicateSettingKey(_:), invalidSettingValue(_:) the settings pass

    Authored failures are translated into those last two cases. AdapterError and every AuthoredBackupReconciler.PlanError map onto invalidAuthoredBlob(key:) except PlanError.orphanedLogicalGameID, which becomes orphanedAuthoredBlob(logicalGameID:). Three sentinel keys appear when the failure has no single row to blame: "<game-identity>" for an AuthoredGameIdentity.IdentityError, "<validated-projection>" for a re-projection source mismatch, and "<authored>" for anything else.

    Authored history¶

    LibraryBackupAuthoredAdapter is the one canonical authored view of a backup. It builds identity candidates, resolves logical-ID ownership, moves every accepted causal row onto its promoted canonical lineage, and runs the reconciler twice.

    Each backup game becomes a candidate addressed by GameOffset(collectionIndex:gameIndex:) (Comparable, ordered by collection then game):

    identitySeed        = GameDedup.authoredIdentityKey(
                          white:, black:, date:, result:, event:, opening:,
                          moveText:, tagsJSON:,
                          strippingDerivedAnnotations:
                              PreparedGameData.computeIsAnnotated(
                                  evalsJSON:, moveText:))
semanticRemoteGameID = GameIdentity.persistedRemoteID(
                          gameID: game.gameID,
                          link:   tags["Link"],
                          site:   tags["Site"])

    project(_:) then runs a deliberately two-pass validation:

    1. backup-ONLY ownership over those candidates, and
   AuthoredBackupReconciler.plan(.init(
       primaryRows:           authored rows as written,
       conflictSidecars:      authored sidecars as written,
       allowedLogicalGameIDs: backupOnlyOwnership.aliases))

   The boundary is backup-only on purpose: a live marker or semantic remote ID
   must never make an otherwise-orphan source row look valid. This pass is what
   still catches duplicate sidecars, mismatched keys, immutable-revision
   sidecars, and sidecars with no primary row — all of which could disappear
   once two aliases regroup under one canonical key.

2. canonicalize every primary row and every sidecar alternate through
   canonicalized(_:canonicalLogicalIDByAlias:); regroup alternates under the
   canonical key and emit keys in sorted order.

3. AuthoredBackupReconciler.plan(.init(
       primaryRows:           canonical rows,
       conflictSidecars:      regrouped sidecars,
       allowedLogicalGameIDs: Set(ownership.logicalIDByCandidate.values)))

   Alias-collision history conflicts surface here, before any live store is
   inspected or mutated.

    Row canonicalization decodes with AuthoredBlobRecordCodec.decode(key:dataJSON:), looks the decoded logicalGameID up in canonicalLogicalIDByAlias defaulting to itself, rekeys when the canonical ID differs, and re-emits (storageKey(for:), canonicalDataJSON(for:), row.updatedAt). Unknown IDs stay unknown by design, so the reconciler's ownership check rejects them instead of laundering an orphan into the selected set. Any failure becomes AdapterError.invalidRecord(key:).

    Projection.allowedLogicalGameIDs holds canonical lineages only. Aliases are transit and storage names, not independent game ownership.

    When live candidates are supplied to project(_:additionalCandidates:), backup rows are tagged CombinedID(kind: 0, index:) and live candidates CombinedID(kind: 1, index:) in one combined ownership replay, so a marker carried by either side can promote deterministic aliases without accepting two logical histories.

    The unforgeable shortcut¶

    reprojectValidated(_:validatedBase:additionalCandidates:) lets a restore adapter skip the raw structural plan it already paid for. The authorization is a fileprivate let validatedSourceProof on Projection — unreachable to callers, so a projection you construct yourself, or one obtained from a different backup, cannot authorize the shortcut and throws AdapterError.validatedProjectionSourceMismatch.

    The proof is recomputed with constant retained storage over exactly the inputs that can affect authored ownership:

    PortableSHA256, every field length-prefixed:

  "library-authored-source:v1"
  collections.count
  per collection: games.count
    per game: white, black, date, result, event, opening,
              moveText, tagsJSON, gameID, annotationEvalsJSON
  "primary"
    per syncedBlobs row where AuthoredBlobRecordCodec.isAuthoredKey(key):
        "row", key, dataJSON, framed(updatedAt)
    primaryRows.count
  "sidecars"
    per authored conflict row:
        "sidecar", key, alternates.count,
        per alternate: dataJSON, framed(updatedAt)
    conflictSidecars.count

framed(nil)  = "nil"
framed(date) = "date", String(date.timeIntervalSinceReferenceDate.bitPattern, radix: 16)

    Progress, repertoire and cache fields are excluded because they cannot affect authored ownership.

    Bounded-memory export¶

    JSONEncoder only hands back a payload-sized Data. The streaming encoder keeps that encoder authoritative for object fields and scalar representation but replaces aggregate arrays with incrementally emitted contents, so a 250,000-game library never needs a second full encoded copy in memory.

    Actor-confined input¶

    LibraryBackupCodec.ReplayableSource is a per-collection header plus a declared gameCount plus a replay closure that yields one LibraryBackup.Game at a time. It carries ordinary, non-@Sendable closures so a persistence actor may capture its native model objects — and it therefore declares:

    @available(*, unavailable, message: "ReplayableSource is actor-confined")
extension LibraryBackupCodec.ReplayableSource: Sendable {}

    It must be consumed synchronously by the actor that created it.

    Every traversal accumulates a field-framed replay proof:

    "library-replay-games:v1"
collections.count
per collection:  collectionIndex, declared gameCount
  per game:      collectionIndex, gameIndex, <replay fields>

<replay fields> — the same framing as LibraryBackup.Game.replaySemanticFingerprint
                  (domain "library-backup-game-replay:v2"):
  orderIndex,
  white, black, date, event, result, opening, moveText, tagsJSON, gameID,
  annotationEvalsJSON, secondBestEvalsJSON, userNotes,
  then each of annotationMateDistancesJSON, annotationProvenanceJSON,
  boardArrowsJSON, consensusJSON, maiaLogLikesJSON, maiaTargetEvidenceV1JSON
  framed as "some" + value, or "nil"

    The proof is field-framed rather than JSON-byte-based so harmless key-ordering changes cannot look like source mutation. Validation and the final write must reproduce the same proof, which is what stops a stateful source from validating one game set and encoding another. A collection that yields a different number of games than it declared throws StreamingError.replayCollectionCountMismatch(collectionIndex:expected:actual:); a later pass that proves different content throws .replaySourceChanged.

    The shell splice¶

    shell = the same value with every aggregate array emptied
        (optional arrays via `map { _ in [] }`, so nil-vs-empty presence survives)

for each aggregate property p:
    marker = "\"p\":[]" located in the encoded shell with Data.range(of:)
    absent → StreamingError.incompatibleArrayShell(property: p)
             — and NO shell bytes have been emitted yet
    insertion index = the index just before the closing ]

sort insertion points ascending, then for each:
    write shell[cursor ..< index]
    write the elements, comma-separated, each encoded independently
    cursor = index
finally write shell[cursor...]

    Nested shells apply the same trick to collections → games, repertoires → moves, and syncedBlobConflicts → alternates.

    Byte accounting and the proof¶

    maximumStreamingChunkBytes = 64 * 1_024 = 65,536

for each chunk of at most 65,536 bytes:
    (next, overflow) = byteCount.addingReportingOverflow(chunk.count)
    overflow || next > maxPayloadBytes → ValidationError.payloadTooLarge(limit:)
    emit(chunk)            ← the sink first
    hasher.update(chunk)   ← then the proof
    byteCount = next

    Only bytes the sink accepted participate in the returned ExactByteProof(byteCount:sha256:); a throwing sink owns disposal of its partial staging target.

    Warning

    Validation completes before the first byte is emitted, but a sink failure or a late aggregate size failure can still leave a partial stream on disk. Always stream into a discardable staging file and publish it only after the call returns successfully.

    validatedStream(for:) runs validateSupported and hands back a Sendable ValidatedStream, so the expensive semantic work can happen before a file-coordination lock is taken. Each write(emit:) returns its own proof, because key order is not a stable part of the portable contract.

    // Prepare before the lock; write inside it.
let stream = try LibraryBackupCodec.validatedStream(for: backup)

let handle = try FileHandle(forWritingTo: stagingURL)
let proof = try stream.write { chunk in
    try handle.write(contentsOf: chunk)
}
try handle.close()

guard proof.isStructurallyValid(
    maximumByteCount: LibraryBackupCodec.maxPayloadBytes
) else { throw ExportError.badProof }

try FileManager.default.replaceItemAt(publishedURL, withItemAt: stagingURL)

    Streaming straight from a persistence actor, without materializing the games:

    let source = LibraryBackupCodec.ReplayableSource(
    exportedAt: Date(),
    collections: storedCollections.map { stored in
        .init(
            name: stored.name,
            source: stored.source,
            username: stored.username,
            lastSyncDate: stored.lastSyncDate,
            includeInOpeningBook: stored.includeInOpeningBook,
            orderIndex: stored.orderIndex,
            dateCreated: stored.dateCreated,
            gameCount: stored.games.count,
            replayGames: { visit in
                // One game in memory at a time. `prepared` is the adapter's own
                // PreparedGameData projection; the enrichment is built beside it
                // so PGN identity and authored payload never get mixed up.
                for row in stored.games {
                    try visit(LibraryBackup.Game(
                        prepared: row.prepared,
                        enrichment: .init(
                            annotationEvalsJSON: row.annotationEvalsJSON,
                            secondBestEvalsJSON: row.secondBestEvalsJSON,
                            userNotes: row.userNotes
                        )
                    ))
                }
            }
        )
    },
    personalTraps: traps,
    trapScanRecords: scans,
    repertoires: repertoires,
    didEncodeGame: { completed, total in
        progress.update(completed: completed, total: total)
    }
)

let proof = try LibraryBackupCodec.streamSupported(source) { chunk in
    try handle.write(contentsOf: chunk)
}

    Ancillary overlays¶

    LibraryBackupAncillaryOverlay is a prior export's ancillary rows without its game graph. collections and repertoires are absent from the encoded shape: a persistence adapter already owns their live representation, and decoding last export's whole game graph just doubles the dominant memory cost.

    init(projecting:) builds one from a full backup; ancillaryEnvelope produces a compatibility LibraryBackup with empty collections and nil repertoires for existing ancillary merge kernels.

    Warning

    An overlay envelope is not a backup and must never be published directly. Authored ownership cannot be checked without game rows, so overlay authored rows must go through AuthoredBackupReconciler against the adapter's live ownership before anything is emitted or persisted.

    Curated settings¶

    LibraryBackupSettingRegistry.definitions holds 40 canonical, platform-neutral keys. Each is a LibraryBackupSettingDefinition (key + LibraryBackupSettingRule); platform adapters keep only their own physical UserDefaults / SharedPreferences mapping.

    20 bools — soundEnabled, hapticsEnabled, autoAnnotateOnImport, consensusAnnotation, pref.secondOpinion, updateGamesFullSweep, explorerAutoFollow, drillAutoAdvance, drillShowArrows, punishDrillSkipMastered, reviewQuizSkipMastered, trapDrillSkipMastered, endgameEndToEnd, otbAutoFlip, showCoordinates, showLegalMoveHints, autoICloudBackupEnabled, defaultStockfishEval, defaultMaiaEval, confirmGameDelete.

    9 bounded ints (inclusive ranges):

    Key Domain
    drillSessionSize 1…100
    checkmateIntensity 0…3
    missedMateMaxN 2…10
    punishTopK 2…8
    punishOpponentElo 800…2,400
    autoICloudBackupRetention 1…30
    masteryThreshold 2…10
    tacticsSwingThreshold 50…1,000
    stockfishDepthLimitPersisted 0…128

    11 bounded strings, every one .string(maximumUTF8Bytes: 256) — boardTheme, pieceSet, explorerDatabase, annotateThoroughness, annotationEngine, tacticsMode, drillStrictness, evalDisplayFormat, libraryGameSort, ratingChartWindow, otbLastTimeControl.

    LibraryBackupSettingPolicy.accepts(row)
    = LibraryBackupSettingRegistry.definition(forKey: row.key)?
          .rule.accepts(row.value) ?? true

  UNKNOWN key   → accepted (forward compatibility; adapters apply only keys in
                  their own physical mapping)
  KNOWN key     → the value kind must match exactly, and:
                     .int(minimum: a, maximum: b)  (a...b).contains(value)
                     .string(maximumUTF8Bytes: n)  value.utf8.count <= n

    normalizedPortableRow(_:) adds one canonicalization on top. Older Apple builds stored lowercase rating-window values while Android stored display labels ("3M", "6M", "1Y", "All"):

    normalizedPortableRow(row)
    !accepts(row)                      → nil
    row.key != "ratingChartWindow"     → row unchanged
    row.key == "ratingChartWindow":
        value must be .string, and RatingChartWindow(storedValue:) must map it
        (trim whitespace/newlines, lowercase)
        → re-emitted as the canonical lowercase rawValue: "3m" | "6m" | "1y" | "all"
        → unmappable value returns nil, so the row is DROPPED rather than
          persisted as a picker selection no UI can represent

    RatingChartWindow also exposes shortLabel (3M/6M/1Y/All) and monthOffset (-3, -6, -12, nil for .all). It conforms to Identifiable but has no UI dependency.

    let safeRows = (backup.settings ?? [])
    .compactMap(LibraryBackupSettingPolicy.normalizedPortableRow)

    Duplicate-game reconciliation¶

    LibraryGameReconciliation plans the lossless collapse of multiple physical rows that are the same logical game. It is persistence-agnostic: preview and execution consume the same immutable Plan — update each survivor from originalGame to mergedGame, then delete exactly deleteIndices. Keeping the survivor preimage also lets an undo adapter restore both sides.

    let plan = LibraryGameReconciliation.plan(games: rows)

if plan.hasChanges {
    for survivor in plan.survivors {
        store.update(at: survivor.inputIndex, to: survivor.mergedGame)
    }
    store.delete(at: plan.deleteIndices)   // already sorted ascending
}
print("\(plan.deletionCount) rows collapsed, \(plan.retainedIndices.count) kept")

    Grouping¶

    BaseProof = (normalizedPersistedID, logicalKey, coreFingerprint, positionSequence)

fingerprint          = GameDedup.compositeKey(white:black:date:result:event:opening:
                                              moveText:tagsJSON:
                                              strippingDerivedAnnotations:)
stableID             = GameIdentity.stableID(gameID:link:site:contentID: fingerprint)
logicalKey           = GameDedup.key(gameID: stableID, compositeKey: fingerprint)
authoritative        = (logicalKey is .remoteID)
coreFingerprint      = authoritative ? "" : fingerprint
positionSequence     = GameDedup.positionSequenceProof(game.moveText,
                                                       tagsJSON: game.tagsJSON)
normalizedPersistedID = GameIdentity.canonicalProviderID(game.gameID)
                     ?? PreparedGameData.normalizedGameID(game.gameID)

    Two field incidents shaped that key:

    • Canonical, not raw, persisted ID. normalizedGameID only trims, so "https://www.chess.com/game/live/171115885774" and "chesscom:171115885774" stay different strings for the same game — while logicalKey, which runs canonicalProviderID, already says they are one. The raw form defeated the canonical one: same logical key, different base proof, never grouped. Latent until commit 73a36701 (2026-07-11) made imports write the canonical form; 96 such pairs were then found in the owner's library, confirmed by identical final-position FENs.
    • Authoritative groups drop text sensitivity. When the logical key is .remoteID, coreFingerprint is stored as the empty string. One chess.com game held three rows, two carrying {[%clk 0:09:54.6] +0.4; best Nf3} and one carrying only {[%clk 0:09:54.6]}. Identical moves, clocks and remote ID — but strippingDerivedAnnotations is computed per row and did not reduce those comments to the same text, so the fingerprints differed, the rows never entered one group, and a completed repair pass left 542 rows untouched. The position-sequence proof is what actually guards this. Content-keyed groups keep the strict fingerprint, since text identity is their only evidence.

    Subsumption¶

    A survivor may absorb a source only if it can prove nothing is lost:

    target.subsumes(source, authoritativeIdentity:)

both modes first require
    source.boardArrows == nil || source.boardArrows == target.boardArrows
        — board arrows are user-authored; never delete a row carrying arrows the
          survivor does not already hold

authoritative (recognized remote ID: provably one online game):
    if source.hasGlyphedMainLine && source.derivedMoveText == nil
       && source.glyphLine != target.glyphLine        → NOT subsumed
        — nothing but the user's hand explains glyphs on a row with no engine
          annotation in either format
    for f in {derivedMoveText, annotationEvals, secondBestEvals,
              mateDistances, annotationProvenance, consensus}:
        require source.f == nil || target.f != nil     ← PRESENCE only
        — a redundant engine run is droppable; a COMPLEMENTARY partial analysis
          is never lost, and the survivor keeps its own values

content-keyed:
    for the same six fields: require source.f == nil || source.f == target.f

    Search and survivor preference¶

    Rows are projected once and bucketed by BaseProof; only buckets with more than one member enter candidate work. Projection and exact-base grouping are linear in total input; the deterministic greedy reconciliation is at most cubic within one conflicting group. Inside a group the loop runs while more than one index remains available, evaluating each still-available index as a survivor over the order-preserving filtered list — never Set or Dictionary iteration order.

    isPreferred(lhs, over: rhs) — first difference wins:
  1. isAnnotated          annotated beats unannotated
  2. positionRichness     higher   (non-nil count among the 7 position fields)
  3. enrichmentRichness   higher   (positionRichness + non-empty note + non-empty maia)
  4. derivedDepth         higher   moveText.count
                                 + annotationEvalsJSON.count
                                 + secondBestEvalsJSON.count
                                 + annotationMateDistancesJSON?.count ?? 0
                                 + annotationProvenanceJSON?.count ?? 0
                                 + consensusJSON?.count ?? 0
                                 + merged.maiaTargetEvidenceV1JSON?.count ?? 0
  5. orderIndex           LOWER
  6. deleteIndices.count  higher
  7. survivorIndex        lower

    The independent userNotes / maiaLogLikesJSON pair is chosen without a Cartesian product:

    choices = { (target.note, target.maia) }
        ∪ { (target.note ?? s.note, target.maia ?? s.maia) for each observed pair s }
        ∪ { (most frequent note-only, most frequent maia-only) }
              — only when the target has NEITHER; ties break to the
                lexicographically smaller value

deletionCount(choice) = freq(nil,  nil)
                      + freq(note, nil)   if choice.note != nil
                      + freq(nil,  maia)  if choice.maia != nil
                      + freq(note, maia)  if both != nil

discard deletionCount == 0, then maximize:
  enrichmentRichness, then deletionCount, then choicePrecedes
  (nil sorts before any value, then lexicographic on note, then on maia)

maiaTargetEvidenceV1JSON folds over the deleted rows through
MaiaBackfillPolicy.preferredTargetEvidence(live:incoming:)

    Collection lifecycle¶

    CollectionLifecycle encodes soft deletion for a CloudKit-synchronized collection in one signed Int64 per parent, so an existing store adopts the protocol without a destructive migration.

    parent scalar:  0        active LEGACY generation (CollectionLifecycle.legacyGeneration)
                positive active generation
                negative deletion generation (a soft tombstone)
child scalar:   the non-negative active generation it was attached to;
                a MISSING child value means legacy generation 0

parentState(lifecycleVersion: v)
    v >= 0 → .active(generation: v)
    v <  0 → .deleted(generation: v == Int64.min ? Int64.max : -v)
             — avoids trapping on abs(Int64.min); an extreme value is
               conservatively the largest representable tombstone

activeGeneration(lifecycleVersion: v) = v >= 0 ? v : nil
    — nil for a tombstone, so a writer cannot stamp a child into a deleted parent

childDisposition(parentLifecycleVersion: v, childIncarnation: c)
    g = c ?? 0
    g < 0                       → .deferred   (outside the wire contract: quarantine,
                                               never destroy on an invalid value)
    parent .active(p):  g == p  → .visible
                        g <  p  → .stale
                        g >  p  → .deferred
    parent .deleted(d): g <= d  → .stale      (the tombstone wins at its own
                                               generation too)
                        g >  d  → .deferred   (a reactivation parent record has
                                               not arrived yet)

isSettledActiveRelationship(parentLifecycleVersion:childIncarnations:)
    requires a non-nil activeGeneration and EVERY child .visible

deletionVersion(after: v)      .deleted        → v          (idempotent on retry)
                               .active(g)      → -(g + 1)
                               .active(Int64.max) → -Int64.max
reactivationVersion(after: v)  generation == Int64.max ? nil : generation + 1

    Only .visible children belong in user-facing reads. .stale children under a deleted parent are what become eligible for physical cleanup; .deferred means CloudKit delivered records out of order — retain and retry.

    The rollout gate¶

    CollectionLifecycle.SoftDeletionReadiness keeps activation explicit so that merely adding lifecycle fields to the local model cannot switch on a wire protocol older peers cannot interpret:

    permitsProtocolV1 = productionSchemaReady && compatibleClientFloorReady

.disabled        = (false, false)
.protocolV1Ready = (true,  true)

    Resumable cleanup¶

    CleanupSnapshot is the exact parent tombstone plus child-generation set observed at an import-idle boundary. Children are canonicalized on init — sorted by token, then incarnation with nil ordering before any value — so equality is deterministic across fetch order, process launches, and JSON round trips.

    CleanupSnapshot.isStructurallyValid   (fail closed on every count)
    parentToken non-empty and <= 8 * 1_024 UTF-8 bytes
    tombstoneVersion < 0 and != Int64.min
    children.count <= maximumCleanupChildrenPerCollection (250,000)
    every child token non-empty, <= 8 * 1_024 UTF-8 bytes, and unique

isExactSubset(of: authorized)
    both snapshots structurally valid
    same parentToken and same tombstoneVersion
    children.count <= authorized.children.count
    every child ∈ Set(authorized.children)

    staleChildTokens and deferredChildTokens are derived through CollectionLifecycle.childDisposition, so read filtering and cleanup authority never drift apart.

    requiredStableCleanupObservations = 2

cleanupTransition(previous:current:observationToken:)

  current invalid, or observationToken empty / > 8 * 1_024 bytes,
  or the retained observation invalid    → .blocked, previous observation preserved
  previous == nil                        → .observing, count 1, action .none

  .observing, SAME lastObservationToken
      identical snapshot                 → no-op (.none)      ← a replayed
                                                                notification never
                                                                increments stability
      different snapshot                 → restart .observing
  .observing, NEW token
      different snapshot                 → restart .observing
      identical, no stale children       → .quiescent, .none
      identical, stale children          → .cleaning,
                                           .cleanup(authorization: current,
                                                    eligibleChildTokens:
                                                        current.staleChildTokens)
  .cleaning
      current not an exact subset of the retained authorization
                                         → restart .observing  ← any ADDITION or
                                                                 generation change
      stale set empty                    → .quiescent, .none
      otherwise                          → re-issue the RETAINED authorization for
                                           another bounded batch
  .quiescent
      snapshot changed                   → restart .observing
      identical                          → no-op (.none)

    Missing children while .cleaning are safe: a prior batch or a peer already removed them, which is exactly why resumption uses subset containment rather than equality.

    let snapshot = CollectionLifecycle.CleanupSnapshot(
    parentToken: parentToken,
    tombstoneVersion: CollectionLifecycle.deletionVersion(after: parentVersion),
    children: childRows.map {
        .init(token: $0.token, incarnation: $0.incarnation)
    }
)

let transition = CollectionLifecycle.cleanupTransition(
    previous: storedObservation,      // CleanupObservation?
    current: snapshot,
    observationToken: completedImportPassID
)
storedObservation = transition.nextObservation

switch transition.action {
case .none:
    break
case .cleanup(let authorization, let eligibleChildTokens):
    try deleteChildren(eligibleChildTokens, authorizedBy: authorization)
case .blocked:
    // Fail closed: preserve every row for manual diagnosis.
    logger.error("cleanup blocked for \(parentToken)")
}

    CleanupObservation.isStructurallyValid ties the counter to the phase: stableObservationCount == 1 in .observing, == 2 in .cleaning, and == 2 with an empty stale set in .quiescent.

    Owner resolution¶

    Online imports carry an authoritative account username. Ordinary PGN files do not, but a typical personal archive has one player in every game and varying opponents. CollectionOwnerResolver recognizes only that unambiguous shape.

    normalized(name) = name.trimmingCharacters(in: .whitespacesAndNewlines).lowercased()

resolve(explicitUsername:games:)
    explicit = normalized(explicitUsername)
    explicit non-empty                                        → explicit
    games.count < 2                                           → nil
    for every game:
        white = normalized(game.white), black = normalized(game.black)
        either empty, either a placeholder, or white == black → nil
        intersection ∩= {white, black}; empty                 → nil   (early bail)
    intersection.count == 1                                   → that name
    otherwise                                                 → nil

placeholders (8): "?", "unknown", "anonymous", "anon",
                  "white", "black", "player", "computer"

    Every other shape fails closed, so an opponent, a placeholder, a match collection, or a one-off PGN cannot be mistaken for the user.

    let owner = CollectionOwnerResolver.resolve(
    explicitUsername: collection.username,      // "" for a plain PGN import
    games: parsed.map {
        CollectionOwnerResolver.GamePlayers(white: $0.white, black: $0.black)
    }
)

    Using it headlessly¶

    A complete validate-and-rehash pass needs nothing but Foundation and ChessCore:

    import FianchettoKit

let data = try Data(contentsOf: url)

// Decode + schema gate + resource ceilings + chess semantics + authored plans.
let validated = try LibraryBackupCodec.decodeSupportedWithAuthoredProjection(data)
let backup = validated.backup

print("schema \(backup.schemaVersion), exported \(backup.exportedAt)")
print("\(backup.collections.count) collections, "
    + "\(backup.collections.reduce(0) { $0 + $1.games.count }) games")
print("\(validated.authoredProjection.allowedLogicalGameIDs.count) authored lineages")

// Canonical re-encode: sorted keys make this SHA-256 a content identity.
let canonical = try LibraryBackupCodec.encodeSupported(backup)
let identity = ExactByteProof(bytes: canonical)
print(identity.sha256, identity.byteCount)

// Every logical ID the game rows safely own, aliases included.
let owned = try LibraryBackupCodec.authoredLogicalGameIDs(in: backup)

    fianchetto-cli today exposes the engine and estimation seams — fianchetto-cli annotate, estimate, maia, accuracy, project, track — and none of the backup kernels yet. The natural additions, each one file conforming to CLICommand over the APIs above, would be:

    Proposed subcommand Would wrap JSON-lines contract
    backup-validate decodeSupportedWithAuthoredProjection(_:) one line per input file: {"path", "ok", "error"} with the ValidationError case name and its associated values
    backup-proof streamSupported(_:emit:) into /dev/null {"path", "byte_count", "sha256"} — the publication identity without writing a copy
    reconcile LibraryGameReconciliation.plan(games:) games in, {"survivors": [{"input_index", "delete_indices"}], "delete_indices"} out
    settings LibraryBackupSettingPolicy.normalizedPortableRow(_:) rows in, normalized rows out plus a dropped reason
    owner CollectionOwnerResolver.resolve(explicitUsername:games:) {"white", "black"} lines in, one {"owner"} line out
    lifecycle CollectionLifecycle.cleanupTransition(previous:current:observationToken:) a snapshot per line, the transition's phase and action per line

    Those are proposals, not shipped commands. The library APIs they would call are the ones documented above, and all of them run without a UI.
