    Library Store Kernel¶

    The persistence and transaction core for the whole game library: one LibraryStoreKernel owns load/save lifecycle, mining admission, chunked import, backup/restore, and every dedup/reconciliation pass, all driven off one JSON aggregate (LibraryData). It was hoisted out of the Android shell's LibraryFileStore class (the "T4 class move") so both platforms — and a headless CLI — share the exact same transaction logic instead of maintaining parallel copies that drift.

    Kernel, context, and ownership¶

    LibraryStoreKernel is @MainActor and imports only Foundation and ChessCore — no SwiftUI, no UIKit, no app-lifecycle dependency anywhere in this subsystem. It publishes UI-visible state through a small protocol seam rather than owning @Observable state itself:

    @MainActor
public protocol LibraryStoreContext: AnyObject {
    var data: LibraryData { get set }
    var isLoaded: Bool { get set }
    var saveErrorMessage: String? { get set }
    var minedEndgameRepairMessage: String? { get set }
    var semanticCollectionMigrationNotice: String? { get set }
}

    A platform shell's @Observable store conforms automatically (its stored properties are named to match), then wires itself in with kernel.attach(context: myObservableStore), which starts the deferred off-main decode. The ownership direction is deliberate: attach(context:) stores the context weakly and the facade that created the kernel holds the kernel strongly, so the kernel can never keep a platform shell alive. LibraryStorePlatformAdapter(settingsRestorer:settingsSnapshot: repertoireExportDirectory:repertoirePieceArt:) carries the four things the kernel is not allowed to hard-code; a nil settingsRestorer just means platform settings are disabled for that store instance — no JVM-backed UserDefaults bridge required. repertoirePieceArt is a (() -> [String: String])? closure from canonical piece-set key to raw SVG text, wired by whichever shell owns the current piece art and used by the repertoire HTML export's board diagrams; nil selects the exporter's Unicode fallback. It is a seam rather than a defaulted kernel argument for a concrete reason: the piece-set choice is the shell's to make, and the choice of whether it is honored has to stay visible. Apple once honored the user's piece set in an exported repertoire while the store-kernel export path silently fell back to Unicode glyphs — one account, one repertoire, no error anywhere (M11).

    File Responsibility
    LibraryStoreKernel.swift load lifecycle, stats/mining admission bookkeeping, incarnation tokens, persistence batches
    LibraryStoreKernel+Mutations.swift collection/game CRUD, chunked online import, dedup, repertoire builder, PGN/HTML export
    LibraryStoreKernel+PGNImport.swift pasted/bulk PGN import with a crash-recovery journal

    The data model — LibraryData¶

    The entire library is one Codable, Sendable, Equatable struct persisted as a single JSON blob under the reserved key "library". Cascade is structural, not referential: Game rows live inside Collection.games, and RepMove rows live inside Repertoire.moves. Deleting a Collection drops every game it contains — there is no foreign-key layer to keep in sync.

    public struct LibraryData: Codable, Sendable, Equatable {
    public var collections: [Collection] = []
    public var repertoires: [Repertoire] = []
    // installation-local: never projected into a portable LibraryBackup
    public var localCollectionIncarnations: [LocalCollectionIncarnation] = []
    public var localGameIncarnations: [LocalGameIncarnation] = []
    public var pendingPGNImport: PendingPGNImport? = nil
    public var pendingAuthoredMutation: PendingAuthoredMutation? = nil
    // locally mined content — coexists with anything imported via LibraryBackup
    public var minedTraps: [PersonalTrapData] = []
    public var minedScanRecords: [PersonalTrapScanRecordData] = []
    public var minedEndgames: [PersonalEndgamePositionData] = []
}

    Every nested type (Collection, Game, Repertoire, RepMove) hand-writes its own init(from:) instead of using the synthesized decoder, and every field goes through decodeIfPresent(...) ?? default:

    public init(from decoder: Decoder) throws {
    let c = try decoder.container(keyedBy: CodingKeys.self)
    id     = try c.decodeIfPresent(UUID.self,   forKey: .id)     ?? UUID()
    white  = try c.decodeIfPresent(String.self, forKey: .white)  ?? ""
    // ...
    orderIndex  = try c.decodeIfPresent(Int.self,  forKey: .orderIndex)  ?? 0
    dateCreated = try c.decodeIfPresent(Date.self, forKey: .dateCreated) ?? Date(timeIntervalSince1970: 0)
}

    The synthesized JSONDecoder throws keyNotFound for a non-optional property even when a default value is declared, so a naive struct would make a library blob written before some new field shipped fail to decode entirely — silently losing the whole library on the next app update. decodeIfPresent ?? default is the back-compat pattern every schema addition in this subsystem must follow.

    Some fields are decode-lenient in a stronger sense

    minedEndgameProjectionSelection fails toward the conservative state on any decode error: a malformed or unrecognized schema version sets minedEndgameRestoredLegacyAuthoritySelected = true and clears the derived projection, rather than aborting the whole library decode. MinedEndgameProjectionSelection.currentSchemaVersion is 1; the type is a tagged .v1(EndgameMiningProjectionReceipt) / .v2(EndgameMiningV2ProjectionReceipt) enum so exactly one receipt format is authoritative at a time.

    Game and collection identity¶

    GameIdentity decides whether a game has a real remote reference or needs a deterministic content ID, and GameDedup turns that decision into a fingerprint every import, backup-merge, and reconciliation path shares.

    contentPrefix       = "content:v2:"
legacyContentPrefix = "content:v1:"
legacyReferenceTag  = "FianchettoLegacyGameID"

canonicalProviderID(raw):
  lichess:  8–12 ASCII alphanumeric chars, from "lichess:<id>" or a
            lichess.org/www.lichess.org URL's first path segment — excluding
            reserved words (analysis, broadcast, calendar, editor, features,
            insights, password, practice, streamer, study, timeline, training)
            → canonicalized to "lichess:<first 8 chars>"
  chesscom: all-ASCII-digit, from "chesscom:"/"chess.com:" or a chess.com /
            www.chess.com URL matching .../game/{live,daily,arena}/<id> or
            .../{live,daily,arena}/game/<id> (an optional leading "analysis"
            segment is stripped first)
            → canonicalized to "chesscom:<digits>"
  else → nil (Site is just a venue, not an ID)

    Lichess's stable component is explicitly the first eight case-sensitive characters, which is why a 12-character URL slug and its 8-character canonical form resolve to one identity.

    Degenerate URLs must not trap

    A raw PGN Site/Link tag or a deep-link token reaches this parser unvalidated. A bare "https://" splits to an empty component array; the internal host/path split used to subscript that array directly, which trapped — and turned one poisoned row into a crash-on-launch loop, because stableGameID re-evaluates identity on every read and re-hit the same trap every time (perf/stability audit, 2026-07-19). canonicalProviderID's host/path split now uses a guarded .first instead of a subscript, so a value with no usable host simply yields nil.

    Recovering identity from a persisted row¶

    canonicalProviderID alone only tells you whether a given string is a provider ID. Reading back a persisted row needs more: older builds sometimes copied Site into gameID outright, and rows promoted from content identity to a real remote ID must not orphan the history keyed on the old identity. Three functions carry that weight.

    persistedRemoteID(gameID:link:site:) recovers the semantic remote ID without rewriting anything, applying four fallbacks in order:

    1. remoteID(link:site:) is non-empty            → that canonical value
2. gameID is a content ID                       → ""
3. gameID canonicalizes as a provider ID        → its canonical form
4. gameID == Link, or gameID == Site            → ""      (see below)
   otherwise                                    → gameID  (backup compatibility)

    Rule 4 exists because many PGN producers reuse a single archive, event, or article Link across every game in a file, and older Fianchetto builds persisted any non-empty Link as a per-game ID. Those rows project to content identity at runtime instead of continuing to collapse distinct games together. stableID(gameID:link:site:contentID:) layers on top: the persisted remote ID, else the explicit ID when it is already a content ID, else the lazily evaluated contentID() — the @autoclosure means an ID-bearing row never pays for content hashing.

    promotingIdentity(_:gameID:tagsJSON:) records an authoritative remote identity without discarding the durable reference already in gameID. A recognized provider ID is written into the Link tag and gameID is left untouched; an unrecognized external ID replaces gameID instead, and the previous value is stashed under the internal FianchettoLegacyGameID tag (legacyReferenceTag) for later reference repair.

    UnambiguousAliasAccumulator is the streaming form of unambiguousAliasMap for auxiliary records (trap and scan rows, which reference a game by an alias rather than owning its identity directly). record(alias:stableID:) normalizes both sides and ignores empties; the first contradicting stableID for an alias removes it from the map and marks it permanently ambiguous. stableID(forAlias:) therefore returns non-nil only when every recorded occurrence named the same game, and canonicalIdentifier(_:) falls back to the normalized spelling when no unambiguous mapping exists. A shared Site value — two different games played at the same tournament, say — ends up attached to no game rather than to an arbitrary one.

    GameDedup.compositeKey is the SHA-256 (via PortableSHA256) content fingerprint used when a game has no recognized remote ID:

    payload = length-prefixed(white) ++ length-prefixed(black) ++ length-prefixed(date)
        ++ length-prefixed(result) ++ length-prefixed(event) ++ length-prefixed(opening)
        ++ canonical-move-tree ++ sorted-non-mirror-PGN-tags

canonical-move-tree: each PGN token tagged
  0 = move (SAN, optionally suffix-stripped of trailing !/? if
      strippingDerivedAnnotations and at variation depth 0)
  1 = variationStart   2 = variationEnd
  3 = comment (dropped if it reduces to nothing but an engine eval/best-move)
  4 = nag

compositeKey        = "content:v2:" + SHA256(payload)
authoredIdentityKey = "authored-content:v1:" + SHA256(payload, excluding Link + legacy migration tag)
legacyPromotionKey  = "promotion:v1:" + SHA256(main-line-only payload, excluding Link)

    authoredIdentityKey additionally excludes the Link tag, so promoting a row from content identity to a real remote ID never orphans its authored history. legacyPromotionKey is deliberately looser (no comments, NAGs, or variations) and is used only to promote one unambiguous legacy local row when a fetch later supplies its recognized remote ID — ordinary import and destructive dedup always use compositeKey.

    GameDedup.MatchIndex<Value> is the generic lookup every import/merge/ reconciliation path builds over a collection, and its Resolution is the one vocabulary every one of those paths switches on:

    public enum Resolution {
    case none                     // insert a new row
    case unique(Value)            // merge into the existing row
    case ambiguous                // multiple strong-key matches — skip, never guess
    /// Strong key had no match, but the relaxed legacy-promotion fingerprint
    /// named multiple local rows. Callers must not pick one.
    case ambiguousLegacyPromotion
}
let resolution = matchIndex.resolution(
    for: GameDedup.Identity(preparedGame),   // GameDedup.Identity(_: PreparedGameData)
    allowLegacyCompositeFallback: true
)

    Durable persistence¶

    LibraryAggregatePersistenceWriter is one serial DispatchQueue lane per physical aggregate-library file path. Synchronous edits call writeSynchronously, off-main imports/maintenance call writeAsynchronously, and restore installs pre-encoded JSON via installEncodedJSONSynchronously — all three funnel through the same queue, so an older async snapshot can never install after a newer synchronous save or restore. A private AsyncCompletionGate actor additionally leases the entire prepare→write→publish sequence for async callers, not just the physical write, so a failed async write finishes its MainActor rollback before a second async caller can snapshot or publish. LibraryAggregatePersistenceWriterRegistry hands out one weakly-held writer per standardized file path (capped at 256, GC-swept on overflow).

    Bulk import writes the whole library repeatedly, so the chunk size adapts to the import size instead of using a fixed page:

    minimumGameImportChunkSize = 1_000
maximumGameImportSaveCount = 4

gameImportChunkSize(for: incomingGameCount):
  quotient  = incomingGameCount / 4
  remainder = incomingGameCount % 4
  size      = quotient + (remainder == 0 ? 0 : 1)
  return max(1_000, size)

    A 50,000-game import therefore chunks at 12,500 games/write (4 whole-library replacements); a 400-game import stays at one 1,000-game chunk (1 write) — the floor exists so a small import never chunks into several tiny writes. kernel.saveNewCollectionInChunks(_:) drives this: each chunk boundary is its own atomic aggregate replacement with a closure-based rollback if that specific write fails, and the returned ChunkedGameWriteResult.inserted count reflects only chunks that actually became durable.

    Capability tokens¶

    Every collection and game carries an opaque incarnation token (CollectionIncarnation / GameIncarnation) that changes only when the row is durably deleted and recreated — even if its public UUID is reused. A retained editor presents its incarnation back to the kernel; if the token no longer matches, the mutation is rejected as .staleOwner instead of quietly overwriting an unrelated row that happens to share a UUID:

    guard let incarnation = kernel.gameIncarnation(for: gameID, in: collectionID) else {
    return   // row no longer exists, or is ambiguous
}
let result = await kernel.updateGame(
    incarnation,
    expecting: GameEditableProjection(game: originalSnapshot),
    white: "Carlsen, M", black: "Nakamura, H",
    event: newEvent, date: newDate, site: newSite, userNotes: notes
)
switch result.outcome {
case .saved:             dismissEditor()
case .conflict:          showConflictBanner(result.failureDescription)
case .staleOwner:        showReplacedBanner(result.failureDescription)
case .persistenceFailed: retry()
}

    updateGame acquires its own internal ChunkedMutationLease — chunked mutations and semantic-collection migrations use that same lease type as an exclusive, fail-closed guard, not a queued lock: beginChunkedMutation() returns nil immediately to a concurrent caller instead of waiting, so a cancelled task can never strand ownership. PersistenceBatch is the caller-owned counterpart for deferred writes — beginPersistenceBatch() opens a stream, markPersistenceBatchDirty records uncommitted work, and flushPersistenceBatch/finishPersistenceBatch commit it — while ordinary mutation APIs called without a batch token still save immediately, so a long batch can never suppress an unrelated user edit.

    Reserved blob key Purpose
    library the aggregate LibraryData
    library.preRestoreRecovery.v1 pre-restore undo snapshot
    library.corruptRecovery.v1 preserved bytes when the aggregate fails to decode
    minedEndgames legacy flat mined-endgame projection key
    local.authoredReplicaID.v1 this installation's authored-mutation replica identity

    Mining admission¶

    Trap, endgame, and combination-puzzle mining share one admission model with three independent purposes:

    public enum MiningAdmissionPurpose: Sendable, Equatable {
    case traps, endgames, combinations
}

    Three separate monotonic counters gate them: miningSourceCoverageEpoch (advances only after a durable source-changing mutation — an unrelated annotation/cache write does not bump it), trapMiningEligibilityEpoch (advances only when trap scan witnesses are deliberately cleared), and aggregatePersistenceRevision (consulted only for .combinations, since combination inputs include annotation payloads that fall outside the narrower trap/endgame source epoch). Trap mining additionally holds one exclusive session (activeTrapMiningSessionID: UUID?) so two trap miners can never publish scan witnesses concurrently — endgame results are positive FEN rows and stay safely additive, so no equivalent session exists for that purpose.

    let decision = kernel.miningAdmissionSnapshot(for: .traps)
guard let snapshot = decision.snapshot else {
    showBanner(decision.failureMessage!)   // e.g. "another mining run is active"
    return
}
defer { kernel.releaseMiningAdmission(snapshot.token) }
let manifests = mineTraps(from: snapshot.library)   // pure, off-main
_ = kernel.replaceMinedTrapProjections(manifests, admissionToken: snapshot.token)
// if validateMiningAdmission(snapshot.token, for: .traps) is no longer
// .isCurrent, the library changed mid-run: results already saved were
// kept, but coverage may be incomplete — mine again

    Mined traps dedup on insert by "\(trap.fen):\(trap.correctMoveUCI)", so a re-run that crosses a cancelled boundary never inserts the same trap twice. The materialized endgame projection uses a UUID-keyed compare-and-swap instead — MinedEndgameProjectionAuthority.mutationID changes on every mutation (never reused, so no ABA), and replaceMinedEndgameProjection(...) returns:

    public enum MinedEndgameProjectionInstallOutcome: Sendable, Equatable {
    case installed(changed: Bool)
    case superseded      // a newer local authority already replaced this one
    case sourceChanged   // the admitted library source universe moved
    case failed
}

    Backup and restore¶

    A full backup restore is one all-or-nothing transaction with exactly seven ordered, idempotent phases:

    public enum LibraryRestoreInterruptionPoint: CaseIterable, Sendable, Equatable {
    case afterJournalAdmission
    case afterRecoverySnapshot
    case afterAuthoredPublication
    case afterAggregateCommit
    case afterAuxiliaryState
    case afterBackupEnvelope
    case afterJournalRetirement
}

    rollForwardRestore is the sole executor for both an interactive restore and startup crash recovery — each phase is re-derivable from journal bytes alone, so resuming after a crash replays exactly the same code path a live restore would take. It writes the pre-restore undo snapshot first (library.preRestoreRecovery.v1), then joins the same serial LibraryAggregatePersistenceWriter lane used by ordinary saves before touching the live library key.

    mergeBackupData applies an imported LibraryBackup additively, never destructively:

    • Games — matched via GameDedup.MatchIndex<Int> (allowLegacyCompositeFallback: true); a .unique match enriches the existing row through mergePortableFields(from:) (blank fields fill from the backup, non-empty analysis/notes fields are backup-authoritative, existing non-empty scalars are never overwritten); .none inserts a new row; .ambiguous is skipped rather than guessed.
    • Traps — deduped on (sourceGameID, fen, correctMoveUCI, userActualMoveUCI, halfMoveIndex), since two different mining sources can legitimately surface the same position.
    • Trap scan records — deduped on (sourceGameID, manifest identity), keeping whichever incoming/existing record has the newer scannedAt.
    • Endgame positions — unioned by FEN, then the projection selection is reset to the legacy generation-zero authority (minedEndgames stays authoritative until a fresh complete scan republishes its own successor) because a portable backup never carries the local immutable proof graph a typed receipt depends on.

    Authored notes and board-mark edits go through a separate four-phase write-ahead protocol (LibraryAuthoredMutationInterruptionPoint) so a crash mid-edit can never leave the aggregate and the causal proof graph disagreeing: afterIntent (the write-ahead intent lands in a durable sidecar) → afterImmutableFacts (append-only causal rows written idempotently) → afterCompactHead (the compact replica head written) → afterAggregateCommit (one aggregate replacement applies desired and installs the identity marker; only then may the sidecar be retired). PendingAuthoredMutation.currentSchemaVersion is 1, and maximumImmutableRows is AuthoredVectorClock.maximumReplicaEntries (32) + 1. kernel.beginAuthoredMutation(incarnation:field:expected:desired: identitySource:) drains any earlier pending intent first, writes this one, then drains again — it never returns with unflushed intent state.

    PreparedGameData and the legacy "; best <SAN>" rewrite¶

    PreparedGameData is the off-main import DTO every parsed game becomes before it reaches the kernel — init(from:orderIndex:) does the expensive tokenization, tag encoding, and identity resolution once, on whatever task built the batch, instead of paying that cost again on every subsequent read.

    Legacy Fianchetto games stored the engine's best move as a bare inline marker directly after the annotated move: "… Nf3 ; best Bc4 …". Standard PGN treats ; as a comment running to end-of-line, but Fianchetto move text is a single line — so ChessCore's tokenizer reads the bare ; as an illegal SAN and drops the entire main line. Making ; run to end-of-line the way standard PGN does is equally wrong here: it would swallow every following move as comment text.

    PreparedGameData.normalizeForParsing(_:) is the public entry point to the kernel-local rewrite (normalizingLegacyBestMoveMarkers) that toPGNGame also applies before tokenizing. It turns each bare marker into a bounded brace comment so the surrounding moves still parse and no content is lost:

    "… Nf3 ; best Bc4 …"          →   "… Nf3 {; best Bc4} …"
"… {+0.2; best e4} …"         →   unchanged, byte for byte

    The SAN is the single whitespace-delimited token after the marker. A "; best" that already sits inside a {...} brace comment is a structured engine annotation and must stay intact — rewriting it there would shift content digests and dedup keys. The literal "; best " text survives inside the new comment, so computeIsAnnotated keeps recognizing these games unchanged after the rewrite. The scan itself uses only character comparison and firstIndex(where:), deliberately avoiding Foundation range search, so it transpiles cleanly to Android via Skip.

    Import pipelines¶

    importPGN is the single-shot synchronous path for one paste/autosave. importPGNInChunks parses off a detached task, then delegates to saveNewCollectionInChunks. importPreparedPGNCollection(_:fingerprint:) is the durable, crash-recoverable path: it records a PendingPGNImport journal (collectionID, fingerprint, collectionName) in the aggregate itself before writing the first chunk. A retry with the same fingerprint reuses the recorded collectionID and lets ordinary live dedup skip chunks that already made it to disk; a different fingerprint is rejected until the user explicitly keeps or abandons the partial import. The journal and every game chunk it protects live in one atomic FileJSONBlobStore write, so there is no separate preference file that could disagree with the games actually on disk after a crash.

    Lichess's complete-history import pages through fetchLichessHistoryPages, and each page commit needs an O(1) proof that the destination collection's identity multiset hasn't silently drifted since the last page. LichessIdentityAccumulator provides that proof without rehashing the whole collection on every page:

    rowDigest(gameID, identity) = SHA-256(
    "fianchetto.android.lichess-destination-row.v1"
    ++ lowercased(gameID.uuidString)
    ++ (identity.remoteID.isEmpty
          ? "content" ++ identity.composite ++ identity.legacyPromotion
          : "remote" ++ identity.remoteID)
)
// split the 256-bit digest into 4 big-endian UInt64 limbs (a, b, c, d)
insert(row): accumulator += rowDigest   // 256-bit add, mod 2^256, with carry
remove(row): accumulator -= rowDigest   // 256-bit subtract, with borrow

    Insertion and removal are each O(1); the accumulator's final hexDigest proves the exact multiset of rows durable at that page boundary, so a promoted (content → remote ID) row updates the witness in place instead of forcing a full collection rewalk.

    Reconciliation and lifecycle¶

    LibraryGameReconciliation.plan(games:) is a pure, persistence-agnostic static function — [LibraryBackup.Game] -> Plan — shared by the dedup preview UI, dedup execution, and LibrarySemanticCollectionReconciler's merges. Rows are grouped by a BaseProof (normalized persisted ID, logical dedup key, core PGN fingerprint, and position-sequence proof); within a duplicate group the survivor is chosen by this exact preference order:

    1. isAnnotated            (prefer an annotated row)
2. positionRichness        (more populated derived-analysis fields wins)
3. enrichmentRichness       (richer note/Maia enrichment wins)
4. derivedDepth             (more bytes of regenerable analysis wins, on a tie)
5. orderIndex ascending      (earlier input wins remaining ties)
6. deleteIndices.count descending  (prefer the survivor that absorbs more)
7. survivorIndex ascending    (final deterministic tiebreak)

    Complexity is O(total input + Σ group reconciliation costs) — projection and exact-base grouping are linear, and only actual duplicate groups pay the (at most cubic) candidate-selection cost. Board arrows are user-authored and are never dropped; a survivor may only absorb a source's redundant engine analysis when the group key is a recognized remote ID (proof the rows are literally the same online game).

    LibrarySemanticCollectionReconciler.migrate(role:collections:) canonicalizes the app-generated collections (.otb, .vsEngine, .boardImports roles) into one collection per role, using the planner above for the merge. A destructive merge is permitted only when every candidate collection and game matches the exact generated shape — tag roster exactly {Event, Date, White, Black, Result} (optionally +{SetUp, FEN}), and for .vsEngine an opponent label prefixed with a known engine tag ("Maia ", "Reckless d", "Stockfish d"). Anything customized is left alone and reported through notice(for:) for manual review instead of merged.

    CollectionLifecycle gives CloudKit-synchronized collections a signed soft-tombstone protocol:

    legacyGeneration = 0

lifecycleVersion >= 0  → active, generation = lifecycleVersion
lifecycleVersion <  0  → deleted, tombstone generation = -lifecycleVersion
                          (Int64.min maps defensively to Int64.max, not a trap)

childDisposition(parent, child):
  active parent:   child == parent → visible
                   child <  parent → stale
                   child >  parent → deferred (out-of-order CloudKit delivery)
  deleted parent:  child <= tombstone → stale
                   child >  tombstone → deferred

    CollectionLifecycle's cleanup extension (CollectionCleanupPolicy.swift) adds the durable two-observation state machine that authorizes actually deleting stale children:

    maximumCleanupChildrenPerCollection  = 250_000
requiredStableCleanupObservations    = 2

observing  → first import-idle snapshot recorded
cleaning   → a second DISTINCT snapshot matched → this snapshot is now
             authorization; every batch re-verifies isExactSubset(of:)
             before deleting, so cleanup can only shrink toward it
quiescent  → the authorized snapshot has no stale children left

    Any structurally invalid snapshot or token (duplicate child tokens, an oversized token, tombstoneVersion >= 0, tombstoneVersion == Int64.min) routes to .blocked — the caller must fail closed and keep every row rather than guess.

    Derived projections¶

    LibraryStatsCache is a @MainActor process-local cache shared by Stats and Review. It coalesces identical in-flight requests (keyed by persistenceRevision + includeEloEstimate) into one shared Task.detached(priority: .userInitiated) computation, and a monotonic generation counter means only the last-started request for a given Elo mode may publish. lastGoodValue(includeEloEstimate:) keeps returning the previous good AggregateStats while a refresh is in flight or fails, so views never flash empty.

    LibraryStatsProjection.snapshot(from:) maps LibraryData onto the shared GameStatsSnapshot that StatsKernel consumes. cachedMoveCount is always projected as -1 (recomputed downstream, never trusted from storage), and repertoire coverage keys go through OpeningBook.epNormalizedKey so transposed lines still register.

    LibrarySortKernel.moveCount(fromMoveText:) fixed a real cross-platform bug — counting whitespace-split PGN tokens counts move-number tokens as moves:

    moveCount(moveText):
  for each whitespace-split token:
    skip if first char is a digit       (move numbers: "1." / "12...")
    skip if first char is '*'           (result token)
    skip if first char in "{}();$"      (comments / NAGs / structure)
    else: plies += 1
  return (plies + 1) / 2

    Name ordering (namePrecedes) deliberately uses String.compare(_:options:[.caseInsensitive, .numeric]) rather than localizedStandardCompare, with a byte-order lhs < rhs fallback on an .orderedSame result — locale-dependent collation would make the same library sort differently on two devices set to different regions, and without the fallback sorted(by:)'s non-stable order would let two devices holding the same games in different arrival order display them differently.

    sortsBefore(lhs, rhs, by: key):
  "date-asc" → lhs.date < rhs.date
  "white"    → namePrecedes(lhs.white, rhs.white)
  "black"    → namePrecedes(lhs.black, rhs.black)
  "event"    → namePrecedes(lhs.event, rhs.event)
  "moves"    → lhs.moveCount > rhs.moveCount
  default    → lhs.date > rhs.date          // newest-first

    CollectionOwnerResolver.resolve(explicitUsername:games:) infers whose library an unlabeled PGN import belongs to: it requires at least two games, exactly one name common to every game's {white, black} pair, and rejects placeholder names (?, unknown, anonymous, anon, white, black, player, computer) — anything less unambiguous fails closed (nil) rather than guessing, so an opponent or a one-off match PGN is never mistaken for the account owner.

    Filename and result-code helpers¶

    PgnFilename.make(white:black:date:) builds the sanitized .pgn filename shared by both platforms' export paths:

    PgnFilename.make(white:black:date:)
  keep only isLetter || isNumber || "-" || "_" || "."
  PGN date dots → hyphens BEFORE cleaning       "2024.01.15" → "2024-01-15"
  drop a side whose cleaned name is empty       (the "?" placeholder)
  join surviving players with "-vs-", then join to the date with "-"
  stem = raw.prefix(50); empty stem → "game"; append ".pgn"

    Dropping the empty side is what stops "White-vs--2024-01-15" — a double hyphen — when one player tag is the PGN placeholder "?".

    PGNResultCode.from(_ humanResult: String?) maps a human-readable end-of-game sentence to a PGN result token by ordered substring contains checks:

    "White wins" → "1-0" · "Black wins" → "0-1" · "Draw" → "1/2-1/2"
nil or unrecognized → "*"

    Prefer PGNResultCode.from(_ outcome: GameOutcome) where a GameOutcome exists

    The string-matching overload substring-matches "White wins" out of prose a view composed elsewhere, so it discards the reason for the result entirely (no Termination tag was ever written from it), and it is one re-worded sentence away from silently answering "*" for a decisive game. It stays only because the import paths genuinely have nothing but prose to work from. The GameOutcome-based overload derives the token from the outcome directly and should be used everywhere else.

    Appendix: GameViewCache¶

    The one presentation-adjacent type in this subsystem. GameViewCache memoizes EBoardSession.buildGameView() because MoveGenerator.legalMoves ran on every call at BLE notification cadence — measured at ~700ms of main-actor block per event on a Samsung Galaxy A17 (Helio G85, debug build), the dominant OTB-view jank source.

    cache key   (ObjectIdentifier(game), game.position.fen, game.currentNode?.move.uci)
    FEN covers position, active color, castling rights, en-passant target, clocks
    currentNodeUCI invalidates the ancestor walk on retraction/take-back
    object identity stops a multi-session switch between two games sharing
      FEN + lastUCI from serving a stale ancestor chain
initial lastNodeUCI = "__INVALID__"      (distinct from the legitimate nil)
on a miss   walk the parent chain for at most 6 plies (take-back detection bound)
            castling rook homes from MoveGenerator.legalCastlingUCIs(for:) mapped
            through {"h1": "e1g1", "a1": "e1c1", "h8": "e8g8", "a8": "e8c8"}
            — measured ~3.6x faster than full legal-move generation

    GameViewSource is the minimal surface (position, currentNode) that lets the two platforms' distinct Game classes share one cache; ChessCore's Game conforms in this file.

    Main-actor only

    GameViewCache is non-Sendable by design — it holds game-tree references without a concurrency penalty — and must only be called from the main actor, the same requirement as the EBoardSession that owns it. It compiles headless (Foundation + ChessCore, no SwiftUI/UIKit), but its output drives an interactive board session, so unlike the rest of this page it has essentially no CLI value — it is not part of the nonisolated pure-value surface below.

    Headless surface and CLI opportunities¶

    Every file in this directory imports only Foundation (plus Dispatch in the persistence writer) and, where chess logic is needed, ChessCore. @MainActor isolation on LibraryStoreKernel itself is not a UI dependency — it is fine to run inside a CLI process's main-actor context — and a large fraction of the subsystem is nonisolated pure value logic that needs no actor at all: GameIdentity, GameDedup, LibraryGameReconciliation.plan(games:), LibrarySemanticCollectionReconciler, LibrarySortKernel, CollectionLifecycle (including its cleanup extension), CollectionOwnerResolver, PgnFilename, and PGNResultCode are all static functions over plain values with no store attached.

    That makes several pieces natural fianchetto-cli subcommand targets beyond the estimate/annotate/maia/accuracy/project/track surface already wired to EloEstimator and StatsKernel:

    • A library import/dedupe pair could drive LibraryGameReconciliation.plan(games:) directly for a preview-then-apply flow, with no store instance needed at all — just an array of LibraryBackup.Game.
    • A stats subcommand reusing LibraryStatsProjection.snapshot(from:) + StatsKernel.compute is the same code path fianchetto-cli's project and track subcommands already exercise for headless Elo estimation, so a library-backed stats command would need no new math — only a LibraryData loaded from a JSON file.
    • GameIdentity's full identity surface — canonicalProviderID, persistedRemoteID, promotingIdentity, stableID — is not the one-line helper canonicalProviderID alone might suggest; see Game and collection identity. Paired with PgnFilename.make, it is well suited to a small identify/export-filename utility subcommand for scripting around PGN archives.
