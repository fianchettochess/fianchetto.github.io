    Endgame mining and the endgame trainer¶

    Two connected subsystems. The trainer generates fresh legal FENs for eight curated archetypes and bounds the tablebase probe/regeneration loop. The mining pipeline turns the user's own games into drill positions and caches them as immutable, content-addressed, sync-safe generations.

    Everything here is pure logic: value types — apart from the two caller-confined scratch classes, EndgameMiningV2OrderingSpool and EndgameMiningV2ScratchLease — plus (String) -> String? load closures, injected FileManager, no actor isolation and no storage backend.

    Layer Types What it decides
    Extraction PersonalEndgameExtractor, PersonalEndgameSourceAnalysis which position in a game is the endgame decision point
    Witnesses EndgameMiningManifest, EndgameMiningGenerationCommit that a source was examined, and that a generation is complete
    V1 storage EndgameMiningShard, EndgameMiningGenerationRecord, EndgameMiningStorageHead how a generation is partitioned into bounded rows
    V1 reconciliation EndgameMiningGenerationResolver, EndgameMiningReclamationPolicy which visible head wins, and what may be deleted
    V2 storage EndgameMiningV2SourceResult, EndgameMiningV2ResultShard, EndgameMiningV2IndexPage generation-neutral results in a radix-16 trie
    V2 writing EndgameMiningV2StorageBuilder, EndgameMiningV2OrderingSpool, EndgameMiningV2ScratchLease streaming construction under bounded memory, disk and ownership
    Trainer EndgamePuzzle, EndgameProbeGuard, EndgameFeedback which drill to show, when to regenerate, what counts as a miss

    Extraction: what counts as a personal endgame¶

    PersonalEndgameExtractor walks a game's main line and returns at most one position — the first point where the user was to move and the board had dropped into tablebase range while still holding material worth drilling. One position per game keeps the list varied instead of yielding twenty near-duplicates from a single long endgame.

    for ply i in 0 ..< mainLine.count:
    position   = mainLine[i].positionBefore        # the decision point
    pieceCount = non-empty squares of position
    require 4 <= pieceCount <= 7                   # else continue
    require mover(ply: i, startIsWhite:) == userColor
    emit one PersonalEndgamePosition and stop

    7 is Lichess tablebase coverage; 4 is the least material that is still a drill. The emitted position carries fen (positionBefore.stockfishSafeFEN), gameInfo ("<white> vs <black>"), moveNumber (the position's fullmoveNumber), pieceCount, userColor, and a category material summary read off the board — "K+R vs K+P", "K+Q vs K+R".

    PersonalEndgamePosition.id is its fen, so rebuilding the projection from an immutable generation does not hand every row a new identity and make a list diff treat unchanged positions as new. PersonalEndgamePositionData is the Codable form: it flattens userColor to userColorRaw ("white" / "black") so one plain-JSON shape is shared by iOS and Android, and decodes leniently (fen "", gameInfo "", moveNumber 1, pieceCount 4, userColorRaw "white", category "").

    currentRevision is 4, and it is one of the three fields of the source key. Bumping it when eligibility or emitted semantics change is what stops an old negative result from suppressing a newer extractor: revision 5 produces different sources, so every game is reconsidered.

    Source identity without replay¶

    A cache needs a key that is cheap to compute. Constructing every intermediate position merely to discover whether a result is reusable would defeat the purpose, so sourceDigest(input:) hashes the lexical PGN semantics. Tokenization drops comments, variations, NAGs, move numbers and results, so a plain copy and the app's annotated rewrite of the same game hash identically.

    PortableSHA256; every field length-prefixed
  (8-byte big-endian UTF-8 length, then the bytes)

domain   "personal-endgame-source:v4"
then     input.white
         input.black
         input.username
         canonicalStartingPositionIdentity(input.startingPositionFEN)
then     decimal count of main-line moves
then     each canonicalized SAN, in order

canonicalStartingPositionIdentity(fen):
    trimmed.isEmpty -> Position.initial().fen
    otherwise       -> Position(fen: trimmed)?.fen ?? trimmed

canonicalLexicalSAN(san):
    remove '+', '#', '!', '?'; trim whitespace
    "0-0" -> "O-O",  "0-0-0" -> "O-O-O"

    The normalization is deliberately conservative: if two unusual SAN spellings are not provably equivalent lexically they become separate sources and are replayed, rather than risking an incorrect cache hit. An invalid starting FEN stays byte-identifiable for repair diagnostics.

    Note

    This digest is an admission witness, not a completion witness. A match at the same extractor revision may reuse a previously validated result; a miss must still complete a diagnostic-free semantic replay before it can publish either positions or noPositions.

    Completion versus rejection¶

    analyze(stableGameID:from:) validates and replays one exact source once and returns .completed or .rejected. Only .completed carries a PersonalEndgameCompletedExtraction, whose initializer is fileprivate — nothing outside the extractor can mint one, so a permissive empty legacy result cannot retire a source as complete.

    Rejection Cause
    insufficientInput white, black, username or move text is blank
    invalidStableGameID empty, or not equal to GameIdentity.normalizedIdentifier of its own NFC-precomposed form
    unresolvedUserColor the saved account name matches neither player
    invalidMainLine(diagnostic) ChessCore reported a replay diagnostic
    insufficientMainLine the record parsed but yielded no playable move

    PersonalEndgameMainLineDiagnostic carries bounded context — invalidFEN(preview:), unparseableMove(san:plyIndex:), tagsOnlyRecord, moveTreeNodeLimitExceeded(maximumNodes:), other. Previews are truncated before they enter the value: the first 96 unicode scalars, whitespace runs collapsed to single spaces, "…" appended when anything was dropped. Surfacing an error can therefore never echo a whole PGN. The diagnostic itself is a plain value; every case renders a distinct user-facing message through the rejection's errorDescription (PersonalEndgameExtractionCompletionError is the LocalizedError), and unparseableMove reports a 1-based "ply \(max(0, plyIndex) + 1)".

    Warning

    A rejection is retry-eligible and must never become a durable noPositions manifest. noPositions means "this exact source was examined and intentionally produced nothing"; a rejection means "this source could not be examined".

    let input = TacticsInput(
    white: game.white,
    black: game.black,
    moveText: game.moveText,
    tagsJSON: game.tagsJSON,
    annotationEvalsJSON: "",
    username: account
)

switch PersonalEndgameExtractor.analyze(stableGameID: game.stableID, from: input) {
case .completed(let extraction):
    let admission = try EndgameMiningStorageAdmission(
        completedExtraction: extraction,
        whitePlayerName: input.white,
        blackPlayerName: input.black
    )
    stage(try admission.manifest(generation: 1, completedExtraction: extraction))

case .rejected(let error):
    report(error.errorDescription)      // retry-eligible; record nothing durable
}

    EndgameMiningStorageAdmission bounds display metadata before it can enter coverage: stableGameID at 512 UTF-8 bytes, white + black player names at 384 UTF-8 bytes combined, else sourceNotStorable. Without that gate one game with a pathological label could make every full-library generation fail forever at the shard writer. Skipped sources should be counted and reconsidered on each rescan; authored game data is never truncated. manifest(...) re-checks that the extraction's source equals the admitted one (commitMismatch) and that the record is shard-storable.

    Witnesses: manifests, outcomes, coverage¶

    EndgameMiningManifest is one immutable per-source V1 result. Its Source is the triple (stableGameID, sourceDigest, extractorRevision) — the full triple is the key, so one game can be mined for several account identities without collision. sourceDigest must be canonical lowercase SHA-256 (64 hex) and extractorRevision must be positive.

    Outcome cardinality — enforced on construction AND on decode:
    (.noPositions, 0 positions)   ok
    (.positions,   1 position)    ok
    anything else                 throw .invalidOutcome

Position validity:
    FEN parses; moveNumber > 0; userColorRaw ∈ {"white","black"};
    actual board piece count ∈ 4...7 and == the declared pieceCount

manifestDigest = H("endgame-mining-manifest:v1", schemaVersion, generation,
                   source triple, outcome.kind, position count,
                   each position's six fields)

    The single-position invariant freezes today's extractor into storage so a malformed record cannot turn one bounded shard into an unbounded payload; a multi-position policy must bump both revision and schema.

    Coverage and the commit are built in constant memory from a canonically ordered stream, so no library-sized array is ever materialized.

    V1 source order (EndgameMiningSourceOrder.precedes):
    stableGameID, then sourceDigest, then extractorRevision

Coverage.Builder: seed "endgame-mining-coverage:v1"; per source append the three
    fields length-prefixed (duplicate -> .duplicateSource,
    out of order -> .sourceOutOfOrder); finish by hashing the decimal count.

Commit Builder: seed "endgame-mining-set:v1"; per manifest append its
    manifestDigest; finish by hashing the decimal count, then require
    rebuiltCoverage == expectedCoverage else .coverageMismatch.

generationDigest = H("endgame-mining-generation:v1", schemaVersion, generation,
                     coverage.sourceCount, coverage.sourceSetDigest,
                     manifestSetDigest)

    Because finish() refuses a partial source set, a cancelled prefix can leave unreachable immutable shards but can never become a visible generation. EndgameMiningHead binds to generationDigest; legacyGeneration = 0 names the historical flat cache, and decode admits only (0, nil) or (>= 1, canonical SHA-256).

    V1 storage layout¶

    Every sync-visible row is bounded and content-addressed, so the encoded payload stays independent of library size.

    Object Bound Storage key
    manifest (inside a shard) 8 KiB —
    EndgameMiningShard 96 manifests, 900 KiB personalEndgames/shard/v1/<shardDigest>
    EndgameMiningGenerationRecord 10 922 shards, 768 KiB personalEndgames/generation/v1/<recordDigest>
    EndgameMiningStorageHead 4 KiB personalEndgames/head/v1
    EndgameMiningProjectionReceipt 8 KiB personalEndgames/projectionReceipt/v1 
    maximumSourceCount = 10_922 * 96 = 1_048_512

expectedShardCount(sourceCount):
    0                        when sourceCount == 0
    ((sourceCount - 1) / 96) + 1   otherwise

expectedManifestCount(inShardAt: i):
    96                                    for every non-final shard
    sourceCount % 96, or 96 when that remainder is 0, for the last

    Since every non-final shard holds exactly 96 manifests, the source count in the commit determines the entire partition — the layout is unique and a repartitioned copy is rejected with invalidCanonicalPartition. The record also binds its parent (EndgameMiningGenerationIdentity, .legacy = (0, nil, nil)) and requires commit.generation == parent.generation + 1. EndgameMiningStorageNamespace marks all of this as infrastructure: keys under personalEndgames/ (or the reserved legacy personalEndgames_) are sync and crash-recovery machinery, so semantic library backups carry only the flat projection.

    EndgameMiningGenerationStorageBuilder writes a generation in constant source memory: feed manifests in canonical order, persist each shard append(_:) returns as it crosses a 96-manifest boundary, then publish Completion(finalShard, commit, generationRecord, storageHead) in exactly that order. Every fallible mutation is staged in value copies, so a rejected append leaves the builder reusable and cannot silently drop a full shard.

    The canonical-JSON contract¶

    EndgameMiningStorageCodec (and its V2 twin) is the only supported entry point, because a bare JSONDecoder enforces neither half of the contract:

    encode: JSONEncoder with [.sortedKeys, .withoutEscapingSlashes]
        reject when data.count > maximumBytes  ->  .payloadTooLarge(limit:)

decode: reject empty, or source.utf8.count > maximumBytes — BEFORE decoding, so
        nested arrays cannot be allocated first
        decode, re-encode, require byte-for-byte equality
        otherwise -> .nonCanonicalJSON

    The byte-exact re-encode rejects unknown fields, alternate key order, insignificant whitespace and noncanonical escaping. It is also why the same bytes compare equal across platforms.

    V1 reconciliation¶

    EndgameMiningGenerationResolver.resolve(...) compares all visible head copies against a freshly recomputed source universe and returns .promote or .retainCurrent(reason).

    if headJSONCandidates.count > 4_096  ->  .retainCurrent(.candidateLimitExceeded)

decode candidates, drop legacy heads
append the current receipt's head (a receipt is itself a durable head witness, so
    a missing or hidden physical head row cannot lose it)
sort DESCENDING by (generation, generationDigest, generationRecordDigest);
    skip exact repeats

per candidate:
    skip when precedes(candidate, currentHead)            # monotonic floor
    skip when candidate == currentHead and its record coverage ==
         expectedCoverage and the flat cache matches the receipt
    require the record loads, head.accepts(record),
            record.commit.coverage == expectedCoverage
    fully revalidate every shard  ->  .promote

else .retainCurrent(currentReceipt == nil ? .noCompleteGeneration
                                          : .currentGenerationPreferred)

    Two rules carry the weight. The receipt is an unconditional monotonic floor: temporary object loss or a changed live source universe may make its projection unusable, but neither authorizes a passive rollback to an older sync-visible generation. And parent identity is audit metadata, not an admission gate — requiring ancestry would permanently fork replicas that advanced opposite sides of a concurrent head race, so deterministic digest tie-breaking is what makes them converge.

    EndgameMiningValidatedGeneration (mintable only by the resolver) re-derives the commit while streaming, checking each shard's content address, generation and expected manifest count, and finally requiring builder.finish() == record.commit.

    V2: generation-neutral results in a radix-16 trie¶

    V1 embeds the scan generation in every manifest digest, so every full scan rewrites every row. V2 removes the generation from result identity, which makes an unchanged source referencable by every later generation.

    sourceKeyDigest = H("endgame-mining-source-key:v2", source triple)
resultDigest    = H("endgame-mining-result:v2", schemaVersion, source triple,
                    outcome.kind, each position's six fields, position count)

V2 order: sourceKeyDigest first; on a hash collision fall back to the V1 tuple
          (stableGameID, sourceDigest, extractorRevision)

    EndgameMiningV2SourceResult reuses the V1 manifest kernel for semantic validation (constructed at firstManifestGeneration) without keeping that generation in the value or either hash. Results live in a content-addressed trie keyed by hex nibbles of sourceKeyDigest:

    leaf: buffer results while count <= 96
97th: split into a radix-16 index page keyed by the nibble at
      depth = prefix.utf8.count, then reapply the rule recursively
depth: a 64-character prefix exhausts the hash -> .hashPrefixExhausted

Result shard: every result's sourceKeyDigest starts with the shard prefix;
    results strictly V2-ordered; no duplicate source.
Index page:   children strictly ascending by nibble; unique child digests;
    <= 16 children; prefix shorter than 64; summed sourceCount > 96, so a page
    can never stand in for a leaf.
Node reference: sourceCount > 0; resultShard <= 96; indexPage > 96.

    Only one child per level is ever active, which bounds writer memory at 96 buffered results plus at most 16 child references per level.

    Object Bound Storage key
    EndgameMiningV2SourceResult 8 KiB — (inside a shard or a spool frame)
    EndgameMiningV2ResultShard 96 results, 900 KiB personalEndgames/result/v2/<shardDigest>
    EndgameMiningV2IndexPage 16 children, 16 KiB personalEndgames/index/v2/<pageDigest>
    EndgameMiningV2GenerationRecord 1 048 512 sources, 16 KiB personalEndgames/generation/v2/<recordDigest>
    EndgameMiningV2StorageHead 4 KiB personalEndgames/head/v2
    EndgameMiningV2ProjectionReceipt 8 KiB personalEndgames/projectionReceipt/v2

    The generation record is a compact selection record — coverage proof (endgame-mining-coverage:v2), result-set proof (endgame-mining-result-set:v2), and the root reference. It requires generation == parent.generation + 1, coverage.sourceCount == resultSet.resultCount, and either (0 sources, nil root) or (>= 1 sources, root.sourceCount == coverage.sourceCount). hasEquivalentSourceResults(to:) is the publisher's no-op predicate — coverage, result set and root only, ignoring generation and parent.

    Writing a V2 generation¶

    EndgameMiningV2StorageBuilder.append(_:) is transactional: coverage, result-set and trie state are staged in copies before commit, and it rejects duplicateSource, invalidCanonicalOrder and tooManySources(limit: 1_048_512). Artifacts stream out dependency-first as subtrees complete, so each can be persisted immediately; finish() returns the remaining artifacts ending with the root, plus the generation record and head.

    Results must arrive in V2 order. A platform whose enumeration is not already in hash order uses EndgameMiningV2OrderingSpool, a caller-scoped disk-backed radix sort that creates and exclusively owns a previously nonexistent directory and removes it after every successful or failed build.

    Frame layout (68 bytes of overhead per record):
    4-byte big-endian JSON length | 64-byte source key | canonical JSON

drain(file, expectedCount, prefix, depth):
    expectedCount <= 96:
        read every frame; require the decoded sourceKeyDigest to equal the frame
        header and to start with `prefix`; sort in memory by
        EndgameMiningV2SourceOrder; feed the trie builder
    otherwise:
        require depth < 64
        partition into up to 16 child files by the nibble at `depth`
        a bucket > 96 whose source keys are all identical throws
            .tooManyEquivalentSourceKeys(limit: 96) rather than copying the same
            input through all 64 radix levels
        recurse over "0123456789abcdef" in order
    Constant Value
    maximumDecodedBatchResultCount 96
    maximumInMemoryResultCount 192 (a batch plus the writer's retained leaf)
    maximumSimultaneouslyOpenFileHandles 17 (one reader, sixteen writers)
    maximumSimultaneouslyResidentScratchFiles 15 · 64 + 17 = 977
    maximumSpoolBytes 1 048 512 · (8 192 + 68) = 8 660 709 120
    maximumWorkingBytes twice that — a partition holds its source and its copy
    minimumFreeCapacityReserveBytes 512 MiB
    workingDirectoryNamePrefix fianchetto-endgame-mining-v2-spool-

    Before each write the spool accumulates bytes and re-probes free capacity every 16 MiB, requiring available >= 512 MiB + 16 MiB or throwing insufficientScratchCapacity(minimumAvailableBytes:) — rendered as MiB by ceiling division on 1 048 576. The reserve leaves room for app recovery, database journals and an actionable error instead of consuming the volume to zero. States run accepting -> sealed -> draining -> finished | failed; any failure closes and removes the whole directory, and a cleanup failure supersedes the operation error so a retained spool is never mistaken for a clean one. reclaimStaleWorkingDirectories(in:olderThan:...) sweeps abandoned directories at startup (defaults: 256 scanned entries, 8 removals).

    let lease = try EndgameMiningV2ScratchLease.acquire(in: scratchParent)
defer { try? lease.release() }

let spool = try EndgameMiningV2OrderingSpool(
    directory: EndgameMiningV2OrderingSpool.workingDirectoryURL(in: scratchParent)
)

for extraction in completedExtractions {
    try spool.append(EndgameMiningV2SourceResult(completedExtraction: extraction))
    try lease.checkpoint()          // fails closed if this owner was displaced
}

let completion = try spool.build(
    generation: nextGeneration,
    parent: parentIdentity
) { artifact in
    try store.write(artifact.storageKey, artifact.canonicalJSON())
}

// Publish only after every immutable node is durable.
try store.write(completion.generationRecord.storageKey,
                EndgameMiningV2StorageCodec.encodeCanonical(completion.generationRecord))
try store.write(EndgameMiningV2StorageHead.storageKey,
                EndgameMiningV2StorageCodec.encodeCanonical(completion.storageHead))

    Warning

    The spool is intentionally not Sendable and performs synchronous file I/O. Create, append and build it on one caller-owned worker; never drive it from several actors or threads.

    Scratch ownership¶

    A spool can legitimately reach several gigabytes, so age-only cleanup is not enough: repeated force-termination can leave several fresh spools before any becomes reclaimable. EndgameMiningV2ScratchLease permits one owner per app-private parent directory.

    acquire: up to 4 attempts at exclusive creation of
         "fianchetto-endgame-mining-v2-lease"

if it exists, observe (owner.json bytes, directory mtime, heartbeat):
    the owner is fresh — takeover forbidden — when the reference time is within
    5 minutes OR lies in the future (a clock rollback must never license two
    owners)

otherwise: same-volume rename to
           "fianchetto-endgame-mining-v2-retired-lease-<UUID>", re-observe, and
           require byte-identical metadata (else restore it and report
           .leaseBusy); then re-create the lease and delete the retired copy

checkpoint(): re-read the token every call — mismatch -> .leaseLost;
              rewrite the heartbeat at most every 5 seconds

    Predecessor cleanup is bounded to 512 scanned parent entries, 64 spool directories and 16 retired leases; exceeding any of them throws cleanupLimitExceeded instead of scanning an unbounded directory.

    Reading, merging and projecting¶

    EndgameMiningV2ValidatedGeneration (public init, throwing headMismatch unless head.accepts(record)) rebuilds the coverage and result-set proofs while descending, checking each node's prefix, digest and sourceCount against its reference (recordMismatch otherwise) and bounding the walk:

    maximumNodeCount = maximumSourceCount + 64 * (maximumSourceCount / 97 + 1)
                 = 1_048_512 + 64 * 10_810
                 = 1_740_352 visited nodes before .tooManyNodes

    forEachReusableResult(currentSources:loadObjectJSON:_:) is the single-pass merge kernel publishers use instead of a library-sized dictionary. It validates currentSources through a V2 coverage builder (rejecting an out-of-order or duplicated universe up front), traverses both streams once in V2 order, invokes the callback on each exact source match, and returns a [Bool] reuse bitmap — every unset entry must be re-extracted. Callbacks can run before a later corrupt dependency is discovered, so callers must stage writes and commit only after the method returns.

    De-duplication reproduces V1 output byte-for-byte regardless of trie layout:

    V1: walk manifests in canonical source order, keep the FIRST occurrence of a FEN
V2: traverse in hash order; for a duplicate FEN keep the winner with the MINIMUM
    source under EndgameMiningSourceOrder, then sort survivors by that same order

    The receipt distinguishes a valid current cache from a partially written one: it requires a non-legacy head and unique FENs, and hashes the head identity, then each position's six fields, then the count (endgame-mining-projection:v1 / :v2).

    switch EndgameMiningV2GenerationResolver.resolveProjection(
    currentReceipt: receipt,
    currentProjectionMatchesReceipt: receipt?.accepts(currentPositions) ?? false,
    expectedCoverage: expectedCoverage,
    headJSONCandidates: perReplicaHeadJSON,
    loadGenerationRecordJSON: { store.string(forKey: $0) },
    loadObjectJSON: { store.string(forKey: $0) }
) {
case .promote(let projection):
    // Atomically replace the flat cache and its receipt — never union them.
    try store.replaceMinedEndgames(projection.positions,
                                   receipt: projection.receipt)
case .retainCurrent(let reason):
    log("kept the current projection: \(reason)")
}

    resolve and resolveProjection share one ranking kernel — (generation, generationRecordDigest) descending, the same 4 096-candidate limit, the same receipt-as-floor rule — and evaluate runs at most once per unique viable head, so the winning trie is walked exactly once whether the caller wanted strict validation or a materialized projection. Missing or corrupt higher dependencies never hide a lower complete candidate.

    Retention¶

    Every full V1 scan creates a new generation, because generation identity is part of the manifest proof. EndgameMiningReclamationPolicy.plan(...) keeps that from growing without bound.

    retain: "personalEndgames/head/v1", plus for each distinct non-legacy visible
        head (INCLUDING the current receipt's) its generation-record key and
        every shard key that record names

defer the whole pass (isDeferred) when candidates exceed 4_096, or an active
        record is missing / undecodable / not accepted by its head — a
        not-yet-arrived directory is the only safe way to discover its shards

reclaim only when ALL hold:
        the key starts with "personalEndgames/shard/v1/"
                         or "personalEndgames/generation/v1/"
        it is unretained
        now - lastModified >= 30 * 24 * 60 * 60 * 1_000 ms  (2_592_000_000)

    The 30-day floor covers long offline and sync intervals. Platforms may use a longer interval, never a shorter one.

    Storage epochs¶

    Occasionally a physical namespace must be retired — a container reset — without changing any semantic V2 object. Epochs give identical bytes a permanently distinct address. EndgameMiningV2StorageEpochIdentity is (sequence, descriptorDigest), valid only as (0, nil) (the shipped unscoped keys) or (>= 1, canonical SHA-256). The descriptor (sequence = parent.sequence + 1, 8 KiB, personalEndgames/storageEpoch/v1/<digest>) binds a transition nonce and the exact replica roster under endgame-mining-v2-storage-epoch:v1.

    epoch 0: exact identity mapping of the logical key

epoch n: "personalEndgames/v2e/" + descriptorDigest + "/" + kind + "." + digest
         kind ∈ { "r" result shard, "i" index page, "g" generation record }

reverse: exactly 4 slash-separated components; [0] == "personalEndgames",
         [1] == "v2e", [2] == the epoch digest, canonical SHA-256 after the '.'

    loadLogicalJSON(for:epoch:loadPhysicalJSON:) is shaped to be handed straight to the graph walks. EndgameMiningV2EpochStorageHead (prefix personalEndgames/head/v2e/ plus a validated EndgameMiningReplicaID — up to 128 bytes of [0-9A-Za-z._-]) and EndgameMiningV2EpochProjectionReceipt both reject a legacy epoch or legacy inner value and hash the canonical inner JSON (endgame-mining-v2-epoch-head:v1, endgame-mining-v2-epoch-projection:v1), so identical inner heads in different epochs are never interchangeable authority.

    The trainer runtime¶

    EndgamePuzzle pairs an archetype with a training tip. Its FEN is regenerated on every attempt, so the spaced-repetition key is deliberately FEN-independent:

    public var masteryKey: String { "\(archetype.rawValue):\(description)" }

    The static catalogue holds 12 drills — two K+Q vs K, two K+R vs K, one K+2B vs K, one K+B+N vs K, three K+P vs K, one Lucena, one Philidor, one K+Q vs K+P. Mastery counts persist through BlunderMasteryStore (see Stores).

    EndgameProbeGuard bounds the "regenerate when the tablebase says drawn" loop and rejects stale in-flight probes:

    beginSetup(isRegen:)  currentToken &+= 1; regenAttempts = 0 unless isRegen
isStale(token:)       nil -> false (unowned mid-puzzle re-probes are fresh);
                      otherwise token != currentToken
decideOnDraw()        regenAttempts < maxRegenAttempts (default 3)
                          -> increment and return .regen
                      otherwise -> .exhausted, permanently, for this puzzle

    var probeGuard = EndgameProbeGuard()          // maxRegenAttempts: 3
var fen = puzzle.archetype.randomFEN()
let token = probeGuard.beginSetup()

let probe = try await TablebaseService.shared.probe(fen: fen)
guard !probeGuard.isStale(token: token) else { return }   // a newer setup won

if probe.category == .draw {
    switch probeGuard.decideOnDraw() {
    case .regen:
        fen = puzzle.archetype.randomFEN()
        _ = probeGuard.beginSetup(isRegen: true)   // keeps the attempt count
    case .exhausted:
        present(fen)                               // stop looping
    }
}

    EndgameFeedback is the answer verdict: correct(dtm:), closeEnough(dtm:best:), wrong(expected:), tablebaseUnavailable, engineUnavailable, done.

    Warning

    engineUnavailable means the Stockfish fallback produced no completed score. It is not a chess miss and must not increment attempts or mastery — otherwise a flaky engine silently resets the user's streak.

    EndgameProbeGuard owns the trainer's own probe tokens; RunGeneration is the separate general-purpose restartable-work token the long-running schedulers use (Maia backfill, the Android mining run lifecycle). begin() and invalidate() both do current &+= 1 (invalidate revokes without granting), and owns(_:) is exact equality. Capture a token, then publish or clear shared state only while owns(_:) holds: cancellation cannot synchronously stop code already inside a non-cancellable framework call, so a predecessor may reach its cleanup after its replacement has started.

    Position generation¶

    EndgameArchetype.randomFEN() retries attemptGenerate() up to 200 times, then returns the per-case fallbackFEN (kqVsK → "8/8/8/4k3/8/3Q4/3K4/8 w - - 0 1", philidor → "8/8/4k3/8/4K3/r7/4P3/3R4 b - - 0 1"). Each random-square primitive retries 50 times before returning to the outer loop. Lucena and Philidor are hard-coded template families (5 and 4 templates), varying the file while preserving the technique.

    Kings are never adjacent (Chebyshev distance <= 1 is forbidden).
A piece adjacent to the enemy king is admitted only when the friendly king
    also defends it.

K+Q vs K, K+R vs K  black king on files/ranks 2...5; white king at Chebyshev
                    distance 2...4
K+2B vs K, K+B+N    black king on files/ranks drawn from {1, 2, 5, 6};
                    white king at distance 2...5
K+P vs K            pawn on 0-indexed rank 2...5; white king within distance
                    1...2 of the square in front of the pawn and never on
                    rank 0; black king at distance 2...4 from the pawn, not
                    adjacent to the white king, not on a pawn-attacked square
K+Q vs K+P          black pawn on 0-indexed rank 1...2, white to move

    Finalization is where "legal" becomes "drillable":

    finalize(pos):
    reject when the side NOT to move is in check
        (the previous move would have been illegal)
    reject when the side to move has no legal move
        (mate or stalemate is not a drill)
    emit pos.stockfishSafeFEN

    That last line matters: Position() defaults castling rights to all-true and a random endgame layout has no kings or rooks on their home squares. stockfishSafeFEN zeros castling and en-passant state inconsistent with the board, which is what stops these FENs from crashing Stockfish's strict parser downstream.

    CustomEndgameConfig covers material outside the curated catalogue. PieceCounts clamps queens, rooks, bishops and knights to 0...maxPerPieceType (4) and pawns to 0...8; totalPieces = 2 + white.totalNonKing + black.totalNonKing, and isValid is totalPieces <= 32. Generation places the black king centrally, then the non-adjacent white king, then non-pawn pieces under the en-prise/defended rule, then pawns on 0-indexed ranks 1...6 with white pawns forbidden from attacking the black king. randomFEN() returns nil after 200 failed attempts; fallbackFEN is "8/8/8/4k3/8/4K3/8/8 w - - 0 1".

    Note

    Positions above 7 pieces fall outside Lichess tablebase coverage, so the trainer skips win verification for them. See Network clients for TablebaseService.

    Using it from the command line¶

    Every seam above is already headless, which is what makes it scriptable without an app. fianchetto-cli today ships annotate, estimate, maia, accuracy, project and track; none of them wrap this pipeline yet. The natural split follows the three proofs:

    Proposed subcommand Seam it would expose
    endgame-mine PersonalEndgameExtractor.analyze + EndgameMiningStorageAdmission + EndgameMiningV2OrderingSpool.build over a PGN corpus, emitting trie artifacts
    endgame-verify EndgameMiningV2ValidatedGeneration.validate / EndgameMiningGenerationResolver.resolve against a directory of head copies
    endgame-pack materializeProjection to the flat position cache plus its receipt

    Because every digest is PortableSHA256 over length-prefixed UTF-8 and every envelope is byte-exact canonical JSON, golden digest fixtures are the cheapest parity test available: mine a fixed corpus once, record the sourceDigest, resultDigest, shardDigest, recordDigest and projectionDigest values, and assert that the iOS and Android implementations reproduce them byte-for-byte.
