    Storage, DTOs & Authored History¶

    The portability seam under every persisted store, the value-type mirrors of the app's SwiftData rows, the identity and dedup rules for games, and the CRDT kernel that reconciles user-authored notes and board marks across replicas.

    This subsystem owns policy, not storage. SwiftData, CloudKit, Room, and file I/O all live behind the seam in the platform shells — no SwiftData or CloudKit symbol appears anywhere in FianchettoKit. Everything on this page except the GameViewCache appendix is a value type or a pure static function, so it runs identically on iOS, on Android via Skip, and in a headless process.

    The storage seam¶

    Two protocols in Storage.swift are the entire portability boundary.

    Type Contract
    JSONBlobStore loadJSON(forKey:) -> String? and saveJSON(_:forKey:). Synchronous, fire-and-forget. The Apple backend hides SwiftData + CloudKit + write debouncing; the Android backend hides files/Room.
    BlobBackedStore A Codable single-row store with a static var blobKey and an init(). The protocol extension supplies load(from:decoder:) and save(to:encoder:).

    The two fail-soft rules matter more than the signatures:

    load(from:)  missing blob  → Self()
             malformed JSON → Self()          (no throw, no partial decode)
save(to:)    encode failure → write dropped   (a lost write must not crash a drill)

    In-repo blob keys:

    Key Owner Kind
    tacticsRating TacticsRatingStore BlobBackedStore
    tacticsPerformance TacticsPerformanceStore BlobBackedStore
    drillSRS DrillSRS BlobBackedStore
    repertoireDrillStats RepertoireDrillStats BlobBackedStore
    combinationPuzzles CombinationPuzzleStore BlobBackedStore
    eBoardDiagnosticCapture EBoardDiagnosticCapture BlobBackedStore
    voiceTranscriptLog VoiceTranscriptLog BlobBackedStore
    blunderMastery BlunderMasteryStore enum namespace, reads/writes the blob directly

    See Stores & the storage seam for what each store computes.

    Persistence DTOs¶

    PersistenceDTOs.swift holds plain Sendable, Codable, Equatable mirrors of the app's @Model rows, because Skip bridges neither @Model nor CloudKit. The app converts @Model ↔ DTO at its boundary; Android persists the DTOs directly.

    Type Notes
    PersonalTrapData fen, correctMoveUCI, userActualMoveUCI, gapCp, halfMoveIndex, sourceGameID, sourceOpeningName, detectedAt.
    PersonalTrapScanRecordData Per-game "already mined" bookkeeping. manifestJSON == nil is a legacy scan marker; malformed or noncanonical JSON stays decodable but is never trusted.
    GameCollectionData isOnlineCollection is exactly source == "chesscom" \|\| source == "lichess". Defaults: source "pgn", dateCreated Date(timeIntervalSince1970: 0).
    RepertoireData / RepertoireMoveData The @Model cascade relationship flattened to a value tree. displayName = name.isEmpty ? color.capitalized + " Repertoire" : name, so pre-Phase-1 rows with an empty name still read cleanly.
    FingerprintedCacheData isValid(against:) is fingerprint == currentFingerprint — reuse is decided by corpus fingerprint equality only, never by age.

    PersonalTrapScanRecordData has a second initializer that makes drift impossible: init(scannedAt:manifest:) derives sourceGameID and trapsFound from the immutable PersonalTrapScanManifest and serializes it through PersonalTrapScanManifestCodec.encodeCanonical, so the call site cannot claim a count the manifest does not contain.

    Field-by-field declarations are on the Persistence DTOs page.

    Saved-game collection roles¶

    SavedGameCollectionRole gives app-generated collections a durable identity that survives a backup round trip without a schema migration. Display names stay user-editable and localizable; the reserved source identifier is what persists.

    Role sourceIdentifier defaultCollectionName defaultEventTag
    .otb fianchetto.otb OTB Games Over the Board
    .vsEngine fianchetto.vs-engine vs Engine Play vs Engine
    .boardImports fianchetto.board-imports Board Imports Board import

    Two legacy sets exist, and the asymmetry is deliberate:

    Role legacySourceIdentifiers (Android) legacyAppleSourceIdentifiers
    .otb {"local", "pgn"} {"local"}
    .vsEngine {"pgn"} {}
    .boardImports {} {"local"}

    An arbitrary Apple PGN import that happens to be named "OTB Games" is not provenance for auto-promotion, so "pgn" never appears on the Apple side. init?(sourceIdentifier:) trims whitespace and lowercases before matching.

    SavedGameTags.make(eventTag:date:white:black:result:startFEN:) is the one tag builder for every app-generated saved game. It writes Event, Date, White, Black, Result in that order, and adds SetUp = "1" plus FEN only when startFEN is non-nil and non-empty. SavedGameTags.pgnDateString(from:) uses a Gregorian calendar with the en_US_POSIX locale and the format yyyy.MM.dd, so a device locale can never reshape a PGN date.

    Game identity¶

    GameIdentity encodes one rule: a PGN Link is a reference, a Site is a venue. Only recognized Chess.com/Lichess game locations are promoted from Site to remote identity; everything else falls back to a content ID.

    normalizedIdentifier first collapses "", "?" and "-" to "". canonicalProviderID is then a full grammar:

    lichess:<suffix>            suffix = first segment before any of  /  ?  #
                            require 8...12 chars, all ASCII alphanumeric
                            → "lichess:" + first 8 characters

chesscom:<suffix>           also accepts the "chess.com:" prefix
chess.com:<suffix>          suffix = first segment before  /  ?  #
                            require non-empty, all ASCII digits
                            → "chesscom:" + digits

web location                accepted when the value starts with https:// , http:// ,
                            or a bare lichess.org/ , www.lichess.org/ ,
                            chess.com/ , www.chess.com/
  host lichess.org          first path segment, 8...12 ASCII alphanumerics, and NOT in
  host www.lichess.org      {analysis, broadcast, calendar, editor, features, insights,
                             password, practice, streamer, study, timeline, training}
                            → "lichess:" + first 8 characters
  host chess.com            drop an optional leading "analysis" segment, then match
  host www.chess.com          game/<daily|live|arena>/<id>
                            or  <daily|live|arena>/game/<id>
                            with an all-digit <id>  → "chesscom:<id>"

anything else               → nil

    Lichess's stable component is explicitly the first eight case-sensitive characters, which is why a 12-character URL slug and its 8-character canonical form resolve to one identity.

    Degenerate URLs must not trap

    A raw PGN Site/Link tag or a deep-link token reaches this code unvalidated. A bare "https://" splits to an empty component array; the internal host/path split uses a guarded .first rather than a subscript, which previously trapped and turned one poisoned row into a crash-on-launch loop through repeated stableGameID evaluation (perf/stability audit, 2026-07-19). A value with no usable host now simply yields nil.

    Recovering identity from a persisted row¶

    persistedRemoteID(gameID:link:site:) recovers the semantic remote ID without rewriting anything, applying four fallbacks in order:

    1. remoteID(link:site:) is non-empty            → that canonical value
2. gameID is a content ID                       → ""
3. gameID canonicalizes as a provider ID        → its canonical form
4. gameID == Link, or gameID == Site            → ""      (see below)
   otherwise                                    → gameID  (backup compatibility)

    Rule 4 exists because many PGN producers reuse a single archive, event, or article Link across every game in a file, and older builds persisted any non-empty Link as a per-game ID. Those rows project to content identity at runtime instead of continuing to collapse distinct games together.

    stableID(gameID:link:site:contentID:) layers on top: the persisted remote ID, else the explicit ID when it is already a content ID, else the lazily evaluated contentID(). The autoclosure means an ID-bearing row never pays for content hashing.

    promotingIdentity(_:gameID:tagsJSON:) records an authoritative remote identity without discarding the durable reference already in gameID. A recognized provider ID is written into the Link tag and gameID is left untouched; an unrecognized external ID replaces gameID, and the previous value is stashed under the internal FianchettoLegacyGameID tag for later reference repair.

    UnambiguousAliasAccumulator is the streaming form of unambiguousAliasMap(_:) for auxiliary records (trap and scan rows). record(alias:stableID:) normalizes both sides and ignores empties; the first contradicting stableID removes the alias and marks it permanently ambiguous. stableID(forAlias:) therefore returns non-nil only when every recorded occurrence named the same game, and canonicalIdentifier(_:) falls back to the normalized spelling. A shared Site value ends up attached to no game rather than to an arbitrary one.

    Content keys and dedup¶

    GameDedup owns three prefixes, each answering a different question:

    Prefix Builder Question it answers
    content:v2: compositeKey(...) Is this the same game content? Covers the full authored PGN tree.
    authored-content:v1: authoredIdentityKey(...) Which authored history does this content own? Excludes Link and internal migration tags so a later legacy-to-remote promotion cannot orphan notes.
    promotion:v1: legacyPromotionKey(...) May one unambiguous legacy local row be promoted to a fetched remote ID? Main line only.

    GameIdentity.legacyContentPrefix (content:v1:) is still recognized by isContentID, but v2 is what new keys use: v1 collapsed comments and variations into a main-line-only fingerprint.

    All three hash the same length-prefixed framing:

    payload = LP(white) LP(black) LP(date) LP(result) LP(event) LP(opening)
        ‖ canonicalMoveText
        ‖ canonicalTags
LP(s)   = UInt64 big-endian UTF-8 byte count, then the UTF-8 bytes

canonicalMoveText
  if the text is NOT structurally balanced (unclosed {, stray }, unbalanced parens):
      byte 1 ‖ LP(raw text)
  else tokenize, then:
      byte 0 ‖ UInt64(tokenCount) ‖ per token:
        0 ‖ LP(san)        move
        1                  variationStart
        2                  variationEnd
        3 ‖ LP(text)       comment  (empty comments are skipped, not encoded)
        4 ‖ UInt64(number) NAG
  if tokenization yields no tokens but the text is not blank:
      byte 1 ‖ LP(raw text)          (same fallback)

canonicalTags
  drop keys that are not ASCII PGN identifiers  ([A-Za-z][A-Za-z0-9_]*)
  drop the mirrored set {white, black, date, result, event, opening, eco}
    + {link} when excludingLink
    + {fianchettolegacygameid} when excludingInternalMigrationTags
  sort the survivors, then UInt64(count) ‖ LP(key) LP(value) …

key = "<prefix>" + SHA-256(payload)

    legacyPromotionKey swaps canonicalMoveText for the canonical main line only (SAN with trailing !/? stripped) and always excludes Link, so it deliberately ignores comments, NAGs, and variations. That relaxation is safe only for promoting one unambiguous legacy row; ordinary import and destructive dedup must use compositeKey.

    strippingDerivedAnnotations removes Fianchetto's own engine output so a game does not change identity merely by being annotated. It applies only at variationDepth == 0: main-line SAN loses its trailing !/? glyph run, and a comment that PGNParser.parseEngineComment recognizes (an eval or a best move) is reduced to the retained pieces "clock:<Double bitPattern>" and "comment:<text>" joined by |, or dropped entirely when nothing remains. User comments, clocks, variations, and explicit NAG tokens always survive.

    A digest is fast identity but never structural proof: hasCompatibleMoveSequence(_:tagsJSON:_:tagsJSON:) compares the exact (canonical main line, start FEN) pair, so a hash collision cannot make two different move/FEN sequences mergeable for position-indexed enrichment.

    Consumer types¶

    GameDedup.Key is .remoteID(String) or .composite(String). GameDedup.key(gameID:compositeKey:) returns .composite when the normalized ID is empty or is itself a content ID — a persisted content ID is a durable reference, not proof that the row's editable content is unchanged, so two divergent edits sharing one historical content ID cannot be grouped destructively.

    GameDedup.Identity computes all three keys together plus a derived key. Its init(_ game: PreparedGameData) sets strippingDerivedAnnotations when cachedIsAnnotated == 1 || PreparedGameData.computeIsAnnotated(evalsJSON: "", moveText:).

    GameDedup.KeySet.registerIfNew answers "was this new?" so within-batch duplicates and already-persisted games follow one rule. ID-bearing games intentionally do not also register their composite — two distinct online games may have identical visible PGN fields — and the @autoclosure overload never evaluates the composite for an ID-bearing game.

    GameDedup.MatchIndex<Value> is the backup-restore lookup. Legacy-promotion buckets are populated only for ID-less rows, so composites never become aliases for existing ID rows.

    Resolution When
    .unique(Value) Strong key matched exactly one row, or the legacy fallback matched exactly one.
    .ambiguous Strong key matched more than one row.
    .ambiguousLegacyPromotion No strong match; the relaxed promotion fingerprint named several local rows. Callers must insert, not pick.
    .none Nothing matched, or the fallback was not permitted.

    The fallback is consulted only when allowLegacyCompositeFallback is true and the incoming row has a remote ID. Call unregister(_:) before promoting a legacy content-only row, or its composite alias can later capture a different remote game.

    import ChessCore
import FianchettoKit

var seen = GameDedup.KeySet()
let fresh = PGNParser.parse(pgnText)
    .enumerated()
    .map { PreparedGameData(from: $1, orderIndex: $0) }
    .filter { seen.registerIfNew($0) }        // within-batch duplicates

var index = GameDedup.MatchIndex<PreparedGameData>()
for row in existingLibrary {
    index.register(row, for: GameDedup.Identity(row))
}

for incoming in fresh {
    let identity = GameDedup.Identity(incoming)
    switch index.resolution(for: identity, allowLegacyCompositeFallback: true) {
    case .unique(let local):
        index.unregister(identity)            // before the row changes identity
        apply(GameIdentity.promotingIdentity(identity.remoteID,
                                             gameID: local.gameID,
                                             tagsJSON: local.tagsJSON), to: local)
    case .ambiguous, .ambiguousLegacyPromotion, .none:
        insert(incoming)                      // never guess
    }
}

    PreparedGameData¶

    The off-main import DTO and the value mirror of the app's @Model StoredGame. init(from:orderIndex:) does the expensive work once, on whatever task built the batch:

    moveText            = PGNExporter.tokenText(from: pgnGame)
tagsJSON            = GameTagCodec.encode(AuthoredGameIdentity.externalTags(from: pgnGame.tags))
gameID              = GameIdentity.remoteID(link:site:), else GameDedup.compositeKey(...)
cachedMoveCount     = (pgnGame.moves.count + 1) / 2
cachedWhiteElo      = parseSanitisedElo(tags["WhiteElo"]) ?? 0
cachedBlackElo      = parseSanitisedElo(tags["BlackElo"]) ?? 0
cachedIsAnnotated   = 0                     // raw PGN ships no annotation
annotationEvalsJSON = ""    secondBestEvalsJSON = nil

    The memberwise initializer instead defaults the four cache fields to the sentinel -1, meaning "not computed yet". parseSanitisedElo trims whitespace and returns nil for "", "?", non-integers, and values <= 0. computeIsAnnotated(evalsJSON:moveText:) is true when the eval JSON is non-empty or the move text contains the literal "; best " — searched with .literal to skip the Unicode/locale fold.

    stableGameID recomputes identity at read time from the persisted Link/Site tags, so legacy Site-derived IDs project to content identity in memory with no destructive backfill.

    annotationEvalsJSON is not part of the source digest

    The per-ply eval arrays exist only for the trap extractor's storage-first prefilter. Including them in the digest would invalidate every existing scan witness and force a full library re-mine.

    Available from the command line: fianchetto-cli annotate emits exactly this white-POV per-ply array shape.

    The legacy "; best <SAN>" rewrite¶

    Legacy Fianchetto games stored the engine's best move as a bare inline marker right after the annotated move. Standard PGN treats ; as a comment to end-of-line, but Fianchetto move text is a single line — so ChessCore's tokenizer reads the bare ; as an illegal SAN and drops the entire main line. Making ; run to end-of-line is equally wrong: it would swallow every following move.

    PreparedGameData.normalizeForParsing(_:) (the public entry point to the same internal rewrite toPGNGame applies before tokenizing) turns each bare marker into a bounded brace comment:

    "… Nf3 ; best Bc4 …"          →   "… Nf3 {; best Bc4} …"
"… {+0.2; best e4} …"         →   unchanged, byte for byte

    The SAN is the single whitespace-delimited token after the marker. A "; best" already inside a {...} brace comment is a structured engine annotation and must stay intact — rewriting it there would shift content digests and dedup keys. The literal "; best " survives inside the new comment, so computeIsAnnotated keeps recognizing these games unchanged. The scan uses only character comparison and firstIndex(where:), avoiding Foundation range search so it transpiles cleanly to Android via Skip.

    Authored causality: the value model¶

    Two user fields are reconciled independently: AuthoredField.notes and .boardMarks. AuthoredFieldIdentity is the Comparable (logicalGameID, field) key — ordered by logicalGameID, then field.rawValue — so backup, health, and restore adapters cannot each invent their own grouping.

    Type Bound Why the bound is a rejection, not a normalization
    AuthoredReplicaID maximumUTF8Bytes = 96; bytes restricted to [0-9A-Za-z] plus - . _; empty rejected Keys must stay portable across JSON, CloudKit, SQLite, and Skip's Android runtime. Deliberately not UUID-only, so a namespaced legacy importer can own one synthetic head.
    AuthoredVectorClock maximumReplicaEntries = 32; a zero counter throws invalidClockCounter Silently dropping a zero counter or an over-cap replica would turn a true concurrent edit into apparent dominance. incrementing(_:) throws clockCounterOverflow at UInt64.max.
    AuthoredNotesValue maximumPayloadBytes = 256 * 1_024; U+0000 rejected Unicode normalization and whitespace are authored content and are preserved exactly. NUL is refused on every platform because Apple's SwiftData/SQLite string bridge truncates there — otherwise a cross-device snapshot could look valid and be unreproducible on Apple.
    AuthoredBoardMarksValue maximumPayloadBytes = 768 * 1_024 Explicitly a raw parser bound only. The authoritative CloudKit safety check is AuthoredHead.maximumEncodedBytes, because nesting this JSON inside a head expands quotes, slashes, and control characters.
    AuthoredHead currentSchemaVersion = 1, maximumLogicalGameIDBytes = 512, maximumEncodedBytes = 900 * 1_024 The encoded ceiling is checked after JSON escaping by encoded(), never estimated from raw text.

    AuthoredBoardMarksValue.init(source:) bounds the input, requires BoardMarkDocument.decodeStrict, re-bounds the canonical re-encoding, and only then hashes the canonical form. Decoding additionally requires document.encoded() == payload, throwing nonCanonicalBoardMarks otherwise. Both value types re-validate size, proof canonicality, and payload/proof agreement on decode — a stored payload can never disagree with its own SHA.

    AuthoredHead requires clock[authorReplicaID] > 0 (authorMissingFromClock) and authoredAtMilliseconds >= 0. encoded() uses [.sortedKeys, .withoutEscapingSlashes]; decodeBounded(_:) is the required entry point for untrusted bytes and rejects oversized data before parsing it.

    The derived revisionProof is a stable tie-break, never a substitute for the clock:

    revisionProof = SHA-256 over length-prefixed components:
    logicalGameID
    field.rawValue
    authorReplicaID.rawValue
    value.sha256
    String(authoredAtMilliseconds)
    "<replicaID>=<counter>"   for each clock replica, in sorted key order

    AuthoredHead.authoring(logicalGameID:authorReplicaID:value:observing:authoredAtMilliseconds:) bounds the observed heads to 32 (headLimitExceeded), requires a shared logicalGameID (identityMismatch) and unique storage keys (duplicateReplicaHead), joins every observed clock by per-replica max, then increments the author's counter. The result dominates every branch the editor actually saw.

    let replica = try AuthoredReplicaID(rawValue: installationIdentifier)
let logicalGameID = try AuthoredBlobRecordCodec.logicalGameID(
    forIdentitySource: game.stableGameID
)

let head = try AuthoredNotesHead.authoring(
    logicalGameID: logicalGameID,
    authorReplicaID: replica,
    value: try AuthoredNotesValue(text: editor.text),
    observing: observedHeads,                      // every branch the editor displayed
    authoredAtMilliseconds: Int64(Date().timeIntervalSince1970 * 1000)
)

// Two rows, written atomically with the direct field by the platform adapter.
let compactKey = AuthoredBlobRecordCodec.compactHeadKey(
    logicalGameID: head.logicalGameID,
    field: head.field,
    replicaID: head.authorReplicaID
)
let revisionKey = AuthoredBlobRecordCodec.immutableRevisionKey(for: head)
let json = String(decoding: try head.encoded(), as: UTF8.self)

    Authored causality: the reconciler¶

    AuthoredReconciler<Value>.relation(_:_:) is the five-case truth table every other decision is built from:

    Clock relation Values equivalent? Result
    .equal yes .equivalentRevision
    .equal no throws inconsistentRevision — a corrupt revision, not a conflict
    .dominates — .lhsDominates
    .dominated — .rhsDominates
    .concurrent yes .concurrentEquivalentValue
    .concurrent no .concurrentDivergentValue

    A differing logicalGameID throws identityMismatch first. Value equivalence requires both sha256 equality and canonicalPayload byte equality, so a SHA stays useful for indexing without a theoretical collision becoming authored identity. The clock relation itself walks the union of both replica key sets (absent = 0), tracking hasGreater/hasLess and returning .concurrent the moment both are true.

    selectSameReplicaHistory(_:limit:) (default limit 64) reduces the rows sharing one storage key:

    1. > limit candidates            → candidateLimitExceeded
2. all candidates must share one storageKey, else identityMismatch
3. exact-duplicate filter: bucket on revisionProof, then real equality inside
   the bucket (linear for ordinary history, still correct under a collision)
4. independent equal-clock detector: build "replica=counter;…" in sorted replica
   order; two distinct payloads under one clock identity set hasRelationFailure
   even if a later head dominates both
5. dominance sweep against the running maximal set; dominated entries move to
   `superseded`; a thrown relation sets hasRelationFailure
6. hasCausalConflict = hasRelationFailure || maximal.count != 1
7. active = the unique maximal head, or — when conflicted — the first entry in
   the stable order: revisionProof ascending, then encoded() bytes lexicographically

    selectReplicaHistories(_:limitPerReplica:) requires one shared logicalGameID, groups by authorReplicaID, rejects more than 32 represented replicas (headLimitExceeded(limit: 32)), and runs the same-replica selector per replica in sorted replica order.

    reconcile(_:) takes physical AuthoredHeadCandidates (≤ 64, unique copyIDs, ≤ 32 distinct storage keys where two candidates sharing a key must carry an identical head). All-pairs dominance splits maximal from superseded; maximal candidates group into AuthoredValueBranches by value equivalence. Ordering is where the annotation bit is handled carefully:

    within a branch   prefer isAnnotatedCopy == true, then (copyID, storageKey, revisionProof)
across branches   (copyID, storageKey, revisionProof) only — isAnnotatedCopy EXCLUDED

    Annotation quality comes from a mutable direct row: engine annotation may change without any user revision and must never advance a vector clock, so it may pick the physical representative of one already-equivalent value but can never select a divergent branch. preferred is the first branch's representative; hasConcurrentConflict is branches.count > 1, and every branch is retained.

    planDirectProjection(frontierCandidates:historicalWitnesses:directCopies:) turns that into a write decision:

    bounds   64 frontier candidates, 512 historical witnesses, 64 distinct direct values
empty    no known history at all → .noCausalState — checked BEFORE the witness
         rule, so direct copies with no causal state are never an error
witness  every direct copy's value must be explained by some known history value
         (SHA-bucketed lookup plus real equality), else unexplainedDirectValue
frontier selection must be conflict-free, else sameReplicaHistoryConflict
rejoin   any historical witness NOT dominated-by or equivalent-to a selected
         frontier head is "uncovered" and rejoins selection (limit 64 + 512),
         because causal knowledge missing from the compact frontier still counts
synthetic candidate copyID = "head.<field>.<replicaID>.<revisionProof>"
         isAnnotatedCopy = some direct copy with that exact value is annotated
verdict  conflict → .concurrentConflict
         otherwise → .converge(value:changedCopyIDs:) where changedCopyIDs is
         every direct copy whose value differs from the converged value

    An empty payload is a real authored value

    .converge with an empty canonicalPayload represents an exact authored clear. Adapters must write it, not skip it as "nothing to save".

    The record grammar¶

    AuthoredBlobRecordCodec is the stable CloudKit/backup key format. Two namespaces, two shapes:

    compactHeadNamespace       = "authoredHead.v1."
immutableRevisionNamespace = "authoredRevision.v1."

compact head key
  "authoredHead.v1." + field.rawValue + "." + token(logicalGameID)
                                      + "." + token(replicaID.rawValue)

immutable revision key
  "authoredRevision.v1." + field.rawValue + "." + token(logicalGameID)
       + "." + token(replicaID) + "." + counterToken(authorCounter)
       + "." + valueSHA256 + "." + revisionProof

token(s)         = base64(s) with '+'→'-', '/'→'_', all '=' stripped
counterToken(n)  = String(n) zero-padded to exactly 20 digits

logicalGameID(forIdentitySource:) = "stable.v1." + SHA-256(identitySource)
    throws invalidIdentitySource for an empty source or one containing U+0000

    The 20-digit padding is load-bearing: it makes lexicographic key order equal numeric counter order, which is exactly the input ordering AuthoredHistoricalReducer requires.

    Parsing is strict in both directions. A compact head key must split into exactly 5 dot-separated parts with parts[0] == "authoredHead" and parts[1] == "v1", a decodable field, a decodable and valid logical game ID, a valid replica ID — and then the parsed components are re-encoded and compared to the original key. A revision key must split into exactly 8 parts, with parts[5] exactly 20 UTF-8 bytes that parse as a UInt64 > 0 and round-trip through counterToken, and both parts[6] and parts[7] exactly 64 lowercase hex bytes, followed by the same full round-trip check. Token decoding refuses any source longer than 683 UTF-8 bytes — 512 logical-ID bytes encode to 683 unpadded base64url bytes — and also requires token(value) == source, so a non-canonical encoding of a valid value is rejected rather than silently accepted.

    DecodedRecord keeps the storage role alongside the payload (.notesHead, .boardMarksHead, .notesRevision, .boardMarksRevision) and exposes uniform kind, field, logicalGameID, authorReplicaID, and revisionProof accessors, so callers branch on role rather than on payload type.

    Member Role
    decode(key:dataJSON:) Bounded decode plus key/payload agreement; storageKeyPayloadMismatch if the key claims something the payload does not.
    selectCompactHeadSiblings(_:maximumCandidates:) Deterministic active/alternates/superseded split for rows sharing one compact key, with hasCausalConflict. Backup layers preserve every ordered candidate; projection layers fail closed on the bit.
    immutableRevisionProjection(for:) The canonical immutable row for any validated compact head.
    canonicalDataJSON(for:) Normalized bytes — raw JSON key order and whitespace are never identity.
    rekeying(_:to:) Moves a causal fact from a pre-marker alias to its canonical promoted identity. Clock, author, value, role, and time stay exact; only the identity-dependent proof and key regenerate.

    maximumCompactHeadCandidates is 64 and maximumCompactHeadAlternates is 63, because a backup sidecar excludes the active row.

    Backup reconciliation¶

    AuthoredBackupReconciler.plan(_:) is mutation-free and must complete before the first persistent write, which is what gives restore all-or-nothing semantics. It runs as an ordered pipeline:

    1. sidecar validation
     unique sidecar keys                    → duplicateConflictSidecar(key:)
     each sidecar has a primary row         → sidecarWithoutPrimaryRow(key:)
     each sidecar key is a compactHead key  → immutableRevisionSidecar(key:)
     <= 63 alternates                       → compactAlternateLimitExceeded(key:limit:)
     every alternate's key == sidecar key   → sidecarKeyMismatch(expected:actual:)
2. bound physical duplication to 256 rows per key, BEFORE decoding
                                            → physicalCandidateLimitExceeded(key:limit:)
3. decode every row                         → invalidRecord(key:)
   reject IDs outside Input.allowedLogicalGameIDs
                                            → orphanedLogicalGameID(String)
4. project EVERY compact head into its canonical immutable revision and re-decode
   it — so no compact history can be dropped as dominated before it exists as a fact
5. canonical immutable rows: group by key; every candidate for a key must be an
   immutable revision with a byte-identical decoded record
                                            → immutableRevisionConflict(key:)
   the surviving row's updatedAt = max over contributors
6. compact frontier groups: group by AuthoredFieldIdentity, collapse exact record
   duplicates (keeping the later timestamp), reject > 64 candidates per field
                                            → compactCandidateLimitExceeded(logicalGameID:field:limit:)
   all-pairs dominance (a thrown relation → compactHistoryConflict(key:)),
   then selectCompactHeadSiblings per storage key and re-check the 63 bound
   groups are emitted sorted by active key

    Step 2's ordering is deliberate: bounding before decoding means repeated identical payloads cannot become a CPU/memory amplification vector. Step 4's ordering is equally deliberate — the backfill happens before any dominated row can be removed.

    Plan.activeRows is the immutable rows plus each group's active row, key-sorted. Plan.conflictSidecars emits only groups with non-empty alternates, also key-sorted. BlobRow.updatedAt is optional because older backup active rows and Android's live file store may carry no trustworthy timestamp; merges take the max of the contributing timestamps.

    DirectProjectionIndex(from:) partitions row locations once so each per-game query decodes only that game's selected field. It re-sorts the immutable row indices by key even though plan(_:) already emits key order — Plan.init is public, and array presentation is never treated as causal evidence.

    When planDirectProjection throws sameReplicaHistoryConflict, the reconciler re-runs selectReplicaHistories on the frontier alone and makes one distinction:

    some FRONTIER selection is itself conflicted
    → the same-key compact siblings are already the visible unresolved frontier
    → downgrade to .concurrentConflict  (lossless; no direct value chosen)
frontier is clean
    → the conflict came from a historical lower-counter fork
    → rethrow, because that fork is retained precisely so a later compact
      projection cannot hide it

    virtualCompactHead(fromImmutable:) converts one validated immutable revision into the equivalent compact row — used only for bounded revision-only recovery when a replica's mutable projection has not arrived locally.

    let plan = try AuthoredBackupReconciler.plan(
    .init(
        primaryRows: liveRows + incomingBackupRows,
        conflictSidecars: incomingSidecars,
        allowedLogicalGameIDs: ownership.rawAllowedLogicalGameIDs
    )
)

let index = try AuthoredBackupReconciler.DirectProjectionIndex(from: plan)
for game in restoredGames where index.containsCausalState(
    logicalGameID: game.logicalGameID, field: .notes
) {
    let directCopies = try game.copies.map { copy in
        AuthoredDirectValueCopy(
            copyID: copy.id,
            value: try AuthoredNotesValue(text: copy.notes),
            isAnnotatedCopy: copy.isAnnotated
        )
    }
    let decision = try index.notesDirectProjection(
        logicalGameID: game.logicalGameID,
        directCopies: directCopies
    )
    switch decision {
    case .converge(let value, let changedCopyIDs):
        write(value.canonicalPayload, to: changedCopyIDs)   // empty text is a real clear
    case .concurrentConflict:
        surfaceConflictUI(for: game)                        // every branch retained
    case .noCausalState:
        break
    }
}

    Bounded history and retention¶

    AuthoredHistoricalReducer<Value, Element> streams one field's append-only history down to its retained causal frontier plus direct-value witnesses. It is generic over an arbitrary Element with a head projection closure, so it reduces storage rows without materializing decoded copies.

    input order    storage-key order: field, replica, zero-padded counter, proof
in flight      exactly one equal-counter batch
equal batch    any pair whose relation throws → inconsistentRevision
               (a later dominating revision must not erase evidence that one
                vector clock carried incompatible immutable payloads)
guards         same replica with authorCounter <= pendingAuthorCounter → inconsistentRevision
               re-entering a completed replica                          → inconsistentRevision
               a 33rd distinct replica                → headLimitExceeded(limit: 32)
flush          selectSameReplicaHistory with limit = maximumRetained * 2,
               guarded by multipliedReportingOverflow
witnesses      the first element matching each unique direct value, appended after selection
retained > maximumRetained (default 512)  → historicalWitnessLimitExceeded(limit:)
finish()       re-normalizes through selectReplicaHistories so inventory repair,
               projection, and every platform adapter share identical replica rules

    Retention is a deliberately one-sided gate. AuthoredRevisionRetentionPolicy.currentGarbageCollectionDecision is always .retainAll(blocker: .acknowledgedEpochUnavailable), and GarbageCollectionDecision.permitsDeletion is a hard-coded false kept as an explicit predicate so no storage implementation can mistake an observational metric — an old counter, a dominated value, elapsed time, a row count — for prune authority. Safe reclamation needs a sync-visible checkpoint epoch, an authoritative active/retired replica set, acknowledgement from every member, and proof that each removed revision is covered. Those records do not exist yet; adding a deletion-authorizing case is reserved for that protocol.

    SyncVisibleRetentionStorageKeys already reserves the key families it will use, all under personalEndgames/retention/v1/: roster/, capability/, root/, proposal/, ack/, seal/, sweepAck/, completion/. Values there are immutable and content-addressed, so adapters may tolerate identical physical duplicates.

    Authored identity markers¶

    AuthoredGameIdentity stores the logical ID inside native game metadata under the reserved key _FianchettoAuthoredLogicalID, which is intentionally not a valid PGN tag name. A valid marker is markerPrefix (stable.v1.) followed by exactly 64 lowercase hex bytes.

    marker(in:) fails closed rather than lenient:

    Condition Result
    No reserved key present and no raw _FianchettoAuthoredLogicalID= substring nil — legacy opaque tag bytes are marker-free, not damaged
    Reserved key present but GameTagCodec.encode(tags) != tagsJSON throws malformedTagStorage
    More than one reserved key spelling throws conflictingMarkers
    Value fails isValidMarker throws malformedMarker

    Each error carries a user-facing LocalizedError description, because the app surfaces them instead of guessing which game an edit belongs to.

    externalTags(from:) and externalTagsJSON(from:) strip the reserved key case-insensitively at every generic PGN boundary (imports, exports, tag editors) so a spoofed spelling cannot cross; native backups preserve it as internal metadata. replacingExternalTags(existingTagsJSON:with:) swaps user-visible tags while retaining the sole valid marker, and identitySeedTagsJSON(from:) additionally drops FianchettoLegacyGameID, since promotion may add that alias after a duplicate copy already exists.

    Ownership resolution runs a two-pass marker preflight: the first pass proves that every marked seed and remote identity is compatible (a contradiction throws conflictingMarkers before any row is touched), and the second resolves marker-free copies. Two result shapes exist:

    Type Retains Use
    LogicalIDOwnership<ID> logicalIDByCandidate plus canonicalLogicalIDByAlias Live import and validation, where a per-game table is wanted.
    ReplayableOwnershipIndex canonicalLogicalGameIDs plus only the aliases whose canonical value actually differs Export, which already owns a replayable native snapshot. Drops the per-game dictionary entirely.

    ReplayableOwnershipIndex.logicalGameID(identitySeed:semanticRemoteGameID:tagsJSON:) re-resolves one replayed copy from the retained marker indexes, and rawAllowedLogicalGameIDs transiently reconstructs the raw set for the first authored preflight rather than retaining a second full set throughout export. Omitting alias -> alias entries is safe because every consumer looks up with identity fallback — and the canonical set doubles as the collision index, so an alias seen later cannot silently rekey an earlier lineage.

    // First explicit authored write on a game with no marker yet.
let resolution = try AuthoredGameIdentity.resolveOrCreate(
    tagsJSON: row.tagsJSON,
    identitySource: GameDedup.authoredIdentityKey(
        white: row.white, black: row.black, date: row.date, result: row.result,
        event: row.event, opening: row.opening,
        moveText: row.moveText, tagsJSON: row.tagsJSON,
        strippingDerivedAnnotations: row.cachedIsAnnotated == 1
    )
)
if resolution.insertedMarker {
    // tagsJSON must be persisted atomically with the direct field,
    // the immutable revision, and the compact head.
    row.tagsJSON = resolution.tagsJSON
}

    Semantic compare-and-save¶

    AuthoredSemanticCAS.plan(current:expected:desired:mode:) is the whole kernel — one pure static function over any Equatable & Sendable value:

    current == desired mode current == expected Decision
    yes .resolveKnownFrontier no .conflict(currentValue: current)
    yes .resolveKnownFrontier yes .repairMetadata(base: expected)
    yes .ordinaryEdit either .repairMetadata(base: desired)
    no either yes .commitDirectValue
    no either no .conflict(currentValue: current)

    An idempotent retry — where the desired value is already durable — still returns .repairMetadata rather than "done", because the direct value may have landed while its causal metadata did not; the adapter must verify or repair against an exact semantic base. And .resolveKnownFrontier refuses a match the user never reviewed: if the durable value happens to equal what they typed but differs from the frontier they were shown, that is a conflict, not a resolution.

    Progress-blob semantic merge¶

    Platform last-write-wins loses earned progress when two devices both trained offline, but a generic JSON-object merge would corrupt these payloads outright. ProgressBlobSemanticMerger is a typed merge for a fixed allowlist; every other key must fall through to the platform's ordinary LWW policy.

    mergeableKeys = tacticsRating, tacticsPerformance, drillSRS, repertoireDrillStats, blunderMastery, endgameHistory. Menu snapshots and rebuildable caches are deliberately excluded.

    Every family shares one gate:

    order        updatedAt DESCENDING, then json ASCENDING
             (so the legacy-baseline choice is fetch-order independent)
filter       keep only candidates the specific consumer can actually decode
abandon      contributors.count <= 1 → nil
             a single readable row keeps its exact bytes and timestamp, while a
             newer malformed sibling remains conflict evidence

    ProgressBlobMergeResult.latestContributorUpdatedAt maxes over contributors only (default .distantPast), so a syntactically valid but wrong-schema sibling cannot lend its newer timestamp to the synthetic union.

    Then, per family:

    tacticsPerformance
  union attempts by UUID; on collision keep the lexicographically smaller
    canonical .sortedKeys JSON
  drop attempts whose id is in the union of discardedAttemptIDs
  drop attempts whose timestamp is not strictly greater than max(resetAt)
  sort by (timestamp, id.uuidString); capLast(3_000)
  schemaVersion = max over stores, default 1

repertoireDrillStats
  the identical rule, applied per repertoire ID
  keep suffix(200) per repertoire; lastDrilled = last retained attempt's timestamp

tacticsRating
  ledger stores = those carrying legacyBaseline, mutations, or clearsLegacyBaseline
  compacted store = max mutationCompactedAt (.distantPast default),
    ties break toward the LOWER index because candidate order is newest-first
  clearsLegacyBaseline when resetAt >= (compactedAt ?? .distantPast)
  baseline: cleared → empty
            else the compacted store's legacyBaseline
            else the first ledger baseline    (a ledger's embedded pre-migration
              base outranks a later legacy whole snapshot, which could
              double-apply mutations)
            else synthesized from the newest store's materialized userRating,
              puzzleRatings, ratingHistory, repertoirePerformance
  mutations unioned by UUID minus discardedMutationIDs, same canonical tie-break,
    emitted sorted by id.uuidString so hash order never leaks into canonical JSON
  finally rebuildFromMutationLedger()

drillSRS
  same ledger/compacted selection; mutations unioned by UUID (no discard set)
  no ledger baseline → per-key FIRST-WINS entry merge over candidate order (newest first)

blunderMastery / endgameHistory  (ConsecutiveCorrectProgress)
  same ledger/compacted selection
  no ledger baseline → per-key MAX across states

    guard ProgressBlobSemanticMerger.canMerge(key: key) else {
    return platformLastWriteWins(key)
}
let merged = ProgressBlobSemanticMerger.mergedResult(
    forKey: key,
    candidates: siblings.map {
        ProgressBlobCandidate(json: $0.json, updatedAt: $0.updatedAt)
    }

store.saveJSON(merged.json, forKey: key)
recordBackupPrecedence(merged.latestContributorUpdatedAt)

    Portable hashing¶

    PortableSHA256 exists for two reasons: CryptoKit is unavailable in the native Android build, and Swift's Hasher is randomized per process, so it can never produce a durable key. It is a standard FIPS 180-4 implementation — initial state 0x6a09e667 … 0x5be0cd19, the 64 round constants starting 0x428a2f98.

    PortableSHA256.Hasher retains constant storage: at most one 64-byte input block plus the fixed 64-word schedule. finalize() copies the state rather than consuming it, so a caller can snapshot a prefix digest and keep appending. byteCount is reduced modulo 2^64 exactly as SHA-256's length encoding requires.

    The single most important method is the framing everything else depends on:

    update(lengthPrefixedUTF8: s)
    = UInt64 big-endian UTF-8 byte count of s   (bytes at shifts 56, 48, … 0)
    ‖ the UTF-8 bytes of s

    That is one unambiguous, injective encoding, and it is used identically by the authored revisionProof and by every GameDedup content key — which is why an Apple device and an Android device compute the same key for the same game. GameDedup.moveTextFingerprint(_:) exposes the plain PortableSHA256.hexDigest(utf8:) for callers that just want a process-independent fingerprint.

    ExactByteProof pairs a byteCount with a lowercase SHA-256 hex string. init(bytes:) and init(utf8:) hash incrementally and retain no payload-sized copy (a payload above Int.max bytes hits an explicit preconditionFailure("An exact-byte proof exceeded Int.max bytes")). Decoding deliberately preserves structurally invalid values so a persistence boundary can quarantine a damaged record without rewriting it, which is why validity is an explicit call:

    isStructurallyValid(minimumByteCount:maximumByteCount:) requires
    minimumByteCount >= 0
 && maximumByteCount >= minimumByteCount
 && byteCount >= minimumByteCount
 && byteCount <= maximumByteCount
 && isCanonicalSHA256(sha256)     // exactly 64 bytes, each in [0-9a-f]

    The bounds themselves must be nonnegative and ordered, so a malformed configuration cannot admit a proof.

    Appendix: GameViewCache¶

    The one presentation-adjacent type in this area. It memoizes EBoardSession.buildGameView() because MoveGenerator.legalMoves ran on every call at BLE notification cadence — measured at ~700 ms of main-actor block per event on a Samsung Galaxy A17 (Helio G85, debug build), the dominant OTB-view jank source.

    cache key   (ObjectIdentifier(game), game.position.fen, game.currentNode?.move.uci)
    FEN covers position, active color, castling rights, en-passant target, clocks
    currentNodeUCI invalidates the ancestor walk on retraction/take-back
    object identity stops a multi-session switch between two games sharing
      FEN + lastUCI from serving a stale ancestor chain
initial lastNodeUCI = "__INVALID__"      (distinct from the legitimate nil)
on a miss   walk the parent chain for at most 6 plies (take-back detection bound)
            castling rook homes from MoveGenerator.legalCastlingUCIs(for:) mapped
            through {"h1": "e1g1", "a1": "e1c1", "h8": "e8g8", "a8": "e8c8"}
            — measured ~3.6x faster than full legal-move generation

    GameViewSource is the minimal surface (position, currentNode) that lets the two platforms' distinct Game classes share one cache; ChessCore's Game conforms in this file.

    Main-actor only

    GameViewCache is non-Sendable by design — it holds game-tree references without a concurrency penalty — and must only be called from the main actor, the same requirement as the EBoardSession that owns it. It compiles headless (Foundation + ChessCore, no SwiftUI/UIKit), but its output drives an interactive board session, so it has essentially no CLI value.

    Using this from fianchetto-cli¶

    Almost everything on this page is already headless and batch-shaped: pure static functions over value types, with no engine, no network, and no UI. The JSONBlobStore seam in particular is trivially satisfiable by a directory of JSON files.

    Today the CLI covers the analysis seams — fianchetto-cli annotate, estimate, maia, accuracy, project, track — and the eval arrays annotate emits are the same shape this subsystem stores as annotationEvalsJSON.

    The natural additions here, following the same JSON-lines contract every existing subcommand shares via Tools/fianchetto-cli/Sources/FianchettoCLI/JSONLines.swift (one JSON object per line on stdin, one per line on stdout in request order, {"id": …, "error": …} for a failed row; per-command shapes live in <command> --help, and the seam map in Tools/fianchetto-cli/SUBCOMMANDS.md):

    Proposed subcommand Seam it would expose
    identity GameIdentity.canonicalProviderID, persistedRemoteID, stableID — audit a corpus for rows whose Link/Site do not resolve.
    dedup GameDedup.Identity + KeySet + MatchIndex.resolution — report duplicate buckets and ambiguous legacy promotions without mutating anything.
    authored-plan AuthoredBackupReconciler.plan and DirectProjectionIndex — validate a backup's authored rows and print the plan, since plan(_:) is already mutation-free.
    merge-progress ProgressBlobSemanticMerger.mergedResult over a set of candidate blobs.
    causality AuthoredReconciler.relation / reconcile / planDirectProjection over supplied heads — a conflict explainer.
    tags SavedGameTags.make and AuthoredGameIdentity.externalTagsJSON — canonicalize and strip internal metadata at a generic PGN boundary.
    digest GameDedup.compositeKey / authoredIdentityKey / legacyPromotionKey and PortableSHA256.hexDigest — reproduce any key by hand for cross-platform comparison.

    None of these are implemented yet; they are listed because each is a thin wrapper over an existing pure function, and because a divergence between iOS and Android key computation is exactly the kind of bug a corpus-scale CLI run finds first.
