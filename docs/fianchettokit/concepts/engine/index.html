    Engine, Annotation & Maia¶

    The engine subsystem: a UCI session layer shared by Stockfish and Reckless, the per-ply classification kernel that turns a raw eval sweep into !!/?? glyphs, two-engine consensus, and the Maia 3 board/policy codec plus the on-device Elo backfill pipeline built on it.

    Overview — headless kernels, one MainActor-isolated driver¶

    Every file under Engine/ imports only Foundation and/or ChessCore — no CoreML, SwiftUI, or UIKit. EngineBroker and EngineProbe are Swift actors, not observable view-model state. The actual UCI process/bridge and the actual model inference are both supplied by the caller through closures.

    That is not the whole isolation story, though: LiveAnalysisDriver and the protocols it publishes through are genuinely @MainActor-isolated, on the type itself — LiveAnalysisDriver.swift:112 (LiveAnalysisContext) and :314 (LiveAnalysisDriver), and LiveAnalysisPublication.swift:295 (LiveAnalysisResultPublishing). This is a real, load-bearing dependency the kit carries, not a doc-comment note about how to call the code. It is deliberate: LiveAnalysisDriver feeds the eval bar, best-move arrow, and "Top lines" panel while the user navigates a game, and it is designed to run on the same actor as the @Observable shell object it writes into, so no cross-actor hop is needed to publish evalCp, bestMoveUCI, or the ranked line list on every engine info line. That is a different case from AnnotationDriver.collectEvals's onProgress parameter, which stays @Sendable and actor-agnostic: a caller touching actor-isolated UI state from that callback still has to marshal onto it itself (Task { @MainActor in … }).

    Everything else here — EngineProbe, EngineBroker, AnnotationKernel, ConsensusKernel, Maia3Encoding, and the whole Maia backfill pipeline — carries no actor isolation beyond its own actor types and runs from a plain executable. LiveAnalysisDriver is the one deliberate exception, because it exists specifically to sit directly under a UI's observable state rather than behind a headless seam. That headless boundary for the rest is what lets fianchetto-cli's annotate, estimate, maia, and accuracy subcommands drive these same kernels from a plain executable, with a process-backed UCI engine and a CPU/ONNX Maia backend in place of the app's CoreML bridge.

    The engine session layer¶

    EngineProbe — the UCI transaction layer¶

    EngineProbe is an actor that owns one live engine's raw output stream and turns it into a journal with monotonic cursors (EngineOutputCursor), so a protocol wait can never be satisfied by stale output. It sits directly above ChessCore's UCIEngine transport seam; the caller supplies an EngineFactory — @Sendable (EngineKind, URL) -> (any UCIEngine)? — that builds a concrete engine or returns nil if it can't initialize (e.g. a missing NNUE net). The kit never links an engine package itself.

    Output journal. Every emitted line gets a monotonically increasing sequence number. The journal retains up to 4,096 lines under normal operation; once it exceeds 2× capacity (8,192 entries), an amortized compaction removes the oldest 4,096 at once rather than trimming per line. A cursor is valid only while its required sequence is still in the retained window — once it ages out, waits against it resolve to nil (fail closed) instead of resuming against a partial journal.

    Protocol barriers.

    • drainSearch(timeoutNanoseconds:) — the single-phase Stockfish barrier: stop + isready, wait for a fresh readyok, and if a search was in flight also wait for its terminal bestmove.
    • beginNewGame(timeoutNanoseconds:) — the two-phase Reckless barrier. Reckless's router ignores ucinewgame while a search is running, so this crosses drainSearch's phase first, then sends ucinewgame + isready and waits for a second readyok.

    Both default to 8,000,000,000 ns (8 s), the same timeout start(kind:networkDirectory:) uses for its own startup handshake.

    One-shot helpers replace the hand-rolled start→send→wait→stop loop every drill/annotation site used to write:

    Helper Returns Notes
    oneShotBestMove(fen:goCmd:maxIter:) String? MultiPV 1; legality-checked via legalBestMove
    oneShotScore(fen:goCmd:maxIter:pointOfView:) EngineScoreAdapter.Evaluation? Last rank-1 info before bestmove
    oneShotEvalCPAndMate(fen:goCmd:maxIter:) (cp: Int?, mate: Int?)? Splits oneShotScore's result
    oneShotIsMatingInBudget(fen:goCmd:budget:maxIter:) Bool? true iff 0 < mate <= budget
    oneShotRawLines(prelude:fen:goCmd:maxIter:pollNs:) [String]? Generalized collector; legacy pollNs default 50,000,000 ns (50 ms), timeout = maxIter × pollNs
    oneShotRecklessRawLines(prelude:fen:goCmd:readyTimeoutNanoseconds:searchTimeoutNanoseconds:) [String]? Fresh beginNewGame barrier; defaults 8 s ready / 20 s search

    legalBestMove(in:for:) is the safety net every helper routes through except the generalized oneShotRawLines collector, which leaves parsing to the caller's own parser by design (its doc comment: site-specific parse semantics are not altered) — oneShotRecklessRawLines still gates on it. legalBestMove itself takes the last bestmove line, parses it with UCIParser, and returns nil unless it's actually legal — rejecting trailing junk, uppercase promotion letters, and omitted promotion suffixes.

    EngineBroker — one live engine per kind¶

    The native engine bridges enforce exactly one live engine per process per EngineKind; a second construction blocks the underlying thread. EngineBroker is the process-wide actor owner that makes that safe under concurrent features, holding one EngineProbe.

    Two consumption patterns share the one probe:

    • Exclusive leases (withEngine(networkDirectory:_:)) — short-lived, one-shot consumers (annotation sweeps, drill probes, trap miners), FIFO across borrowers. No start/stop inside the lease — the broker starts lazily on first use and never tears down a healthy engine.
    • The revocable live slot (claimLiveSlot(id:networkDirectory:pause:resume:isValid:) / releaseLiveSlot(_:)) — continuous consumers (live eval bar, second opinion, play-vs-engine search). Last claimant wins: claiming pauses the current holder via its own pause closure and returns an opaque LiveClaim (probe, holderID, epoch), so a stale continuation can never interrupt a replacement. An exclusive lease likewise pauses the live holder first and resumes it once the last queued borrow drains.

    Failure is never silent. If the engine can't start, or stops answering its owner barrier (ownerBarrierTimeoutNanoseconds, default 8,000,000,000 ns), the broker attempts exactly one revival — tear the wedged engine down and rebuild through the same EngineFactory — before surfacing a typed, LocalizedError-conforming BrokerError.engineStartFailed / .protocolBarrierFailed. It never substitutes a different engine kind.

    let broker = EngineBroker(kind: .stockfish, engineFactory: myEngineFactory)

let bestMove = try await broker.withEngine(networkDirectory: netDir) { probe in
    await probe.oneShotBestMove(fen: position.fen, goCmd: "go movetime 800", maxIter: 200)
}

    Warning

    Never nest withEngine calls on the same broker — the FIFO lease queue self-deadlocks, since the outer call already holds the only lease the inner call is waiting on.

    Position evaluation¶

    AnnotationEval is the per-position payload every kernel here consumes (both iOS's PositionEval and Android's PositionEvalResult map onto it): engine-POV bestCp (mate flattens to ±100,000), optional secondBestCp, isMate, a signed mover-POV mateIn (the only place the mate distance survives the flatten), and bestMoveUCI ("" for terminal positions).

    PositionEvaluator is the one-method seam the whole pipeline depends on instead of a concrete engine — func evaluate(fen: String) async -> AnnotationEval?. AnnotationDriver.collectEvals(positions:evaluator:onProgress:) walks a game's positions, filling terminal ones from AnnotationKernel.terminalEval(for:) directly and routing the rest through the evaluator; it returns nil on cancellation or if the evaluator ever returns nil (engine went silent aborts the whole sweep).

    AnnotationEngineKind (String, CaseIterable, Codable, Sendable) sits beside that seam as the registry of which concrete evaluator a user may pick to drive library annotation — .stockfish (displayName "Stockfish") and .reckless ("Reckless"), persisted under settingsKey, the literal string "annotationEngine":

    AnnotationEngineKind.settingsKey            // "annotationEngine"
AnnotationEngineKind.resolve(nil)           // .stockfish
AnnotationEngineKind.resolve("reckless")    // .reckless
AnnotationEngineKind.resolve("maia")        // .stockfish — unknown values fall back

    resolve(_:) never fails: nil, an unknown raw value, or a value naming an engine that no longer qualifies all resolve to .stockfish. Membership here is a capability boundary, not a taste — only evaluating search engines, those producing a best move plus a centipawn or mate score per position, belong in this enum. Maia is deliberately absent: a human-move predictor (policy + WDL) cannot produce the centipawn deltas blunder-grading is built on, so it can never conform to PositionEvaluator's contract. Playing against an engine carries no such requirement, which is why PlayConfig.Engine is the wider set .maia / .stockfish / .reckless.

    struct StockfishEvaluator: PositionEvaluator {
    let broker: EngineBroker
    let networkDirectory: URL
    let movetimeMs: Int

    func evaluate(fen: String) async -> AnnotationEval? {
        try? await broker.withEngine(networkDirectory: networkDirectory) { probe in
            guard let lines = await probe.oneShotRawLines(
                prelude: ["setoption name MultiPV value 2"],
                fen: fen,
                goCmd: "go movetime \(movetimeMs)",
                maxIter: 400
            ), let position = Position(fen: fen) else { return nil }
            let ranked = UCIInfoParser.bestInfoByRank(lines)
            let bestMoveUCI = EngineProbe.legalBestMove(in: lines, for: position) ?? ""
            return AnnotationKernel.extractEval(fromRankedInfos: ranked, bestMoveUCI: bestMoveUCI)
        }
    }
}

    ranked above is a [Int: UCIInfoLine] rank map. UCIInfoLine is not a FianchettoKit type of its own — it's a compatibility typealias for ChessCore.UCIInfo. UCI line parsing is foundational chess logic, so ChessCore owns it; the alias (alongside UCIInfoParser for ChessCore.UCIOutputParser) exists purely so every FianchettoKit call site, and the Android port, kept compiling unchanged after the former kit-local copies were collapsed onto ChessCore's — which had already picked up the better parser (nps parsing, no mandatory pv token, bestmove (none) handling, bestInfoByRank). ChessCore.UCIInfo is a strict superset of the old line type: it keeps depth, multipv, scoreCp, mateIn, nps, pv, bestMoveUCI, centipawns, winProbability, displayText, and whitePovCentipawns, and adds a .score enum view plus .multiPV.

    RecklessLine is a different shape over the same kind of MultiPV sweep, built for display and persistence rather than kernel consumption: one Identifiable (on rank, 1 = best), Codable value per ranked line — rank, evalText (pre-formatted White-POV, e.g. "+1.34", "M5"), bestMoveSAN, bestMoveUCI. It deliberately leaves origin/target squares for the caller to derive from bestMoveUCI's prefix/suffix rather than storing them redundantly. It's the canonical replacement for what iOS (AnalysisSession.swift's own RecklessLine) and Android (RecklessTopLine, which split UCI into separate from/to fields) each kept as independent duplicates — the shared form standardizes on bestMoveUCI and adds Codable so a ranked-line list can round-trip through session persistence.

    EngineScoreAdapter is the one place a raw ChessCore.UCIInfo.Score becomes a mate-aware, explicitly-oriented Evaluation (centipawns + optional mateIn). PointOfView is .sideToMove (UCI convention) or .opponentOfSideToMove (flipped); flipping negates both fields via a saturating negation (Int.min maps to Int.max, never traps) — guarding a malformed cp Int.min line from turning a POV flip into a crash.

    The annotation kernel¶

    AnnotationKernel is the pure classification core both platforms previously hand-kept in sync: given a sweep of AnnotationEvals it decides, per ply, which glyph (if any) the move earns.

    Thoroughness scaling¶

    Two knobs read the same user "Annotation thoroughness" pref string ("fast" / "thorough" / anything else including nil):

    annotateMovetime(batch:thoroughness:)      // Stockfish, ms per position
  base = batch ? 500 : 1000
  "fast"      -> base * 6  / 10   //  300 / 600 ms
  "thorough"  -> base * 16 / 10   //  800 / 1600 ms
  default/nil -> base             //  500 / 1000 ms

annotateDepth(thoroughness:)               // Reckless, search depth in plies
  "fast" -> 10   "thorough" -> 14   default/nil -> 12

    Terminal and extracted evals¶

    terminalEval(for: position)
  no legal moves, in check  -> bestCp = -100_000, isMate = true,  mateIn = 0,   bestMoveUCI = ""
  no legal moves, no check  -> bestCp = 0,         isMate = false, mateIn = nil, bestMoveUCI = ""
  has legal moves           -> nil   // non-terminal; caller must probe the engine

extractEval(fromRankedInfos: bestMoveUCI:)     // from a UCIInfoParser.bestInfoByRank map
  rank 1 .mate(m)  -> bestCp = ±100_000 (sign of m), isMate = true,  mateIn = m
  rank 1 .cp(cp)   -> bestCp = cp,                    isMate = false, mateIn = nil
  no rank 1 score  -> nil
  rank 2 .mate/.cp -> secondBestCp set the same way; absent -> nil

    Every forced mate collapses bestCp to ±100,000 throughout this subsystem; the true distance survives only in mateIn.

    classifyGlyph — the annotation decision cascade¶

    Evaluated in order; first match wins:

    classifyGlyph(wpDrop:wpBefore:wpAfter:gap:playedBestMove:opponentMissed:involvesSacrifice:absEvalCp:)

Error band (worst first):
  wpDrop >= 0.20   -> blunder
  wpDrop >= 0.10   -> miss (if opponentMissed) else mistake
  wpDrop >= 0.05   -> miss (if opponentMissed) else dubious

Positive band (wpBefore < 0.75 required for brilliant — "not already winning"):
  wpDrop < 0.02 && gap >= 0.15 && |absEvalCp| < 50_000
    && wpBefore < 0.75 && involvesSacrifice          -> brilliant
  wpDrop < 0.02 && gap >= 0.08
    && (wpBefore < 0.40 || (wpBefore < 0.55 && wpAfter > 0.60)) -> great
  playedBestMove && gap >= 0.03                      -> best
  wpDrop < 0.02 && gap >= 0.03                       -> excellent
  wpDrop < 0.05 && gap >= 0.06                       -> good
  otherwise                                          -> nil   // fine, not remarkable

    gap is the MultiPV win-probability gap between best and second-best (0 if no second line). opponentMissed, computed per ply:

    opponentMissed = (oppWP - oppWPAfter) >= 0.10 && wpBefore > 0.55
  oppWP      = winProbability(evals[i-1].bestCp)   // opponent's WP two plies back
  oppWPAfter = 1 - wpBefore                        // opponent's WP right after their move

    — the previous mover held a 10+ point swing and the current mover is still above 55%, meaning the opponent just failed to capitalize. involvesSacrifice (positionBefore:positionAfter:) feeds the brilliant gate:

    for each of the mover's pieces on the post-move board, excluding king and pawn:
  skip unless the opponent attacks the square
  attacked AND undefended by the mover        -> sacrifice
  attacked AND defended, but specifically by
    an opponent PAWN                          -> sacrifice (still a net material loss)

    AccuracyAggregator.classifyMoveQuality(wpDrop:playedBestMove:) (see Analysis Math) runs alongside classifyGlyph inside computeAnnotations to derive the separate, coarser 6-band MoveQuality written onto each node: playedBestMove short-circuits to .best; otherwise wpDrop >= 0.20/0.10/0.05/0.02 steps down through blunder/mistake/inaccuracy/good/excellent.

    computeAnnotations, applyAnnotations, annotateNodes¶

    The pass splits into a pure stage (computeAnnotations(inputs:evals:startIsWhite:) -> [NodeAnnotationResult], Sendable end to end so it can run in Task.detached) and a write stage (applyAnnotations(_:to:game:)) that always clears every node's annotation fields first — so a re-annotation pass starts from a clean slate — then writes the new values. annotateNodes(mainLine:evals:game:startIsWhite:) is the backward-compatible wrapper that does both.

    let evals = await AnnotationDriver.collectEvals(
    positions: positions,   // positions[0] = start; positions[i+1] = after mainLine[i]
    evaluator: StockfishEvaluator(broker: broker, networkDirectory: netDir, movetimeMs: 1000)
)
guard let evals else { return }   // cancelled, or the evaluator went silent

AnnotationKernel.annotateNodes(mainLine: mainLine, evals: evals, game: game, startIsWhite: true)

    The annotation pass kernel¶

    AnnotationPassKernel sits above AnnotationKernel and owns the pass-level recipes both shells previously duplicated. Each decision below is pinned to a lettered "D" number from the 2026-07-31 extraction and covered by a kit parity test.

    One-shot eval validation (D11). validatedOneShotEval(_:fen:) -> AnnotationEval? — AnnotationDriver.collectEvals only calls the evaluator for non-terminal positions, so an acceptable eval must name a legal best move. Stockfish's "(none)" normalizes to ""; empty, unparseable, or illegal-in-fen rejects the eval outright (aborts the sweep).

    Verify-baseline rebuild (D7 / D8). rebuildVerifyBaseline(nodes:startIsWhite:provenanceJSON:finalPosition:retainedFinalWhiteCp:) -> Result<[AnnotationEval], VerifyBaselineFailure> reconstructs a mover-POV baseline from stored per-node fields (StoredBaselineNode { engineEval, engineBestMoveUCI }) for a "verify with the second engine" pass. D8: refuses to run unless provenanceJSON decodes to a Stockfish AnnotationProvenance (.provenanceNotStockfish). D7: every node must carry a parseable stored eval; one unparseable node hard-fails the entire rebuild (.unparseableStoredEval) rather than quietly substituting cp(0), which could misclassify that move. The parser inverts AnnotationKernel's display format:

    parseStoredWhitePovEval(_:)
  "-M<N>" / bare "-M"   -> .mate(-N)     // bare sentinel means N = 1
  "M<N>"  / bare "M"    -> .mate(+N)
  "+1.3" / "-0.5" / "+0.0"  -> .cp(round(value * 100))   // pawns, |value| <= 1_000
  anything else          -> nil

storedWhiteCPScore(_:)                    // decoding the retained final-eval chart value
  non-finite, or |value| > 100_000  -> nil
  |value| == 100_000                -> .mate(value >= 0 ? +1 : -1)
  otherwise                         -> .cp(round(value))

    The trailing sentinel (eval "after the last move") prefers the exact terminal eval when the final position is terminal, else the retained chart value — never inventing cp(0), which could falsely reclassify the last move (.missingFinalEval otherwise).

    Batch charts and the per-game recipe (D1 / D4). serializeCharts(evals:startIsWhite:) -> AnnotationCharts (evalsJSON, secondBestJSON, mateDistancesJSON, all White-POV). D1: all three charts are always emitted, with explicit JSON null where no second line / no forced mate exists, so a game annotated on either platform satisfies the same isFullyAnnotated contract. runBatchGame(positions:startIsWhite:hasMoves:evaluator:pauseGate:progress:persistCharts:markUnevaluable:) -> BatchGameResult (.persisted, .unevaluable, .persistRejected, .engineSilent, .cancelled). D4: a zero-move / unparseable game calls markUnevaluable() and returns .unevaluable instead of being silently skipped forever, so a batch pass converges.

    Provenance and display¶

    AnnotationProvenance — compatibility rules¶

    AnnotationProvenance (engine, engineRevision, searchKind: .movetimeMilliseconds | .depth, searchLimit, multiPV, includesConsensus, plus schemaVersion/contractVersion pinned to 1) is the durable identity of one annotation run — without it, switching Stockfish ↔ Reckless or changing thoroughness could silently reuse a stale array as current.

    Two compatibility checks, deliberately different strictness:

    Field satisfies — serve a cached request satisfiesRefreshRequirement — offer an auto-refresh
    schema/contract version both self and required == current same
    engine exact match exact match
    engineRevision exact match ignored — revisions describe, they don't expire
    searchKind exact match exact match
    searchLimit self >= required (deeper/longer satisfies weaker) self >= required
    multiPV exact match exact match
    includesConsensus superset: includesConsensus \|\| !required.includesConsensus same

    AnnotationProvenanceCodec.decode only accepts JSON ≤ 4,096 UTF-8 bytes that is also structurally valid: engineRevision non-empty, ≤ 512 UTF-8 bytes, printable ASCII only (0x20...0x7e); searchLimit in 1...60_000; multiPV in 1...32. A missing, malformed, or future-schema envelope decodes to nil — stale, never silently current.

    AnnotationDisplay — glyph, name, and color tables¶

    Centralizes what iOS and Android had each copied and let drift once already ("Dubious" vs "Inaccuracy"). Pure String/Double extensions on ChessCore.MoveAnnotation / MoveQuality — no SwiftUI Color.

    MoveAnnotation.displayGlyph / .displayName / .displayRGB:

    great △ Great (0.35, 0.55, 0.71)
    best ✓ Best (0.55, 0.72, 0.30)
    excellent ✓ Excellent (0.55, 0.72, 0.30)
    good ! Good (0.45, 0.65, 0.50)
    interesting !? Interesting (0.45, 0.70, 0.45)
    dubious ?! Inaccuracy (0.90, 0.64, 0.45)

    Two-engine consensus¶

    ConsensusKernel reads two independent strong engines' takes on the same position and reports how much they agree — the basis for the "higher confidence" badge and "critical moment" flags. Both Stockfish and Reckless emit normalized centipawns (Reckless's normalize_to_cp mirrors Stockfish's NormalizeToPawnValue), so AccuracyAggregator.winProbability applies to both on the same scale — no engine-specific calibration needed.

    compare(a, b, criticalGap: 0.15)     // EngineRead { cp, isMate, bestMoveUCI }; winProbability clamps mate to 0/1
  gap      = |a.winProbability - b.winProbability|
  sameMove = a.bestMoveUCI == b.bestMoveUCI && bestMoveUCI not empty
  critical = gap >= criticalGap || (!sameMove && gap >= criticalGap * 2 / 3)   // 0.15, or ~0.10 on disagreement
  confidence = sameMove && gap < 0.05 ? .high : critical ? .low : .medium

    reconcileAnnotation(_:_:) merges two independently classified glyphs into one consensus glyph via a severity ladder, so a single engine's noise can't produce a false-positive ??/!!:

    severity: brilliant=+4  great=+3  best/excellent=+2  good/interesting=+1
          nil=0  dubious=-1  miss/mistake=-2  blunder=-3

reconcileAnnotation(a, b):
  severity(a) == 0 || severity(b) == 0     -> nil   // one engine finds it unremarkable
  sign(severity(a)) != sign(severity(b))   -> nil   // opposite directions, no consensus
  otherwise -> whichever of a, b has the SMALLER |severity|   // what both engines actually support

    ConsensusRecord (ply, agree, winProbGap, confidence as a raw string, critical) is the persisted per-ply summary; ConsensusJSON encodes/decodes [ConsensusRecord] as a plain array, returning "[]" / [] on any failure rather than throwing.

    Maia 3¶

    Maia3Encoding is the pure, engine-agnostic codec for the Maia 3 network — inference (CoreML on Apple, ONNX/LiteRT on Android) stays app-side; only the tensor shapes are shared.

    encodeTokens(position:)                          // 768 Float32s = 64 squares x 12 planes
  isBlack = position.activeColor == .black
  for each square (White's rank/file order):
    actualRank   = isBlack ? 7 - rank : rank                       // mirror ranks when Black is to move
    pieceColor   = isBlack ? piece.color.opposite : piece.color    // mirror color too
    featureIndex = pieceFeatureIndex(type) + (pieceColor == .white ? 0 : 6)
    tokens[(rank*8 + file)*12 + featureIndex] = 1.0
  pieceFeatureIndex: pawn=0 knight=1 bishop=2 rook=3 queen=4 king=5

policyIndex(for: move, activeColor:)             // squares mirrored to White's view when Black is active
  regular:    fromSq*64 + toSq                         // 0..4095, sq = rank*8 + file
  promotion:  4096 + fromFile*32 + toFile*4 + promoIdx  // 4096..4351; promoIdx: queen=0 rook=1 bishop=2 knight=3

    decodeOutput(moveLogits:valueLogits:position:topK:) throws -> EngineAnalysis requires moveLogits.count >= 4352 or throws .predictionFailed. Its value head reorients the raw side-to-move-POV softmax into an explicit White-POV WDL — [stmLoss, drawProb, stmWin] = softmax(valueLogits[0..2]), then Black-to-move maps to .winDrawLoss(win: stmLoss, draw:, loss: stmWin) and White-to-move to .winDrawLoss(win: stmWin, draw:, loss: stmLoss). Legal moves (.noLegalMoves if none) are gathered by policyIndex, softmaxed only over that legal-move subset (max-subtracted for stability), then sorted and truncated to topK ScoredMove(move, notation, probability) entries.

    PlayMoveKernel.weightedRandomMove(from:using:) picks the move actually played from that distribution, generic over RandomNumberGenerator for deterministic tests:

    totalProb <= 0  -> moves.first
else: r = uniformRandom(in: 0..<totalProb); walk moves subtracting probability;
      first move where r <= 0 (a CDF walk) -> chosen; walk exhausts -> moves.last

    let tokens = Maia3Encoding.encodeTokens(position: position)
let (moveLogits, valueLogits) = try await maiaModel.predict(tokens: tokens, eloSelf: 1500, eloOpponent: 1500)
let analysis = try Maia3Encoding.decodeOutput(moveLogits: moveLogits, valueLogits: valueLogits, position: position, topK: 5)
let chosen = PlayMoveKernel.weightedRandomMove(from: analysis.topMoves)

    MaiaRankStyle.tier(forRank:) maps a 0-based prediction rank to a display tier — .best (rank 0), .good (1–2), .moderate (3–4), .poor (≥5, or −1 for outside the top-K) — replacing two byte-identical implementations iOS and Android had each independently written. EloKernel.bestElo(from:) -> Int? picks the single most-likely Elo bucket from a {Elo bucket: average log-likelihood} map by argmax (nil for an empty map).

    GameAnalysis and GuessEloResult are the two result shapes the Maia move side of this feeds. GameAnalysis holds an array of nested MoveResult(moveIndex:playerMoveRank:playerMoveProbability:) values — 0-based ranks — and derives three summaries over moveResults: accuracy (share at rank 0), top3Accuracy (share with rank in 0..<3), and averageProbability (mean playerMoveProbability); all three return 0 for an empty array rather than dividing by zero. GuessEloResult carries whiteElo and blackElo as Int?, where nil means no estimate was produced for that side. Both types moved into FianchettoKit from ChessCore in the 2026-06-30 split; neither has a fianchetto-cli surface today — the Maia scoring path is reachable headlessly through fianchetto-cli maia, but the CLI emits its own JSON rows rather than these two struct shapes.

    The Maia Elo backfill pipeline¶

    Backs fianchetto-cli's estimate subcommand and the on-device background pass: score every qualifying position of the account owner's own moves against an 11-point Elo grid, accumulate log-likelihoods, and persist a versioned evidence envelope a separate estimator turns into a rating.

    Eligibility. isEligibleForBackfill = isCandidateForBackfill (statisticsEnabled && hasAnnotationEvals && !hasMaiaVector) && isEligible(tc:). TC eligibility: bullet/blitz/rapid/classical are eligible (classical alone contributes +115.6 Elo in the v4.1 fit); correspondence is not, and is served by the v2 binned-median instead. Position qualification mirrors the Python corpus collector: qualifiesForInference(plyIndex:legalMoveCount:) = plyIndex >= 8 && legalMoveCount > 2 (skip the opening 8 half-moves and forced moves).

    Golden fixture

    Ruy Lopez, Morphy Defence — 1. e4 e5 2. Nf3 Nc6 3. Bb5 a6 4. Ba4 Nf6 5. O-O Be7 6. Re1 b5 7. Bb3 d6 8. c3 O-O (16 plies) yields 8 qualifying positions at plies 8–15, with legal-move counts [27, 30, 25, 30, 25, 30, 27, 33] — pinned against a Python chess-library reference walk of the same game. The White-only walk returns plies [8, 10, 12, 14], Black-only [9, 11, 13, 15]. Scholar's mate (1. e4 e5 2. Qh5 Nc6 3. Bc4 Nf6 4. Qxf7#, 7 plies) yields zero — every ply is below the threshold.

    Opponent conditioning — Maia was trained on Lichess ratings, so a Chess.com (or unknown-provider) rating can't feed elo_oppo unadjusted:

    OpponentConditioning When used Opponent Elo fed to the model
    .exactLichess source == "lichess" and the rating is inside trainedOpponentEloRange (400...3,200) the game's actual opponent rating
    .neutralLichessPrior everything else neutralOpponentElo = 1,500

    Input fingerprint. ScoringContext.inputFingerprint is a 64-hex-character SHA-256 digest (PortableSHA256.Hasher) binding a persisted vector to the exact move list it was scored from. It hashes three things, each pushed as length-prefixed UTF-8 so no concatenation of adjacent tokens can collide: the current targetEvidenceContractID, then "white"/"black" for the owner's color, then every SAN token of the main line in order (mainLineSAN, from PGNParser.tokenize + .flatMoves over the normalized move text). Including the contract ID in the hash means a contract bump changes every fingerprint too, not just the envelope's contractID field.

    Elo grid. Sourced from EloCalibrationData.v41ensembleModel(forRawTC: TimeControlClass.blitz.rawValue), falling back to [600, 800, 1000, 1200, 1400, 1600, 1800, 2000, 2200, 2400, 2600]. expectedVectorLength == eloGrid.count == 11.

    Position encoding fails closed. encodeForInference(qualifying:) requires every position to encode to exactly 768 tokens with a policy index inside 0..<4352; one failure aborts encoding for the whole game (returns nil) rather than dropping that position via compactMap.

    Note

    Apple and Android originally disagreed three ways here — whole-game abort vs. silent drop, checked vs. unchecked token width, one- vs. two-sided policy-index range — so the same PGN could carry differently-normalized evidence (eligibleMoveCount normalizes the persisted estimate) depending on which platform scored it. Apple's fail-closed rule is now the shared contract.

    Evidence envelope. Versioned JSON: targetEvidenceContractID = "maia3-v4.1-owner-moves-elo-sweep-v1", schemaVersion = 1, moveScope = "account-owner-only", plus the owner's color/source/opponent-conditioning, the inputFingerprint above, eligibleMoveCount, and the 11 summed log-likelihoods. targetEvidenceContractID binds persisted evidence to a specific model and serving contract: the current Apple and Android asset hashes are registered alongside this same value in ModelContracts/maia-target-evidence-assets.registry, and Apple's staging pipeline verifies that registry before bundling the model. Bump the contract ID whenever the model's outputs, the Elo grid, the move scope, or the conditioning semantics change, so every stored envelope fails validation and requeues by itself — a registry-only hash update is safe only for byte-level repackaging whose numerical equivalence was established explicitly.

    Decoding (decodeTargetEvidenceEnvelope, run before any context check) enforces a full structural ruleset, not just the four headline fields:

    • schemaVersion == 1 and contractID == targetEvidenceContractID
    • moveScope == "account-owner-only"
    • playerColor is "white" or "black"
    • ownerUsername non-empty
    • source is already canonical (re-normalizing it is a no-op)
    • opponentElo finite and > 0
    • inputFingerprint.count == 64
    • every value in logLikes finite

    then a status-dependent shape check (status == "scored" requires eligibleMoveCount > 0 and exactly 11 logLikes; a missing status is treated as .scored, since the first generation of envelopes predates the field; "no-qualifying-owner-moves" requires both empty), then a conditioning cross-check (.exactLichess requires source == "lichess"; .neutralLichessPrior requires opponentElo == 1500). Any failure on any of these — not only a schema/contract/scope/side mismatch — makes the stored evidence stale and it requeues automatically.

    Legacy bare arrays are rejected here

    encodeVector(_:) / decodeVector(_:) still read and write the old unversioned [Double] form for the retired maiaLogLikesJSON field — kept only so old backups and the retired ANE remediation stay source-compatible; new scoring must never write it, and decodeVector only accepts arrays of exactly 11 values. The target-evidence path above never accepts a bare array. Those old vectors were scored over both players' moves, so a restored pre-fix backup must requeue rather than masquerade as corrected evidence.

    logSoftmaxAt(logits, idx)        // used by both scorers below
  idx out of range, or any logit non-finite -> nil
  else: logits[idx] - (max(logits) + log(sum(exp(logit - max(logits)))));  result non-finite -> nil

    Sequential and parallel scorers. MaiaBackfillGridScorer.score(eloGrid:encodings:opponentElo:inference:) sums logSoftmaxAt across every position, per grid point, via an Inference closure — @Sendable (tokens, eloSelf, eloOpponent) async throws -> [Float]. Any single inference failure throws and aborts the entire vector — a partial vector would bias exactly the point it stopped at and could never be cleanly retried. MaiaBackfillParallelScorer is the many-core twin: it scatters all eloGrid.count × encodings.count units across width = max(1, min(workerCount, units)) strided workers into a NaN-initialized terms array (NaN = "never computed", so the reduce hard-fails on any gap), then reduces per grid point in position order — bit-identical to the sequential scorer regardless of worker scheduling.

    Pacing. MaiaBackfillPacingPolicy replaced two independently-drifted magic numbers:

    Preset Inter-game delay Inter-slice delay
    .handheld 1 s 100 ms
    .desktop 100 ms 0 s (no slicing on the fan-out path)

    Per-game skeleton. MaiaBackfillGameScorer.score(_:pacing:workerCount:constraintGate:inferenceForWorker:): parse the main line off-actor → resolve scoringContext (.unresolvedAccountIdentity on failure) → no moves, or none qualifying, yields a terminal "no qualifying owner moves" evidence receipt → encodeForInference once, reused across every grid point (.positionEncodingRejected on failure) → sweep: workerCount > 1 fans out through MaiaBackfillParallelScorer, else one grid point per detached slice with the pacing breather between each (keeps a 30–90 s sweep cancellable and thermally quiet) → encodeTargetEvidence into .evidence(json), or .evidenceEncodingFailed. MaiaBackfillScoringFailure (unparseableMoveText, unresolvedAccountIdentity, positionEncodingRejected, inferenceFailed(String), evidenceEncodingFailed) is the typed reason for every non-evidence outcome; only inferenceFailed reports isTransient == true.

    MaiaBackfillRunKernel — the scheduler run loop. candidateLimit = 2_000 rows/batch, candidateEnumerationBatchSize = 256, completedRunRestartInterval = 900 s (15 min). shouldThrottleRestart(force:lastCompletedRunAt:lastCompletedStoreRevision:currentStoreRevision:now:) suppresses a restart only when unforced, a completion stamp exists, the store revision is unchanged, and less than 900 s has elapsed — a new/edited/imported game bypasses it via the revision check. shouldRecordSuccessfulSweepCompletion requires owning the generation, no cancellation, no candidate-limit truncation, no retryable failure, and processedCount == eligibleCount before stamping a completion. BoundedCandidateCursor<Candidate, ID> admits up to limit candidates while skipping already-excludedIDs, flipping reachedLimit once full — the pagination cursor that lets the scheduler page into older rows across batches instead of the newest 2,000 rows starving the rest of the library. SuccessorQueue coalesces forced wakes that arrive mid-sweep into exactly one immediate successor run; cancellation always clears any queued successor.

    Headless usage¶

    Three closure seams let this whole subsystem — engine, annotation, consensus, Maia — run from a plain executable:

    Seam Shape Supplies
    EngineFactory @Sendable (EngineKind, URL) -> (any UCIEngine)? The concrete UCI engine — process-backed on a CLI, native in the app
    PositionEvaluator func evaluate(fen:) async -> AnnotationEval? Whatever sits behind annotation — routes through an EngineBroker lease either way
    MaiaBackfillGridScorer.Inference @Sendable (tokens, eloSelf, eloOpponent) async throws -> [Float] The Maia backend — CoreML, ONNX Runtime, or a remote call

    The StockfishEvaluator shown earlier needs nothing beyond a UCIEngine conformer that shells out to a Stockfish binary — no CoreML, SwiftUI, or UIKit. The same shape carries through to Maia: wire inferenceForWorker to an ONNX Runtime session instead of a CoreML MLModel, and every kernel from MaiaBackfillPolicy through MaiaBackfillGameScorer runs unmodified.
