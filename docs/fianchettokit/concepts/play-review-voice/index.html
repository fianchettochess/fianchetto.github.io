    Play, Review & Voice¶

    The Play clock/result flow, the Review pane's derived stats, spoken-move input, and cross-platform leaf utilities (hashing, formatting, licensing data). Everything here is Foundation + ChessCore only — no SwiftUI, @Observable, Timer, or app-lifecycle types — so it runs the same in a unit test, in the iOS/Android apps, or headlessly from a CLI. See Headless-by-construction for the import table.

    Play¶

    ClockCore — the clock state machine¶

    Deadline-based, not per-tick. ClockCore banks each side's remaining time privately (whiteBanked/blackBanked) plus one optional activeSince: ContinuousClock.Instant? marking when the side to move started thinking. Every read computes banked − (now − activeSince) against ContinuousClock; nothing ticks the clock, and a read that arrives 40 seconds late (backgrounding, a paused compositor, a headless test with no frame clock) still comes back correct with no recovery code anywhere. whiteRemaining, blackRemaining, isRunning, isExpired, and loser are retained spellings — kept for the eleven Apple call sites that already read them — but they are now computed projections over the banked state, not independent mutable fields that could drift out of sync with it. ClockCore itself imports only Foundation and ChessCore: no Timer, no @Observable. A shell's own display loop decides how often to look; the clock doesn't care.

    RunState replaces a single isRunning Bool, because the old stop() conflated three situations that resume differently: .idle (never started), .running, .pausedByPlayer (a person pressed pause — the only state resume() accepts), and .stopped(StopReason), terminal. StopReason is .flagged(PieceColor) (latched at the deadline, never un-latches on its own) or .gameEnded (an outcome — checkmate, resignation, an agreed draw — after which no flag can fall, even if resume() is called).

    The mutating surface:

    Member Behavior
    start(color:at:) Begins the clock with color to move; refuses if a side is already flagged.
    pause(at:) A person paused: banks the elapsed time, moves to .pausedByPlayer. Returns false if nothing was running.
    resume(at:) Resumes from .pausedByPlayer or .idle only — refuses a clock stopped by a flag or an outcome.
    stop() Retained spelling; maps to pause() (its legacy call sites all meant "a person paused").
    stopForOutcome(at:) Terminal stop for a chess/adjudication reason. resume() will not undo it.
    switchTurn(at:) Banks the mover's elapsed time, pays the increment, hands the turn over, and records a per-ply history frame. No-op unless running.
    tapAdvance(side:at:) The OTB button rule: the first tap starts the opponent's clock; thereafter only the side to move may press; a tap from the wrong side changes nothing. Returns whether the tap did anything.
    rewind(plies:at:) Undoes a takeback: restores banked time and the side to move from history. The increment is revoked; the thinking time is not refunded.
    poll(at:) Latches a flag that has fallen, attributed and banked at the deadline rather than at the read instant. Idempotent; call before any read that must not see a clock "still running" past its deadline.
    reset() Restores both sides to the initial time, white to move, not running, history discarded.

    And the reads:

    Member Behavior
    deadline() The instant the active side's flag falls, or nil if nothing is running — lets a shell schedule one wakeup instead of polling.
    flagged(at:) The side whose flag has fallen, derived from the deadline while running, read off the latch once poll has fired.
    renderRevision(at:) A value that changes exactly when a rendered clock string could look different — packs a structural counter with each side's display bucket (tenths below TimeInterval.clockTenthsThreshold, whole seconds above it), so a shell redraws on real state changes and not on every frame.
    text(_:at:) The rendered string for a side, via the kit's one clock formatter (TimeInterval.clockString), using the same threshold renderRevision buckets against — so the two cannot drift apart the way two hand-rolled per-face computations once did. 
    var clock = ClockCore(minutes: 5, increment: 3)   // 5+3 blitz
clock.tapAdvance(side: .black)   // black's first tap starts WHITE's clock
clock.tapAdvance(side: .white)   // white moved: elapsed time banked, +3s paid, black to move
_ = clock.poll()                 // latch a flag if the deadline has already passed
if let loser = clock.flagged() { print("\(loser) flagged") }
print(clock.text(.white))        // e.g. "4:58"

    Three siblings, not one type

    ClockSnapshot is the packed [Int64] wire shape a shell polls (fields, flags, whiteMillis, blackMillis, activeSide, incrementMillis, flaggedSide, plyCount, renderRevision) — a primitive array rather than JSON because a clock is read roughly ten times a second and crossing JNI as primitives costs ~11.7 ns against JSON's ~98 µs. ClockDefaults.defaultBaseSeconds (600) is the base time control assumed when a game carries no clock at all — an untimed replay still needs something to classify pressure against. ClockPressureBand is that classification: .healthy/.low/.critical via band(remainingSeconds:baseSeconds:), with the low/critical thresholds themselves relative to the base control — controls under quickControlSeconds (180s) go critical under 10s and low under 30s; longer controls go critical under 30s and low under 60s.

    TimePreset & TimeControlSelection¶

    TimePreset's raw value is the "<minutes>+<increment>" notation:

    Category Cases (raw value)
    Bullet bullet1_0 (1+0), bullet2_1 (2+1)
    Blitz blitz3_0 (3+0), blitz3_2 (3+2), blitz5_0 (5+0), blitz5_3 (5+3)
    Rapid rapid10_0 (10+0), rapid15_10 (15+10)
    Classical classical30_0 (30+0)

    TimeControlSelection (.noClock / .preset(TimePreset) / .custom(minutes:increment:)) codecs the persisted @AppStorage value. Apple and Android once wrote different strings for the same choice — Apple "preset:5+0", Android the bare rawValue "5+0" — so a preference saved on one platform silently read as "nothing saved" on the other (no crash or log; the picker just falls back to default). Canonical form is Apple's now, since Apple had already shipped those strings; the decoder accepts both:

    encoded:  .noClock -> "none"   .preset(p) -> "preset:<p.rawValue>"   .custom(m,i) -> "custom:<m>:<i>"

decode(raw): ""                  -> nil       (no stored preference)
             "none"               -> .noClock
             "custom:<m>:<i>"     -> parsed as Double then truncated to Int
                                     (old Apple entries can read "5.0:3.0")
             "preset:<rawValue>"  -> .preset(TimePreset(rawValue:))
             "<rawValue>" (bare)  -> .preset(TimePreset(rawValue:))   // legacy Android
             anything else        -> nil

    UserDefaults.standard.set(TimeControlSelection.preset(.blitz5_3).encoded, forKey: "timeControl")
switch TimeControlSelection.decode(stored) {
case .preset(let p):          ClockCore(minutes: p.minutes, increment: p.increment)
case .custom(let m, let i):   ClockCore(minutes: m, increment: i)
case .noClock, nil:           break   // untimed, or no stored preference
}

    CheckmateCelebrationPolicy & CheckmateCelebrationState¶

    A pure decision function from a stored Intensity (off=0, subtle=1, standard=2, festive=3 — Intensity(storedValue:) falls back to .standard, not .off, for any unrecognized integer) plus two accessibility flags, to a Decision:

    decision(storedIntensity, reduceMotion, hapticsEnabled):
    intensity = Intensity(storedValue: storedIntensity)
    showsConfetti      = intensity.rawValue >= Intensity.standard.rawValue(2) && !reduceMotion
    playsFestiveHaptic = intensity == .festive && hapticsEnabled
    showsGrandFanfare  = intensity == .festive && !reduceMotion
    playsGrandFinale   = intensity == .festive     // NOT gated on reduceMotion or haptics

    playsGrandFinale is the non-screen finale (sound gated separately by the view's sound preference, plus a connected e-board LED/beep) — independent of Reduced Motion because it isn't screen motion.

    CheckmateCelebrationState keeps hasCelebrated plus three monotonic trigger counters (confettiTrigger, festiveHapticTrigger, grandFanfareTrigger). celebrateOnce(storedIntensity:reduceMotion:hapticsEnabled:) -> Decision? is a no-op (nil) once hasCelebrated; on first call it flips hasCelebrated, computes the Decision, and bumps whichever counters that decision calls for via &+= 1 (wrapping, never rolled back — resetForNewGame() clears only hasCelebrated, since resetting a trigger to zero can itself re-fire the platform API bound to it).

    playsGrandFinale has no trigger counter

    grandFanfareTrigger tracks showsGrandFanfare (festive and not Reduced Motion), not playsGrandFinale (festive, full stop). A caller wanting the finale effect must read decision.playsGrandFinale directly off celebrateOnce's return value — no counter observes it later.

    GameResultPresentation — terminal-state text¶

    text(for state: GameState, activeColor: PieceColor) -> String?, isDraw(_ state: GameState) -> Bool:

    GameState text(for:activeColor:) isDraw
    .checkmate "Checkmate — White wins" / "...Black wins" false
    .stalemate "Stalemate — Draw" true
    .draw "Draw by 50-move rule" true
    .insufficientMaterial "Draw — insufficient material" true
    .repetition "Draw by threefold repetition" true
    .playing, .check nil false

    The checkmate winner is who is not to move: activeColor == .white ? "Black" : "White" — at checkmate activeColor is the side with no reply.

    Review¶

    ReviewSnapshotBuilder — the Review pane's derived state¶

    The off-view computer for every stat the Review pane shows, carved out of what were @MainActor computed properties re-evaluated on every body invalidation (including scroll). nonisolated; every function is a pure static transform over a mainline, an eval array, and PGN tags.

    public static func build(
    mainLine: [MoveNode], annotationEvals: [Double], loadedTags: PGNGame.OrderedTags?,
    whiteMoves: RepertoireBookKernel.RepertoireMoves = [:],
    blackMoves: RepertoireBookKernel.RepertoireMoves = [:]
) async -> ReviewSnapshot

    ReviewSnapshot carries perGameAccuracy, criticalMoments, brilliantMoments, topSwings, tablebaseEntryNode, openingExitNode + openingExitName, missedWinMoment, repertoireFit. build(...) fills it in a fixed order, calling await Task.yield() after each of the first seven assignments (not the eighth — the function returns right after):

    1 criticalMoments->yield  2 brilliantMoments->yield  3 tablebaseEntryNode->yield
4 missedWinMoment->yield  5 topSwings->yield          6 perGameAccuracy->yield
7 openingExit(node+name)->yield   8 repertoireFit (no yield — return)

    Only TablebaseService.pieceCount(for:) is touched — synchronous and local, never TablebaseService's network probe(fen:).

    • Critical/brilliant — criticalMoments filters .mistake/.blunder, sorts blunders before mistakes then by ascending plyIndex, prefix(6). brilliantMoments filters annotation == .brilliant || .great, keeps mainline order, prefix(6).
    • Tablebase entry — first mainline node whose positionAfter has pieceCount(for:) <= 7.
    • Opening exit — walks from move 1 through OpeningBook.shared, stopping at the first non-book position; nil if move 1 is already out of book (a contiguous-prefix walk, not "any book move anywhere").
    • Win-probability swings — needs ≥2 evals. Converts before/after White-POV eval via AccuracyAggregator.winProbability(cp:) (see Analysis math), flips for a Black mover: delta = (wpAfter - wpBefore) * 100 (mover-relative points). swing.delta = abs(delta); directionForMover keeps the sign. Top 6 by magnitude.
    • Missed-win moment — needs ≥20 evals and a Result tag. Scans plies [20, count) (skips the first 10 full moves), tracking White's and Black's peak eval independently so one side's early missed chance isn't hidden behind the other's later, larger, converted advantage: 
      white qualifies iff result != "1-0"  and  200 <= whitePeak.cp      < 5000
black qualifies iff result != "0-1"  and  200 <= abs(blackPeak.cp) < 5000
pick the qualifying side with larger abs(cp);  movedAt = (index / 2) + 1
    • Per-game accuracy — combines White's and Black's independent AccuracyAggregator.GameAccuracy sample-count-weighted, not a flat 50/50 average (an odd-ply game gives one side an extra move, which a flat average silently dropped): weightedMean = (lhs·lhsCount + rhs·rhsCount) / (lhsCount+rhsCount), applied independently to overall, every Phase, and every move-number bucket, each with its own paired sample counts.
    • Repertoire fit — examines min(mainLine.count, 20) plies (≈10 full moves each side), counting RepertoireBookKernel.isRepertoireMove hits per color. "The user's side" is whichever color has hits >= the other's (ties favor White); nil when both sides have 0 hits.
    let snapshot = await ReviewSnapshotBuilder.build(
    mainLine: game.mainLine, annotationEvals: EvalJSON.decode(game.evalsJSON),
    loadedTags: game.tags, whiteMoves: book.whiteMoves, blackMoves: book.blackMoves
)
if let mw = snapshot.missedWinMoment {
    print("missed win at move \(mw.movedAt): \(mw.asWhite ? "White" : "Black") had +\(Int(mw.evalCp))cp")
}

    BoardMarkDocument — the board-mark wire format¶

    Canonical, size-bounded JSON for user-drawn arrows/circles, shared by both platforms.

    currentVersion = 1                        maximumTotalMarks = 16_384
maximumEncodedBytes = 1_048_576 (1 MiB)   maximumPositionKeyBytes = 512
maximumPositions = 4_096                  maximumMarksPerPosition = 128

    decodeStrict(_:)'s validity gate: version == 1, byPosition.count <= 4_096; per position key, non-empty and <= 512 UTF-8 bytes with <= 128 marks, a running total <= 16_384 marks, and no duplicate (kind,from,to) id; every mark's fromIndex/toIndex in 0..<64, with kind == .arrow requiring fromIndex != toIndex and kind == .circle requiring fromIndex == toIndex. A missing kind on decode (legacy Apple documents) defaults to .arrow.

    The interesting design decision is what happens on failure: a document this build doesn't recognize (future version, or a failed bound) is not discarded or normalized to empty. decodePreserving(_:) keeps its exact original source bytes as an opaque payload, and encoded() returns those bytes back byte-for-byte — a recognized empty drawing still encodes to "" (the historical blank sentinel), but only an unrecognized document round-trips verbatim.

    var doc = BoardMarkDocument.decodePreserving(storedJSON)
if doc.isRecognized {
    doc.byPosition[position.positionKey, default: []]
        .append(BoardMark(fromIndex: e2, toIndex: e4, color: .green, kind: .arrow))
}
let roundTripped = doc.encoded()   // unrecognized storedJSON comes back byte-identical

    encoded() sorts keys and doesn't escape slashes ([.sortedKeys, .withoutEscapingSlashes]) so two builds of the same drawing are byte-identical — usable as digest input into PortableSHA256.

    Voice¶

    SpokenMoveParser — spoken utterance to legal move¶

    Two entry points are public — normalize(_:profile:) -> [String] and match(_:position:profile:) -> [VoiceMoveCandidate] — the normalization pipeline behind them is internal. match generates candidate strings, tries each against the position's legal moves, dedupes by resulting SAN: 0 candidates = no match, 1 = clear match, >1 = disambiguation. normalize runs the candidate through nine sequential stages, accumulating everything it produces (not stopping at the first plausible one):

    1 Whole-phrase rewrites   — lexicon.rawPhraseRewrites applied in order to raw lowercased text
2 Collapsed literal        — the phrase with all spaces removed, as-is
3 Piece-name prefix         — "knight c3": strip piece word, apply capture verbs (-> "x") + fillers inline
4 Castle phrases              — substring match; bare "castle"/"castles" emits BOTH "O-O" and "O-O-O"
5 Capture-verb split            — "e takes d5" -> split on verb into <piece><file>x<dest>
6 Filler-word removal             — " to " removed mid-phrase: "e2 to e4" -> "e2e4"
7 File/rank homophone substitution — fileHomophones then rankHomophones over the whole string
8 Promotion suffix                  — trailing "queen"/"rook"/"bishop"/"knight" -> "=Q"/"=R"/"=B"/"=N"
9 Confusable-letter variants          — file/piece swaps, only for 2–5 char SAN-length candidates

    let candidates = SpokenMoveParser.match("knight to f3", position: position, profile: .apple)
switch candidates.count {
case 0: showNoMatchToast()
case 1: apply(candidates[0].move)
default: presentDisambiguation(candidates)   // e.g. Nf3 vs Ngf3
}

    Lexicon & profiles. Every recognizer quirk is a data row, not a code branch: RecognizerProfile.lexicon = .core.merged(with: overlay). .apple's overlay is empty (on-device, well-trained on chess vocabulary); .google's is rawPhraseRewrites: [("before","b4"), ("84","e4")], pieceWords: [("brook","R")]. merged(with:) appends overlay rows after core's, so core stays higher-priority in ordered matching. Two orderings inside .core are load-bearing:

    fileHomophones: "gee " MUST precede "ee " — "gee" contains "ee"; rows apply
    sequentially, so "ee " first would turn "gee six" into "ge six"
rankHomophones: " fore" (leading space) MUST precede "for" — without the
    guard, "before" -> "be4" (a spurious b4 the PGN parser accepts); with
    it, " fore" isn't a substring of "before" at all, so "before" is left
    alone and the later "for" rule turns it into unparseable "be4e"

    VoiceAttemptOwnership — async recognition race safety¶

    A generic ownership/provenance state machine so only the newest in-flight recognition attempt can publish state or run cleanup, since platform recognizers shut down asynchronously and a stale one can call back after a newer attempt has started. VoiceAttemptOwnership<SessionID, PositionProof, Confirmation> tracks one activeAttempt: VoiceAttemptProvenance? through four private phases (recognizing → awaitingConfirmation → consumed, with invalidationRequested reachable from either of the first two on a session/position mismatch):

    registerConfirmation and consumeConfirmation traffic in VoiceAttemptResult<SessionID, PositionProof, Confirmation> — the matched payload welded permanently to the VoiceAttemptProvenance that produced it. It exists so a UI can hold and present a match without smuggling in a different attempt's context: consumeConfirmation compares the presented result's provenance against the owner's own stored result and, on a match, returns the owner's copy rather than trusting whatever payload the caller handed back.

    begin(token, sessionID, positionProof): accepted only if token.processSequence
    STRICTLY EXCEEDS every token this owner has ever accepted (monotonic); a
    newer attempt immediately makes the prior attempt's provenance stale.
acceptsCallback: true only if activeAttempt == provenance AND phase == .recognizing.
    A session/position mismatch marks the attempt invalidationRequested
    PERMANENTLY, so a later return to an equal FEN can't revive it.
registerConfirmation: first match wins — freezes phase to .awaitingConfirmation
    so a second matched result from the same attempt can't overwrite the first.
consumeConfirmation: compares the presented result's provenance against the
    OWNER-HELD pendingConfirmation (not the caller-supplied payload) and
    returns the owner's copy — compare-and-consume, exactly once.
clear(ifOwnedBy: p): compare-and-clear — only clears if activeAttempt == p, so
    stale cleanup from an old attempt can't clear a newer one's state.

    var ownership = VoiceAttemptOwnership<UUID, String, VoiceMoveCandidate>()
guard let provenance = ownership.begin(
    token: VoiceAttemptToken(processSequence: nextSequence()),
    sessionID: sessionID, positionProof: position.fen
) else { return }   // a newer attempt already started; this one is stale

recognizer.recognize(utterance) { candidate in
    guard ownership.acceptsCallback(for: provenance, currentSessionID: sessionID,
                                     currentPositionProof: position.fen) else { return }
    _ = ownership.registerConfirmation(candidate, for: provenance,
                                        currentSessionID: sessionID, currentPositionProof: position.fen)
}

    VoiceTranscriptLog — privacy-minimal tuning ring buffer¶

    BlobBackedStore (see the storage seam), blobKey = "voiceTranscriptLog", cap = 200 (oldest dropped on append(_:)). Each VoiceTranscriptEntry carries a timestamp, transcript, alternatives, FEN, a VoiceOutcome (.matched(san:) / .disambiguation(candidates:) / .noMatch), and the recognizer profile string.

    append(_:) itself doesn't filter by outcome — it just appends and trims. "Log only .noMatch/.disambiguation by default, treat .matched as opt-in" is a call-site convention documented on the type to keep the persisted log's privacy surface small, not something the ring buffer enforces. VoiceOutcome hand-writes its own Codable with a kind discriminator field instead of Swift's default enum-with-payload encoding, so the on-disk shape is stable and explicit. The tuning loop this exists for: speak on device → collect misses from the log → add one SpokenMoveLexicon overlay row + one corpus test case → rebuild — no engine code changes.

    Support¶

    PortableSHA256 — dependency-free SHA-256¶

    A from-scratch FIPS 180-4 SHA-256, because CryptoKit is unavailable on native Android and Swift's Hasher is intentionally process-randomized. 64 round constants (0x428a2f98 ... 0xc67178f2), the 8-word IV (0x6a09e667, 0xbb67ae85, 0x3c6ef372, 0xa54ff53a, 0x510e527f, 0x9b05688c, 0x1f83d9ab, 0x5be0cd19), 64-byte blocks, standard Merkle–Damgård padding (0x80 then zero-pad to 56 mod 64, then an 8-byte big-endian bit length), 32-byte digest. Hasher is incremental (update(_:)/update(byte:)/update(utf8:), finalize() -> [UInt8], hexDigest() -> String); hexDigest(utf8:) is the one-shot form.

    update(lengthPrefixedUTF8:) prepends an 8-byte big-endian byte count (of the UTF-8 encoding) before the string's own bytes — "the shared canonical framing used by authored causal and frontier proofs," per its doc comment — so a hash commits to a string's exact length rather than leaving where one field ends and the next begins ambiguous:

    var hasher = PortableSHA256.Hasher()
hasher.update(lengthPrefixedUTF8: fen)
hasher.update(lengthPrefixedUTF8: san)
let digest = hasher.hexDigest()

    RunGeneration — the epoch-counter idiom¶

    begin() -> UInt64 and invalidate() both do current &+= 1 (wrapping); owns(_ token:) -> Bool is current == token. begin() hands the new value back as a token to own; invalidate() discards it — no token satisfies owns(_:) again until begin() is called.

    var generation = RunGeneration()
func startAnalysis() {
    let token = generation.begin()
    Task {
        let result = try await engine.analyze(position)
        guard generation.owns(token) else { return }   // stale — a newer run started
        self.evaluation = result
    }
}

    The same "reject stale async work" shape as VoiceAttemptOwnership, stripped to a single counter for call sites that don't need provenance.

    DurationFormatting — the rounding fix¶

    drillDuration(seconds):
    totalTenths = Int((seconds * 10).rounded())          // ONE rounding, up front
    totalTenths < 600 (< 60s):  "\(totalTenths/10).\(totalTenths%10)s"      // "9.4s"
    else: totalSeconds = Int(seconds.rounded())           // rounded again, not truncated
          "\(totalSeconds/60)m \(zero-padded totalSeconds%60)s"             // "1m 05s"

    The bug this replaced: Apple used String(format: "%.1fs") (rounds); Android hand-rolled the idea (SkipFoundation doesn't reliably support String(format:)) but mixed a truncating Int(seconds) with a separately rounded tenths digit — at 9.97s that produced "9.0s", a whole second wrong, invisible except right at a rounding boundary. Rounding once, up front, in tenths, lets a value that carries into the next second or minute do so correctly. The shells also disagreed on padding above a minute ("3m 5s" vs "3m 05s"); the shared formatter always zero-pads.

    PieceSet — the piece-set picker¶

    10 cases: cburnett, merida, inkwell, crownline, scandi, minimal, leipzig, mpchess, staunty, maestro — the raw values are the literal @AppStorage keys both apps write ("pieceSet" on iOS, "pref.pieceSet" on Android) and must never change.

    assetName(for: piece):  cburnett      -> "{w|b}{K|Q|R|B|N|P}"          // "wK", "bP"
                         other 9 sets -> "{rawValue}_{w|b}{K|Q|R|B|N|P}" // "merida_wK"

    selectableCases is a curated 7-set picker subset, in owner-curated order — [.cburnett, .merida, .staunty, .maestro, .leipzig, .mpchess, .inkwell] — filtered against pendingPermission (currently empty, so a no-op filter as of the 2026-07-20 sadsnake1 grant). Crownline, Scandi, and Minimal stay fully wired (assets, export switch, persisted selections) but are hidden to keep the list short; pickerCases(including:) adds a current selection back in even when it isn't in selectableCases, so an existing choice never renders as empty.

    SharedUtilities — the grab-bag¶

    Small pure helpers deduplicated out of code reimplemented identically in several places.

    Type / extension Purpose
    PercentFormat.whole(_:) Double (0...1) → "73%", "—" for non-finite
    Array.capLast(_:) trims to the most recent max elements
    Position.fenStartsWithWhite(_:) parses FEN side-to-move; defaults true on malformed input
    EvalJSON codec for the eval-array JSON blob (below)

    DrillLeniency.leniencyAccept(bestCp,bestIsMate,playedCp,playedIsMate,marginCp):
  if bestIsMate:
      guard bestCp > 0 else return false          // best move that's mate AGAINST mover shouldn't occur
      return playedIsMate ? (playedCp > 0) : (playedCp >= 500)
  else:
      if playedIsMate:  return playedCp > 0        // upgraded to / kept a real mate
      if bestCp >= 500: return playedCp >= 200      // best already decisive -> any clear win
      else:              return playedCp >= bestCp - marginCp   // within margin (typically 50-150cp)

    A played move that hands the opponent a mate (playedIsMate && playedCp < 0) is correctly rejected by the playedCp > 0 check — an earlier kernel version accepted any playedIsMate, mis-grading a blunder-into-mate as a solve.
