    Network Clients & Game Import¶

    The three REST clients FianchettoKit owns — Chess.com / Lichess game import, the Lichess opening explorer, and the Lichess Syzygy tablebase — over one shared URLSession shim. Most of the code here is not transport: it is the decision rules that stop an interrupted import from losing games and an incremental re-fetch from advancing a cursor past archives it never read.

    Networking follows Fianchetto's higher deployment floor (iOS 18 / macOS 15) while ChessCore keeps a generous community floor (iOS 13 / macOS 10.15), so the clients live here, on top of ChessCore's PGNGame / PGNParser / Position.

    File What it holds
    ChessAPIService.swift Chess.com sweep, Lichess export + resumable history walk, ImportFilters, ChessAPIError, GameUpdatePlanner
    LichessGameStreamDecoder.swift NDJSON framer, both pagination accumulators, LichessGamePaginationError
    LichessHistoryImportCheckpoint.swift LichessHistoryImportIdentity, LichessHistoryImportCheckpoint
    LichessExplorer.swift explorer actor, ExplorerResult / ExplorerMove / ExplorerDatabase
    TablebaseService.swift Syzygy actor, TablebaseResult / TablebaseMove
    URLSession+DataResult.swift the cancellation-correct dataResult shim

    ChessPlatform (.chesscom = "Chess.com", .lichess = "Lichess") is the display vocabulary. It is not what GameUpdatePlanner.fetch reads: that compares a collection's stored source against the lowercase literal "lichess" and treats everything else as Chess.com.

    Concurrency and isolation¶

    public nonisolated final class ChessAPIService: Sendable { … }
public nonisolated enum ChessAPIError: LocalizedError { … }
public nonisolated enum GameUpdatePlanner { … }

    The fetch methods are @concurrent, not merely nonisolated: under the project's NonisolatedNonsendingByDefault setting a plain nonisolated async method runs on the caller's actor, so a sweep started from a MainActor view would parse every month's PGN on the main thread. The class is Sendable (final, holding only two immutable URLSessions) so a view can hold one and hand it to off-main work, and ChessAPIError is nonisolated because its cases and LocalizedError witness are thrown from those pool-resident methods. Progress callbacks are typed (@MainActor @Sendable (Int, Int) -> Void)? and fire once per progress tick — one archive month — so @State writes stay correct without flooding main.

    Transport: URLSession.dataResult¶

    dataResult(for:) / dataResult(from:) back-deploy URLSession.data(for:) to iOS 13 / macOS 10.15 and are used by all three clients. They exist because the async data(for:) / bytes(for:) are iOS 15 / macOS 12 only and swift-corelibs-foundation has no async bytes(for:) at all — only the completion-handler dataTask is available everywhere.

    Cancellation can race all three phases: before the task exists, after it starts, after its completion handler fires. One NSLock-guarded box holds the task and the continuation and gives the continuation exactly one terminal path.

    dataResult(for:) =
  withTaskCancellationHandler {
      try Task.checkCancellation()
      withCheckedThrowingContinuation { c in
          let task = dataTask(with: request) { d, r, e in state.complete(data: d, response: r, error: e) }
          state.start(task: task, continuation: c)
      }
  } onCancel: { state.cancel() }

start(task:continuation:)
  isCancelled already -> isCompleted = true; task.cancel(); resume(throwing: CancellationError())
                         // cancel()-before-resume() is NOT guaranteed to fire every
                         // Foundation implementation's completion handler
  otherwise           -> store task + continuation; task.resume()

cancel()
  isCancelled = true
  isCompleted || continuation == nil -> no-op
  otherwise -> isCompleted = true; nil both fields; task.cancel(); resume(throwing: CancellationError())

complete(data:response:error:)
  isCompleted        -> no-op                       // the ignored late callback
  error != nil       -> resume(throwing: error)
  data && response   -> resume(returning: (data, response))
  otherwise          -> resume(throwing: URLError(.badServerResponse))

    Session budgets¶

    Every request sends User-Agent: Fianchetto-ChessApp/1.0.

    Session Request Resource Sized for
    ChessAPIService.session 30 s 180 s one Chess.com archive month per request
    ChessAPIService.streamSession 60 s 7_200 s one long Lichess account export; the 60 s idle covers server-side pauses between games
    LichessExplorer.session 10 s — one position lookup
    TablebaseService.session 10 s — one FEN probe

    Without timeoutIntervalForResource, URLSession enforces only the per-segment idle timer and a perfectly slow stream stays open forever — but 180 s, right for month-shaped archives, guarantees failure for a whole-account export. Hence two sessions.

    Import filters¶

    ImportTimeControl raw values (bullet, blitz, rapid, classical) match Lichess perfType exactly so they can be sent verbatim; chessComTimeClass maps .classical to "standard", which is what Chess.com writes in its TimeClass PGN tag. ImportColor.any means "no restriction" everywhere. All ImportFilters fields default to nil, so existing callers are unaffected.

    isActive = ratedOnly != nil
        || timeControls?.isEmpty == false
        || (color != nil && color != .any)
        || since != nil
    Filter Lichess (server-side) Chess.com (client-side)
    ratedOnly rated=true / rated=false !game.event.contains("(Unrated)")
    timeControls perfType= raw values .sorted().joined(separator: ",") TimeClass tag vs chessComTimeClass
    color color=white / color=black, omitted for .any lowercased username vs White / Black
    since since= ms, merged with the incremental cursor Date tag parsed as "YYYY.MM.DD", keep gameDate >= since

    Chess.com has no server-side filter API; the client-side predicate runs only when filters.isActive, so an inactive bundle costs nothing.

    Chess.com: the archive sweep¶

    Archives are partitioned by UTC calendar month, and the month filter never uses Calendar.current:

    chessComArchiveURLs(archives, notBefore: since)
  since == nil -> keep everything
  calendar = Calendar(identifier: .gregorian), timeZone = GMT+0
  (sinceYear, sinceMonth) = components of `since`
  per URL: split on "/", read the last two path components as year, month
      fewer than 2 components, or non-integer year/month  -> KEEP (return true)
      keep when  year > sinceYear || (year == sinceYear && month >= sinceMonth)

    A device-local calendar would let a positive-UTC-offset device already be in the next local month shortly before a transition and skip the still-current UTC archive permanently. Malformed entries are kept on purpose, so the validated fetch loop reports them as a partial failure instead of treating an incomplete archive list as a clean sweep.

    The sweep then walks filtered.reversed() — newest month first — reporting (index + 1, total) once per month.

    Stage Condition Outcome
    archives index 404 / 429 / other non-2xx invalidUsername / rateLimited / networkError("HTTP <code>")
    archives index no top-level archives array of strings noGamesFound
    per archive scheme != https or host != api.chess.com added to failedArchives, never fetched
    per archive 429 rateLimited — aborts the whole sweep
    per archive non-2xx, non-HTTPURLResponse, empty or non-UTF-8 body added to failedArchives
    per archive CancellationError rethrown immediately — control flow, not a failed month
    per archive a typed ChessAPIError rethrown verbatim, so an auth problem is not coerced into a rate-limit toast
    per archive anything else added to failedArchives, sweep continues

    Each server-supplied archive URL is re-validated before "/pgn" is appended, so a compromised index cannot redirect fetches elsewhere. PGNParser is deliberately permissive for hand-authored imports, so archives get a stricter boundary before they count as a successful month:

    isStructurallyValidChessComArchive(games)
  games non-empty, and EVERY game has
      White  trimmed and non-empty
      Black  trimmed and non-empty
      Result trimmed and in ["1-0", "0-1", "1/2-1/2", "*"]

    Move-less and aborted games stay valid; what this rejects is an HTML error page or truncated body being parsed into a zero-or-garbage-game month.

    Finally guard !finalGames.isEmpty || !failedArchives.isEmpty else { throw .noGamesFound }: a sweep where every listed archive failed is partial, not "no games". That distinction is what stops GameUpdatePlanner — which normalizes noGamesFound into a clean empty result whenever a watermark is present — from advancing the watermark past months it never read.

    import ChessCore
import FianchettoKit

let api = ChessAPIService()

let sweep = try await api.fetchChessComGames(
    username: "MagnusCarlsen",
    since: lastSyncDate,
    filters: ImportFilters(
        ratedOnly: true,
        timeControls: [.blitz, .rapid],
        color: .white
    )
) { completed, total in
    // @MainActor — one tick per archive month, safe to write @State directly.
    importProgress = Double(completed) / Double(total)
}

if sweep.isPartial {
    // Do NOT stamp lastSyncDate, or these months are skipped forever.
    print("failed archives:", sweep.failedArchives)
}

    sweep.games are ordinary ChessCore PGNGame values, so they feed the analysis path directly. Available from the command line: fianchetto-cli annotate (per-ply evals) and fianchetto-cli estimate (rating estimate from them).

    Lichess: one base request, three shapes¶

    lichessBaseRequest(username:since:filters:) is the single source of account normalization and every filter; the one-shot snapshot and the resumable page producer both start there, so their query shapes cannot drift.

    https://lichess.org/api/games/user/<username>
  username: trimmed, lowercased, percent-encoded with (.urlPathAllowed minus "/")
            — empty -> ChessAPIError.invalidUsername
            — the stock set treats "/" as legal, which would let a username
              cross path-segment boundaries
  always:   opening=true, pgnInJson=true
  since:    max(since, filters.since) as Int64 milliseconds, when either exists
  filters:  rated, perfType, color as in the table above
    Shape Removes Appends
    ongoing probe since, until, max, sort, rated, perfType, color, opening, pgnInJson, ongoing, finished pgnInJson=true, ongoing=true, finished=false
    newest-first page until, max, sort, finished, ongoing until=<ms>, max=<pageSize>, sort=dateDesc, finished=true
    oldest-first page (Android / Linux) since, until, max, sort until=<snapshot>, max=1_000, sort=dateAsc, since=<cursor>

    The probe strips everything, including the incremental cursor. That is not tidiness: Lichess's since filter keys on game creation time, so a game that began before the existing cursor is invisible even with ongoing=true. A probe inheriting the cursor would report "no ongoing games" and let the watermark jump over a game still in progress.

    Response Result
    not an HTTPURLResponse networkError("Invalid HTTP response")
    401 / 404 / 429 unauthorized / invalidUsername / rateLimited
    other non-2xx networkError("HTTP <code>")

    Requests send Accept: application/x-ndjson, and Authorization: Bearer <token> only when a non-empty token is supplied — a token buys throughput, and the anonymous endpoint stays supported. The server clock is parsed from the HTTP Date header with an en_US_POSIX / GMT DateFormatter on "EEE',' dd MMM yyyy HH':'mm':'ss 'GMT'"; missing or unparseable yields nil, which deliberately disables watermark advance downstream.

    Platform split. Apple platforms stream streamSession.bytes(for:) through the byte decoder. On os(Android) || os(Linux) the snapshot uses the finite, overlapping completion-handler page walk instead: SkipFoundation's AsyncBytes adapter converts an InputStream read error into ordinary end-of-stream (a truncated export would look successful and could advance the watermark), and swift-corelibs-foundation's URLSession has no async bytes(for:). Both are fail-closed choices.

    The NDJSON decoder¶

    LichessGameStreamDecoder frames the export byte-at-a-time and releases a record as soon as its newline arrives, so a large account never exists as a full response Data plus a full response String.

    consume(byte)
  byte == 0x0A (\n)                    -> decode the buffered line
  line.count >= maximumLineByteCount   -> throw lineTooLarge(limit:)
                                          // default 8 * 1_024 * 1_024 = 8 MiB
  otherwise                            -> append, return nil
finish()                               -> drain a final line when the server
                                          closes without a trailing newline

decodeBufferedLine()
  strip a trailing 0x0D, ignore an empty line
  decode Envelope { id, createdAt, status, pgn? }; empty id -> invalidEnvelope
  status.lowercased() not in finalStatuses -> ONGOING record (finishedGame == nil)
  pgn == nil                               -> invalidPGN
  PGNParser.parse(pgn) must yield exactly ONE game with non-empty
      White, Black and Result                         -> else invalidPGN

    The 12 documented terminal GameStatusName values are aborted, mate, resign, stalemate, timeout, draw, outoftime, cheat, nostart, unknownfinish, insufficientmaterialclaim, variantend. Anything else counts as ongoing: persisting a future in-progress state is worse than retrying it next sync, and an ongoing PGN is a moving snapshot that must never be stored as final. Both byte loops set bytesUntilCancellationCheck = 4_096, decrement per byte, and call Task.checkCancellation() at zero; the AsyncBytes loop adds one more check after the loop, before finish().

    finishedLichessGames(in:)    = records where finishedGame != nil, first id wins
earliestOngoingGameDate(in:) = min over isOngoing records of
                               Date(timeIntervalSince1970: createdAtMilliseconds / 1_000)

    Resumable history walks¶

    fetchLichessHistoryPages walks one fixed newest-first snapshot in bounded pages. There is no total game cap: a full page yields a strictly older continuation and iteration ends only on a short page.

    onPage is the durability handshake. Returning from it acknowledges the games and the cursor, and the producer never issues the next (older) request before that return; a throw or a cancellation stops the walk first. Cancellation is checked before the request, after the response, and after onPage.

    fresh walk
  require (1...maximumLichessHistoryPageSize).contains(pageSize)      // 1...5_000
                                     else invalidPageSize(maximum: 5_000)
  probe once for serverDate + earliestOngoingGameDate
  snapshotUntilMilliseconds = Int64((serverDate ?? Date()).timeIntervalSince1970 * 1_000
                                    rounded down),  must be > 0 else invalidResumeCursor
  nextUntil = snapshot;  previousPageIDs = []

resumed walk
  cursor.hasValidIntegrityAndShape            else invalidResumeCursor
  cursor.matches(requestSignature:pageSize:)  else resumeCursorRequestMismatch
  snapshot / serverDate / earliestOngoingGameDate come FROM THE CURSOR, so a
  resumed walk cannot replace fixed metadata with a later view of a game that
  was ongoing when the snapshot was taken

    LichessHistoryPageCursor
  public       schemaVersion, snapshotUntilMilliseconds, nextUntilMilliseconds,
               serverDate, earliestOngoingGameDate, overlapGameIDs, integritySHA256
  fileprivate  requestSignature, pageSize

hasValidIntegrityAndShape
  schemaVersion == 1;  integritySHA256 recomputes identically
  snapshotUntilMilliseconds > 0;  nextUntilMilliseconds > 0
  nextUntilMilliseconds < snapshotUntilMilliseconds
  overlapGameIDs non-empty, count <= pageSize, no duplicates, no empty-string ID

requestSignature = PortableSHA256 over length-prefixed UTF-8:
  "fianchetto.lichess-history-request-signature.v1", normalizedUsername,
  String(pageSize), query-item count, then each (name, value) with nil -> "",
  pairs SORTED by name then value      // independent of emission order

integritySHA256 = PortableSHA256 over length-prefixed UTF-8:
  "fianchetto.lichess-history-page-cursor.integrity.v1", schemaVersion,
  snapshotUntilMilliseconds, nextUntilMilliseconds, dateField(serverDate),
  dateField(earliestOngoingGameDate), requestSignature, pageSize,
  overlapGameIDs.count, then EACH overlap ID in order   // membership AND order

dateField(nil)  = "none"
dateField(date) = "some:" + String(date.timeIntervalSinceReferenceDate.bitPattern, radix: 16)
                  // exact IEEE-754 bits: Codable round-trips losslessly,
                  // sub-millisecond mutation is still detected

    Integrity, not authenticity

    integritySHA256 uses no secret key. It detects accidental or partial mutation of a persisted cursor; it does not prove where that cursor came from. isValid(for:) pairs it with a LichessHistoryImportIdentity: rebuild the base request from the identity, recompute the signature, and require both the shape invariants and a signature + page-size match. The API token is deliberately outside request identity — authentication changes throughput, not which public games match.

    Pagination accumulators, side by side¶

    Both refuse partial results, de-duplicate by stable game ID, and overlap the next boundary by exactly one millisecond — correct whether Lichess reads the bound inclusively or exclusively, and free because stable IDs strip the overlap.

    LichessNewestFirstPageAccumulator (sort=dateDesc — the public history walk)
  page.count > pageSize          -> pageTooLarge(limit: pageSize)
  duplicate IDs within the page collapse
  IDs in previousPageIDs are dropped from novelRecords but still join nextOverlapIDs
  short page (count != pageSize) -> nextUntilMilliseconds = nil, overlap = []  (terminal)
  full page:  pageMinimum = min createdAtMilliseconds, must be < Int64.max
              nextUntil = pageMinimum + 1
              require nextUntil < currentUntilMilliseconds  else cursorDidNotAdvance

LichessGamePageAccumulator (sort=dateAsc — the Android / Linux walk)
  page.count > pageSize          -> pageTooLarge(limit: pageSize)
  de-dupes by ID across ALL pages
  short page                     -> .finished
  full page:  pageMaximum = max createdAtMilliseconds
              require pageMaximum > previousMaximumCreatedAt else cursorDidNotAdvance
              nextSince = pageMaximum == Int64.min ? Int64.min : pageMaximum - 1

    cursorDidNotAdvance guards two failures at once: an infinite loop, and a timestamp cluster larger than the server's page limit, where advancing would silently skip games. The newest-first accumulator needs only the immediately preceding page's IDs, because the strictly descending cursor prevents an older page from reappearing — that bound is what makes the public walk resumable without retaining every seen ID in memory or in the crash journal.

    Checkpoints and identity¶

    LichessHistoryImportIdentity(username:since:filters:pageSize:) is failable: it returns nil on an empty normalized username, a pageSize outside 1...5_000, or a non-finite / out-of-Int64 since. It normalizes username (trimmed, lowercased), since to Int64 milliseconds via .rounded(.towardZero), timeControlRawValues sorted, and .any color to nil. isValid re-checks all of that on a decoded value plus that every raw value is a real ImportTimeControl / non-any ImportColor; filters reconstructs an ImportFilters and returns nil when the reconstruction is not isActive. storageToken is a length-prefixed PortableSHA256 digest over "fianchetto.lichess-history-import-identity.v1", schema version, username, ratedOnly ?? "any", colorRawValue ?? "any", sinceMilliseconds ?? "all-time", page size, time-control count, then each time-control value — an identity digest for blob keys, explicitly not a secret.

    LichessHistoryImportCheckpoint.isValid(for: expectedIdentity)
  schemaVersion == 1
  identity.isValid && identity == expectedIdentity
  cursor.isValid(for: identity)
  acknowledgedPageCount > 0
  acknowledgedGameCount >= 0
  insertedGameCount >= 0 && insertedGameCount <= acknowledgedGameCount

    Write order is games first, then the cursor. Crashing between those writes replays one acknowledged page, which is harmless because collection persistence de-duplicates on stable IDs. Decoders stay lenient, so a future schema version is discarded and restarted rather than made fatal.

    // A resumable full-history import. `onPage` is @Sendable, so mutable
// bookkeeping belongs behind your own actor rather than captured vars.
guard let identity = LichessHistoryImportIdentity(
    username: "DrNykterstein",
    filters: ImportFilters(ratedOnly: true),
    pageSize: 5_000
) else { return }

let journal = ImportJournal(identity: identity)        // your actor
let saved = await journal.loadCheckpoint()
let resumeCursor = (saved?.isValid(for: identity) == true) ? saved?.cursor : nil

let completion = try await api.fetchLichessHistoryPages(
    username: "DrNykterstein",
    token: lichessToken,
    filters: identity.filters,
    pageSize: identity.pageSize,
    resumingFrom: resumeCursor
) { page in
    // Games durable FIRST, then the cursor. Returning is the acknowledgement:
    // no older request starts until this closure returns.
    try await journal.persist(page.games, then: page.resumeCursor)
}

print(completion.acknowledgedPageCount, completion.acknowledgedGameCount)
let watermark = completion.safeSyncWatermark()

    resumeCursorRequestMismatch means the saved cursor belongs to a different account or filter request; invalidResumeCursor means it failed integrity or shape validation. Both are recoverable by discarding it and starting fresh.

    Sync watermarks¶

    lichessSafeSyncWatermark(fetchStartedAt:serverDate:earliestOngoingGameDate:)
  serverDate == nil                    -> nil        // no trustworthy boundary
  candidate = min(fetchStartedAt, serverDate) - 61 s
      // 60 s: Lichess deliberately delays ongoing exports by up to a minute
      //  1 s: overlap for a just-started game the probe cannot see
  earliestOngoingGameDate <= candidate -> earliestOngoingGameDate - 1 s   // rewind
  otherwise                            -> candidate

    Capping at min(local, server) stops a fast local clock from skipping games created after the response snapshot. LichessFetchResult.safeSyncWatermark(fetchStartedAt:) applies this to a one-shot snapshot; LichessHistoryCompletion.safeSyncWatermark() reconstructs fetchStartedAt as Date(timeIntervalSince1970: Double(snapshotUntilMilliseconds) / 1_000) — the original snapshot boundary, not the much later moment a long or resumed walk happened to finish.

    GameUpdatePlanner¶

    The cross-platform "Update Games" policy — the semantics that must not drift between the iOS and Android update actions. Persistence writes, progress UI, and token storage stay per-app.

    sinceDate(fullSweep:lastSyncDate:)
    fullSweep -> nil (re-walk everything, rely on dedup);  else lastSyncDate

syncStamp(isPartial:now:)
    isPartial -> nil                     // a partial fetch must never stamp
    else      -> Date(timeIntervalSince1970: now.timeIntervalSince1970.rounded(.down))
        // HTTP `Date` is second-granular; a fractional client time from the same
        // second would compare LATER than the authoritative response boundary
        // even with perfectly synchronized clocks

syncStamp(for:source:requestStartedAt:)
    source == "lichess" -> result.exactSyncWatermark
    else                -> syncStamp(isPartial: result.isPartial, now: requestStartedAt)

    fetch(api:source:username:since:lichessToken:onProgress:) dispatches on the literal "lichess". Lichess captures fetchStartedAt, takes a snapshot, and returns mustRetainSyncWatermark = (safeSyncDate == nil) with exactSyncWatermark = safeSyncDate and failedArchiveCount = 0 (a single stream has no month archives). Chess.com forwards onProgress and reports failedArchives.count. In both branches a caught ChessAPIError.noGamesFound is normalized into an empty UpdateFetchResult when since != nil — an up-to-date collection is not an error — and rethrown otherwise.

    newGames(in:existing:checking:)
    seen = existing            // a MUTABLE COPY, so the pass also de-dupes
                               // WITHIN the fetched batch
    per fetched game, in order:
        run the injected cancellation check
        seen.registerIfNew(
            gameID: GameIdentity.remoteID(link: tags["Link"], site: tags["Site"]),
            compositeKey: GameDedup.compositeKey(white:black:date:result:event:
                                                 opening:moveText:tagsJSON:)  // @autoclosure
        )

    An explicit Link wins; Site is accepted only when it is a recognized Chess.com / Lichess game location, and a generic PGN venue falls through to content identity. The autoclosure means an ID-bearing online game never pays for token-text export or fingerprinting. newGamesCheckingCancellation(in:existing:) injects Task<Never, Never>.checkCancellation() so a retired UI task stops hashing thousands of games off-screen.

    imported failed months resultMessage(imported:failedMonths:)
    0 0 "No new games found."
    0 > 0 "No new games found. <n> month(s) failed to download — retry later."
    > 0 > 0 "Imported <n>; <m> month(s) failed — retry later."
    > 0 0 nil — plain success; the visible count change is the only feedback needed 
    let requestStartedAt = Date()
let result = try await GameUpdatePlanner.fetch(
    api: api,
    source: collection.source,          // "chesscom" / "chess.com" / "lichess"
    username: collection.username,
    since: GameUpdatePlanner.sinceDate(fullSweep: false,
                                       lastSyncDate: collection.lastSyncDate),
    lichessToken: lichessToken,
    onProgress: { done, total in importProgress = Double(done) / Double(total) }
)

var existing = GameDedup.KeySet()
for stored in storedGames { existing.registerIfNew(stored) }
let fresh = try GameUpdatePlanner.newGamesCheckingCancellation(
    in: result.games, existing: existing
)
try await persist(fresh)

// Only a clean sweep with a trustworthy boundary advances the cursor.
if !result.mustRetainSyncWatermark,
   let stamp = GameUpdatePlanner.syncStamp(for: result,
                                           source: collection.source,
                                           requestStartedAt: requestStartedAt) {
    collection.lastSyncDate = stamp
}
banner = GameUpdatePlanner.resultMessage(imported: fresh.count,
                                         failedMonths: result.failedArchiveCount)

    Newly imported games are what the rating pipeline consumes. Available from the command line: fianchetto-cli estimate (per-game rating estimate), fianchetto-cli track (Kalman strength tracking), and fianchetto-cli project (the Elo-points projection).

    Lichess opening explorer¶

    An actor over explorer.lichess.org with a bounded in-memory cache.

    normalizedRatings(_:)
    intersect with [1000, 1200, 1400, 1600, 1800, 2000, 2200, 2500], sort ascending
    empty intersection -> [1600, 1800, 2000, 2200, 2500]

normalizedSpeeds(_:)
    trim + lowercase the request, then FILTER the canonical list
        ["bullet", "blitz", "rapid", "classical", "correspondence"] by membership
        // output order is canonical, never request order
    nothing matches -> ["blitz", "rapid", "classical"]

cacheKey(fen:database:ratings:speeds:)
    .masters -> "<rawValue>:<fen>"                    // ratings/speeds are not sent
    .lichess -> "<rawValue>:<fen>:r=<ratings,>:s=<speeds,>"
    always over NORMALIZED values, so equivalent requests share one entry

insert only when white + draws + black > 0
evict when cacheOrder.count >= 200: drop cacheOrder[0] from both the dictionary
    and the order array, then append the new key       // oldest-first FIFO

    ratings and speeds are sent only for .lichess; a Bearer token is optional. 401 is .unauthorized, 429 is .rateLimited, other non-2xx is .networkError("HTTP <code>").

    Malformed JSON is an error, not an empty result

    A non-dictionary body throws .networkError("Malformed response from Lichess explorer"). The earlier empty-result form rendered as "no data for this position", masking edge and proxy errors — and, because the empty was cached, poisoning that position for the rest of the session.

    let result = try await LichessExplorer.shared.explore(
    fen: position.fen,
    database: .lichess,
    ratings: [1600, 1800, 2000, 2200, 2500],
    speeds: ["blitz", "rapid", "classical"],
    token: nil
)
for move in result.moves.prefix(5) {
    print(move.san, move.totalGames, move.averageRating ?? 0)
}

    ExplorerDatabase.endpoint returns the same two URLs, but explore re-derives them with its own inline switch — the property is a parallel copy, not the call path.

    Syzygy tablebase¶

    An actor over https://tablebase.lichess.ovh/standard with an unbounded per-FEN memo (unlike the explorer's 200-entry FIFO). TablebaseService.pieceCount(for:) — position.board.compactMap { $0 }.count — is the eligibility gate callers apply before probing at all. TablebaseResult.Category raw values are win, loss, draw, cursed-win, blessed-loss, unknown, and isDecisive is everything except .draw and .unknown.

    Lichess reports each move's category from the perspective of the side to move after the move, so TablebaseMove.userVerdict inverts it:

    API category userVerdict displayText
    loss, blessed-loss .keepsWin "Win"
    draw .draws "Draw"
    win, cursed-win .losesWin "Loss"
    unknown .unknown "Unknown"

    Never filter on the raw category

    Filtering moves for raw .win selects suicide moves. That inversion made the endgame trainer flag every winning K+Q-vs-K probe as drawn, burning all three regeneration attempts before surfacing "Tablebase unavailable". Route every consumer through userVerdict rather than repeating the mapping inline.

    if TablebaseService.pieceCount(for: position) <= 7 {
    let result = try await TablebaseService.shared.probe(fen: position.stockfishSafeFEN)
    if result.category.isDecisive {
        let keeps = result.moves.filter { $0.userVerdict == .keepsWin }
        print(result.category.displayText, result.bestMove ?? "—", keeps.count, "winning moves")
    }
}

    429 is .rateLimited, other non-2xx is .networkError("HTTP <code>"), a non-dictionary body is .networkError("Could not parse tablebase response"), and a URLError is rethrown unchanged. No branch logs the FEN publicly: FENs identify positions and can leak ongoing tournament games through device log exports.
