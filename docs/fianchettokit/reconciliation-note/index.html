    Reconciliation note¶

    The FianchettoKit documentation is currently authored across two branches: the library concept pages on one, the fianchetto-cli pages on the other. This note records where each page set lives, the link rule that was followed while they were apart, and exactly what has to happen when they reconcile.

    Where each page set lives¶

    Page set Branch Source it was written from
    Library concept pages, home, installation, getting started, examples docs/fianchettokit-reference The cmp-desktop-port reference tree — 180 Swift files under FianchettoKit/Sources, foldered into Authored/, Boards/, Engine/, Library/, Library/Backup/, Network/, Play/, Repertoire/, Review/, Stats/, Storage/, Support/, Train/, Train/Combinations/, Train/Endgames/, Train/Tactics/, Train/Traps/, Voice/
    cli/ pages — the six shipped subcommands, plus the expansion proposal fianchetto-cli The CLI package under Tools/fianchetto-cli, and the kit as it exists on that branch

    Each page set was written from source readable on its own branch. Nothing on either was inferred from the other.

    The cross-branch link rule that was followed¶

    A page never links to a page that exists only on the other branch. It names it in prose instead.

    A Markdown link to a file that is not in docs_dir produces a broken link in the built site and a nav entry that resolves to nothing, so a link written in anticipation of a merge is a defect until the merge lands. Naming the target in prose costs the reader one search and costs the build nothing.

    Applied in both directions:

    • The reference-branch pages mention fianchetto-cli and its subcommands eighteen times in prose, and link to a cli/ page zero times.
    • CLI expansion names the reference-branch concept pages in prose and links to none of them, and closes with a note saying why.

    The rule has one consequence worth stating: the absence of a link is not a judgement about relevance. Every prose mention listed below is a link that was deliberately withheld, not a connection nobody noticed.

    Merge task 1 — add the CLI nav section¶

    The reference branch's mkdocs.yml has no Command-Line Interface section, because no cli/ page exists there. The merged config needs one appended after Usage Examples:

      - Command-Line Interface:
      - cli/index.md
      - annotate: cli/annotate.md
      - estimate: cli/estimate.md
      - maia: cli/maia.md
      - accuracy: cli/accuracy.md
      - project: cli/project.md
      - track: cli/track.md
      - Expansion (proposed): cli/expansion.md

    Two details that are easy to lose:

    • cli/index.md is listed bare rather than with a title. That is deliberate — the site enables navigation.indexes, so a bare index path makes the section header itself the link to the overview page.
    • cli/expansion.md is not in the CLI branch's nav today. It is reachable only by direct URL. Adding it is part of this task, not a separate one.

    Everything else in the two mkdocs.yml files is identical in intent — same theme, same palette, same feature list, same markdown extensions. Take the reference branch's site_description, which does not yet mention the CLI, and extend it.

    One mention is not merely unlinked, it is wrong

    concepts/network-clients.md:197 reads "This capability is exposed headlessly by the fianchetto-cli import-related subcommands". There are no import subcommands. The CLI ships exactly six — annotate, estimate, maia, accuracy, project, track — and import is a proposal on the expansion page. Rewrite the sentence to say the capability is proposed rather than exposed, then link it to cli/expansion.md. Do not simply add a link: that would make a false statement look sourced.

    Re-pathing the superseded concept set¶

    The larger job, and the one that breaks the build if skipped. The CLI branch's seven other cli/ pages each close with a "Related" section linking into that branch's own concepts/ directory. Those filenames differ from the reference-branch set, so every one of those links dangles once the reference pages become canonical.

    Link in a cli/ page Appears in Retarget to
    ../concepts/strength-and-elo.md cli/index.md, cli/estimate.md (×2), cli/accuracy.md, cli/project.md, cli/track.md ../concepts/elo-estimation.md
    ../concepts/engine-annotation.md cli/index.md, cli/annotate.md ../concepts/engine.md
    ../concepts/maia.md cli/index.md, cli/maia.md ../concepts/engine.md — the reference branch folds Maia into "Engine, Annotation & Maia"
    ../concepts/analysis.md cli/index.md, cli/accuracy.md ../concepts/analysis.md — unchanged, the only one that survives as-is

    One link carries an anchor: cli/estimate.md:133 points at ../concepts/strength-and-elo.md#time-control-routing. The reference page's equivalent section is ## Two time-control classifiers, so the retarget is ../concepts/elo-estimation.md#two-time-control-classifiers. Anchors are generated from heading text, so this one has to be read off the merged page rather than guessed.

    Note

    Decide the direction before doing any of this. These tables assume the reference-branch concept set wins and the CLI branch's older concepts/ directory is deleted. That is the right call — the reference pages were written against the larger tree and cover subsystems the older set has no page for — but it is a decision, and half-merging the two sets produces two pages describing the same type with different constants.

    Merge-day checklist¶

    1. Choose the concept set. The reference-branch pages win; delete the CLI
   branch's concepts/ directory rather than merging it page by page.
2. Copy the cli/ directory onto the reference branch unchanged.
3. Append the Command-Line Interface nav section to mkdocs.yml, including
   cli/expansion.md, and extend site_description to mention the CLI.
4. Retarget the four ../concepts/ link paths in the seven older cli/ pages,
   including the one anchor.
5. Correct concepts/network-clients.md:197 — the import subcommands are
   proposed, not shipped — then link it to cli/expansion.md.
6. Link the other seventeen prose CLI mentions in the concept pages.
7. Link the prose concept mentions in cli/expansion.md and delete its
   closing cross-branch admonition.
8. Build with strict link checking. Every item above is a dangling link if
   it is missed, so the build is the acceptance test.
9. Delete this note, or reduce it to a dated changelog entry.

    Step 8 is the one that makes the rest safe. Every task on this page is either adding a link or repointing one, so a build that fails on unresolved links catches anything skipped — which is the reason the link rule was worth following while the branches were apart.
