    annotate¶

    Per-ply White-POV centipawn evals for arbitrary games, produced by driving a live UCI Stockfish session through the app's own annotation sweep. This is the command that turns games into the white_pov_evals array every other command consumes.

    stdin¶

    One JSON object per line.

    Field Type Required Default Meaning
    id String yes — echoed on the response line; the only unconditionally required field
    uci_moves [String] one of the two — moves from the standard start position, resolved strictly through UCIParser.uciToMove
    pgn String one of the two — a PGN game; headers optional
    movetime_ms Int no the thoroughness policy below engine movetime per position
    thoroughness String no "default" behavior "fast" / "default" / "thorough" — the app's annotation-thoroughness scale

    If both uci_moves and pgn are present, uci_moves wins. A game with zero main-line moves is an error, not an empty result.

    Movetime, when movetime_ms is absent, comes from AnnotationKernel.annotateMovetime(batch: true, thoroughness:) — integer arithmetic on the batch base:

    base = 500 ms                     (batch; the single-game base of 1000 is not used here)
"fast"      -> base * 6 / 10   =  300 ms
"thorough"  -> base * 16 / 10  =  800 ms
"default", null, anything else -> 500 ms

    stdout¶

    One JSON object per line, in input order.

    Field Type Meaning
    id String the request id
    white_pov_evals [Double] length = plies + 1; [0] is the start position and [i + 1] is the position after ply i
    engine.name String the engine's own id name line from the UCI handshake
    engine.version String parsed from that name: the first digit-bearing token onward, joined by spaces ("Stockfish 18" → "18"); empty when absent
    engine.options [String: String] the setoption values this session applied

    engine.options always carries Threads and Hash. It also carries nnue — the required NNUE sha256s, sorted and joined with + — but only when the in-process engine is used. MultiPV is re-sent before every search and is deliberately not recorded there.

    Evals are always oriented to White: positive means White is better regardless of whose turn it is. Forced mates flatten to ±100000, the app's sentinel; a terminal checkmate position is filled by the driver as -100000 from the mover's point of view and converted to White POV by the kernel. Stalemate fills as 0.

    Flags¶

    Flag Meaning Default
    --engine-path <path> drive an external UCI binary over stdin/stdout pipes the in-process SwiftStockfish the app ships — not a system or Homebrew Stockfish
    --nets-dir <dir> NNUE directory for the in-process engine <repo>/Fianchetto/Resources, located by walking five parents up from #filePath
    --threads <n> engine Threads; must parse as an Int ≥ 1 max(1, ProcessInfo.processInfo.activeProcessorCount / 2)

    There is no --hash flag. Hash follows from threads, exactly as the app derives it:

    threads >= 4 -> Hash 256 MB
threads >= 2 -> Hash 128 MB
otherwise    ->  Hash 64 MB

    A --nets-dir that fails StockfishNetworkLoader.requiredNetworksSatisfied(in:) is rejected with a message naming the required filenames, and any unrecognized argument is a hard error.

    The engine session¶

    The per-position protocol is the app's, step for step, with the budgets it uses:

    handshake (once)
    "uci" -> capture `id name` / `id author` until "uciok"      budget 20 s
    setoption name Threads value <n>
    setoption name Hash value <mb>
    "isready" -> "readyok"                                      budget 20 s

pre-run barrier (ONCE per process, not per game — the transposition table
deliberately carries across games of one run)
    "stop" + "isready"                                          budget 30 s
    "ucinewgame" + "isready"                                    budget 30 s

per position
    setoption name MultiPV value 2
    position fen <Position.stockfishSafeFEN>
    go movetime <ms>
    safety timeout = max(30, movetime / 1000 * 4) seconds       (integer division)

    The info accumulation rule is the subtle part, and it is the app's rule verbatim:

    a line must carry a score to be considered at all
a pv-less line never displaces a pv-bearing entry at the same MultiPV rank
a score-bearing pv-less line still fills an empty slot
    -> this is what makes terminal `info depth 0 score mate 0` work

"bestmove" ends the search; "bestmove (none)" parses to nil and becomes ""
rank-1 score presence still gates the result inside AnnotationKernel.extractEval

    On a safety timeout the CLI sends stop, drains that search's terminal bestmove with a 5-second budget, and returns nil — which makes AnnotationDriver abort the sweep, exactly like the app's "engine stopped responding" path.

    Failure semantics¶

    Failure Effect
    unparseable line {"error": …}, stream continues
    illegal UCI move, unparseable PGN, no moves, neither input field {"id", "error"} for that game, stream continues
    the engine stops responding {"id", "error": "engine stopped responding"}, remaining stdin lines are drained without processing, process exits 1

    Worked example¶

    printf '%s\n' \
  '{"id": "scholars-mate", "uci_moves": ["e2e4","e7e5","d1h5","b8c6","f1c4","g8f6","h5f7"], "movetime_ms": 120}' \
  | .build/debug/fianchetto-cli annotate --threads 1

    {"engine":{"name":"Stockfish 18","options":{"Hash":"64","Threads":"1","nnue":"37f18f62…+c288c895…"},"version":"18"},"id":"scholars-mate","white_pov_evals":[43,35,35,-59,-40,-46,100000,100000]}

    Seven plies in, eight evals out. The mate-in-one after ply 6 and the checkmate position itself both pin to +100000; the fool's-mate mirror (f2f3 e7e5 g2g4 d8h4) pins to -100000. The nnue sha256s are elided above for width — the real line carries them in full.

    Seam provenance¶

    Linked — everything that decides a number:

    Behavior Kit surface
    the eval sweep, including the terminal-position fill and abort-on-failure AnnotationDriver.collectEvals(positions:evaluator:)
    checkmate -100000 / stalemate 0 sentinels AnnotationKernel.terminalEval(for:)
    rank-1/rank-2 resolution, mate → ±100000, nil when rank 1 is scoreless AnnotationKernel.extractEval(fromRankedInfos:bestMoveUCI:)
    movetime / thoroughness policy AnnotationKernel.annotateMovetime(batch:thoroughness:)
    engine-POV → White-POV conversion AnnotationKernel.whitePovEvals(_:startIsWhite:)
    FEN sanitization, UCI/PGN parsing, info parsing ChessCore Position.stockfishSafeFEN, UCIParser, Game.loadPGN, UCIOutputParser
    the engine and its NNUE manifest SwiftStockfish StockfishEngine, StockfishNetworks

    Mirrored — the UCI session plumbing only (UCIAnnotationSession.swift): handshake, option application, the pre-run barrier, the accumulation rules above, the safety timeout, and a generation-guarded line mailbox so a stale timer can never resume a later wait. The app's EngineManager lives in the app target, is @MainActor and @Observable-coupled, and is entangled with SwiftData, UserDefaults, thermal gates, and stream leases, so an SPM executable cannot import it.

    PositionEvaluator conformance is the load-bearing seam: the CLI's session implements evaluate(fen:) async -> AnnotationEval?, which is what lets the kit's own sweep drive it.

    // What the CLI does, in kit terms:
let positions = [game.startPosition] + game.mainLine.map(\.positionAfter)
guard let evals = await AnnotationDriver.collectEvals(
    positions: positions,
    evaluator: session           // any PositionEvaluator
) else { /* engine stopped responding */ return }

let whitePovEvals = AnnotationKernel.whitePovEvals(
    evals,
    startIsWhite: game.startPosition.activeColor == .white
)

    Intentional, output-neutral differences from the app: searches are strictly sequential (no stale-bestmove bookkeeping needed); no MultiPV startup seed, since annotation re-sends MultiPV 2 before every search anyway; no thermal or background pause gate and no persistence; thoroughness comes from the request instead of UserDefaults; bestmove (none) ends the search immediately; and zero-move or unparseable games emit an explicit error line instead of being stamped unevaluable.
