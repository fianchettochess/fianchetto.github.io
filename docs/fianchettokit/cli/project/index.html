    project¶

    Replays one account pool's chronological game sequence through the serving-side strength projection — the Kalman tracker, the personalized offset calibrator, and the Chess.com anchored per-game projection — wired in exactly the order StatsKernel.eloPoints wires them. This is the command that reproduces the number the app charts.

    One run models exactly one account pool

    A pool is one provider × account × speed group. The app never shares a tracker or a calibrator across pools, and neither should you: feed one pool per process, oldest game first. Grouping — and the app's decision to skip correspondence pools entirely — stays with the caller.

    stdin¶

    One JSON object per line, in chronological order.

    Field Type Required Default Meaning
    id String yes — echoed on the response line
    performance object or null no absent the game's Elo estimate; absent or null marks an unannotated game
    actual_rating Int or null no null the provider's rating tag for this game

    performance members:

    Member Type Required Default Meaning
    elo Double yes — the point estimate
    ci_low / ci_high Double yes — must satisfy ci_low <= elo <= ci_high
    accuracy Double yes — 0–100; part of the projection validity gate
    sample_moves Int yes — this side's move count; sets the evidence weight
    used_maia Bool no false keys which residual bucket this game calibrates

    The five required members are exactly the fields estimate emits, so building the request is a rename and a wrap.

    stdout¶

    Only annotated games produce a line. An unannotated game emits nothing at all; it still advances the anchor through projectionCalibrator.observe(actualRating:), and only when the pool personalizes to Chess.com.

    Field Type Meaning
    id String the request id
    strength_mean Double the charted number for this game
    strength_ci68 [Double] [lo, hi]
    strength_ci95 [Double] [lo, hi]
    calibration String "lichessEquivalent" / "chessComCalibrating" / "chessComPersonalized"
    calibration_sample_count Int labels behind the offset
    uses_empirical_intervals Bool whether the interval came from conformal errors rather than the propagated form
    projection object the anchored per-game dot — the key is absent until the calibrator warms up

    projection members: anchor, mapped_performance, evidence_weight, mean, interval68 [lo, hi], interval95 [lo, hi], offset, sample_count, used_maia.

    strength_mean is the slow posterior for the account; projection.mean is this game's "played like" dot, anchored on the most recent strictly earlier rating. They are different numbers answering different questions, and the command emits both.

    Flags¶

    Flag Meaning Default
    --source <s> the provider for this pool; lowercased before comparison "chesscom"

    Only chesscom enables personalization: personalizesToChessCom = (source == "chesscom"). Any other value disables both Chess.com paths, which means the personalized offset is never applied, no projection is ever emitted, no label is ever observed, and every line reports calibration: "lichessEquivalent".

    Wiring order¶

    The order is the whole point of the command, and step 6 must come last:

    per pool
    tracker  = StrengthTracker(priorMean: 1500, priorSigma: 300)
    local    = PersonalizedStrengthCalibrator()
    proj     = ChessComGameProjectionCalibrator()

per game (strict prequential)
    unannotated -> proj.observe(actualRating:) only; NO output line
    1. projection = proj.projection(for: performance)      // strictly earlier ratings
    2. tracker    = tracker.updated(with: performance)
    3. personalized = local.prediction(baseStrength: tracker.posteriorMean,
                                       baseSigma:    tracker.posteriorSigma)
    4. select displayed mean / CI68 / CI95 / calibration label
    5. emit the point
    6. local.observe(baseStrength:actualRating:personalizedPrediction:)
       proj.observe(actualRating:rawPerformanceElo:usedMaiaRefinement:projection:)

    Neither projection(for:) nor prediction(baseStrength:baseSigma:) takes a current-rating parameter, so this game's label physically cannot leak into its own estimate. Observing before emitting would silently turn an honest forecast into a fit.

    Step 4 is a two-branch selection:

    Condition mean / intervals calibration calibration_sample_count uses_empirical_intervals
    a personalized prediction exists its mean, interval68, interval95 chessComPersonalized the prediction's count the prediction's flag
    Chess.com pool, still warming up tracker.posteriorMean, tracker.ci, mean ± 1.96σ chessComCalibrating the local calibrator's sampleCount false
    any other provider the same tracker values lichessEquivalent the same false

    Calibrator constants¶

    Constant PersonalizedStrengthCalibrator ChessComGameProjectionCalibrator
    residual window 20 20
    minimum samples before answering 20 20
    forecast-error window 50 100
    minimum samples for empirical intervals 20 20

    The 20-label warm-up is directly observable in the output: calibration flips from chessComCalibrating to chessComPersonalized at exactly the 20th observed label.

    Projection-specific constants:

    weight            = 0.60 * sample_moves / (sample_moves + 15.0)    // 30 moves -> 0.40
mappedPerformance = clamp(elo + pathOffset, 100, 3500)
weightedDelta     = weight * (mappedPerformance - anchor)
cappedDelta       = clamp(weightedDelta, -250.0, +250.0)
mean              = clamp(anchor + cappedDelta, 100, 3500)

propagated interval arms (fewer than 20 strictly earlier projection errors)
    offsetStandardError = 1.2533 * max(50.0, 1.4826 * MAD) / sqrt(n)
    lowerSigma = sqrt((elo - ci_low)² + offsetStandardError²)
    upperSigma = sqrt((ci_high - elo)² + offsetStandardError²)
    bound      = mean ± multiplier * weight * sigma      // 1 for 68%, 1.96 for 95%

empirical interval arms (>= 20 strictly earlier projection errors) — conformal
    half = the finite-sample quantile of the sorted absolute errors

    Residuals and forecast errors are kept in separate buckets keyed on used_maia, so a partially backfilled pool can never calibrate one serving path with the other path's residuals.

    Errors¶

    A performance violating ci_low <= elo <= ci_high emits {"id", "error"} and is skipped without disturbing any state. Unparseable lines emit an id-less error and the stream continues.

    Worked example¶

    A pool of identical games — every one estimated at 1600 ± 100 over 30 moves, against a steady Chess.com rating of 1520 — isolates what the calibrators do:

    for i in $(seq 1 22); do
  printf '{"id":"g%d","performance":{"elo":1600,"ci_low":1500,"ci_high":1700,"accuracy":79.8,"sample_moves":30,"used_maia":false},"actual_rating":1520}\n' "$i"
done | .build/debug/fianchetto-cli project --source chesscom

    The first game, with the pool at its 1500/300 prior:

    {"calibration":"chessComCalibrating","calibration_sample_count":0,"id":"g1","strength_ci68":[1495.2471117358514,1685.2406931421974],"strength_ci95":[1404.0501926608056,1776.4376122172432],"strength_mean":1590.2439024390244,"uses_empirical_intervals":false}

    No projection key: the anchored calibrator has no residual window yet. After the 20th label, both change:

    {"calibration":"chessComPersonalized","calibration_sample_count":20,"id":"g21","projection":{"anchor":1520,"evidence_weight":0.4,"interval68":[1479.609218653262,1560.390781346738],"interval95":[1440.8340685603935,1599.1659314396065],"mapped_performance":1520,"mean":1520,"offset":-80,"sample_count":20,"used_maia":false},"strength_ci68":[1438.8188876120516,1601.3024517274134],"strength_ci95":[1360.826776836678,1679.2945625027871],"strength_mean":1520.0606696697325,"uses_empirical_intervals":false}

    evidence_weight is exactly 0.60 × 30 / (30 + 15) = 0.4, and offset is −80 — the median residual of a pool whose estimates ran 80 Elo above its Chess.com ratings. Because mapped_performance lands on the anchor, mean does too.

    Seam provenance¶

    Linked — StrengthTracker, PersonalizedStrengthCalibrator, ChessComGameProjectionCalibrator, and the EstimatedStrengthCalibration label enum are all the app's own types, called directly.

    Mirrored — only the wiring order above, which lives in StatsKernel.eloPoints in the kit's stats pass. The CLI reproduces the sequence line-cited; it does not reimplement any calculation.

    var tracker = StrengthTracker(priorMean: 1500, priorSigma: 300)
var trend = PersonalizedStrengthCalibrator()
var projections = ChessComGameProjectionCalibrator()

let projection = projections.projection(for: performance)
tracker = tracker.updated(with: performance)
let personalized = trend.prediction(
    baseStrength: tracker.posteriorMean,
    baseSigma: tracker.posteriorSigma
)
// … emit the point here, and only then observe this game's label.
trend.observe(
    baseStrength: tracker.posteriorMean,
    actualRating: actualRating,
    personalizedPrediction: personalized
)
projections.observe(
    actualRating: actualRating,
    rawPerformanceElo: performance.elo,
    usedMaiaRefinement: performance.usedMaiaRefinement,
    projection: projection
)
