    fianchetto-cli¶

    Six headless subcommands that expose Fianchetto's engine and analysis seams as stdin/stdout filters. Every command reads one JSON object per line and writes one JSON object per line, so an entire library can be annotated, scored, tracked, and projected from a shell pipeline.

    Why it exists¶

    The CLI is not a reimplementation. Its Package.swift depends on the same path-pinned packages the app builds against, so a number printed by fianchetto-cli is the number the app would have computed for that input:

    Dependency Path What it supplies
    FianchettoKit ../../FianchettoKit AnnotationKernel, AnnotationDriver, AccuracyAggregator, EloEstimator, StrengthTracker, both calibrators, MaiaBackfillPolicy, Maia3Encoding
    ChessCore ../../../ChessCore (sibling @ 7fdb0d1) Position, Game, PGNParser, UCIParser, UCIOutputParser, MoveQuality
    SwiftStockfish ../../../SwiftStockfish (sibling @ 05ec038) the in-process Stockfish the app ships, plus the NNUE manifest

    Two words are used throughout these pages, and they mean precise things:

    • Linked — the CLI calls the app's own shipped code. The behavior cannot drift, because there is only one copy.
    • Mirrored — the logic lives in the app target rather than a library, so an SPM executable cannot import it. It is reproduced in the CLI with file:line citations to the original.
    Command Linked Mirrored
    estimate everything numerical nothing (JSON shaping only)
    accuracy everything numerical nothing (JSON shaping only)
    track everything numerical nothing (JSON shaping only)
    project tracker + both calibrators the StatsKernel.eloPoints wiring order
    maia grid, conditioning, qualification, encoding, log-softmax the Core ML transport and the grid-sweep loop
    annotate kernel, driver, parsers, FEN sanitizer, engine, nets manifest, movetime policy, White-POV math the UCI session plumbing

    Only two commands mirror anything load-bearing, and both for the same reason: the app's EngineManager and MaiaEngine are @MainActor, @Observable-coupled, and entangled with SwiftData, UserDefaults, and thermal gates. Everything that decides a number still comes from the kit.

    Building and running¶

    The package is tools-only — swift-tools-version: 6.0, Swift 6 language mode, a macOS 15 floor inherited from FianchettoKit, one executable product. The app's own project is untouched.

    cd Tools/fianchetto-cli
swift build
.build/debug/fianchetto-cli <command> [options] < input.jsonl > output.jsonl

    Two defaults are resolved relative to #filePath — the annotate NNUE directory and the Maia model package, both under <repo>/Fianchetto/Resources. A binary copied away from this checkout must pass --nets-dir / --model-path.

    The commands¶

    Command Produces Wraps
    annotate per-ply White-POV centipawn evals the app's Stockfish annotation path
    estimate a per-game Elo performance + CI EloEstimator.estimate
    maia the 11-point Maia log-likelihood evidence vector MaiaBackfillPolicy + Maia3Encoding
    accuracy per-move losses, labels, and both accuracy aggregates AccuracyAggregator
    project the serving-side strength point for one account pool StatsKernel.eloPoints's wiring
    track the Kalman strength posterior after each game StrengthTracker

    The JSON-Lines protocol¶

    One JSONLines enum owns the whole contract, so all six commands behave identically at the stream level.

    stdin
    read with readLine, one request per line
    blank / whitespace-only line   -> skipped, no output
    decodes for this command       -> one response line
    fails to decode                -> {"error": "unparseable request line: <underlying>"}
                                      and the stream CONTINUES

stdout
    JSONEncoder outputFormatting = [.sortedKeys, .withoutEscapingSlashes]
    one object per line, in input order, flushed immediately
    keys are alphabetical (stable golden diffs)
    nil fields are omitted entirely, not written as null

stderr
    every human-readable diagnostic: engine identity, model load, ANE probe
    verdicts, self-test PASS/FAIL. Never mixed into stdout.

    Two consequences of "nil fields are omitted" are worth knowing before you write a consumer: an error line for a request whose id could not be read has no id key at all, and project's projection key is absent — not null — until the anchored calibrator has warmed up.

    A per-request failure is a data event, not a process event: the command emits {"id": …, "error": …} for that line and moves on. The one exception is annotate, where a wedged engine aborts the whole run (see that page).

    Because output is flushed per line and input order is preserved, the binary can be driven as a long-lived pipe rather than re-spawned per game — which matters most for annotate (one engine handshake per run) and maia (one model compile per run).

    Dispatch, help, and exit codes¶

    Situation Output Exit
    no arguments global help on stdout 2
    first argument is -h, --help, or help global help on stdout 0
    unknown command token fianchetto-cli: unknown command '<token>' on stderr, then global help 2
    --help / -h anywhere after the command token that command's usage 0
    the command throws fianchetto-cli <name>: <error> on stderr 1
    normal completion the response stream 0

    The global help pads each command name to 12 characters before its abstract, and the registry order is the listing order: annotate, estimate, maia, accuracy, project, track.

    Composing the commands¶

    Hop Flows through untouched Needs reshaping
    annotate → accuracy id, white_pov_evals add start_is_white, color
    annotate → estimate id, white_pov_evals add start_is_white, color, clock fields
    estimate → track the whole object (extra keys are ignored) nothing
    estimate → project elo, ci_low, ci_high, accuracy, sample_moves wrap as performance, add actual_rating
    maia → estimate maia_log_likes or build a maia_evidence object from maia_log_likes + positions_scored + opponent_conditioning 
    fianchetto-cli annotate < games.jsonl       > evals.jsonl
# join each row with its start_is_white / color / clock fields first
fianchetto-cli estimate < estimate-in.jsonl > estimates.jsonl
fianchetto-cli track    < estimates.jsonl   > posterior.jsonl

    track and project both consume an ordered sequence: oldest game first. project additionally models exactly one account pool per run — grouping by provider × account × speed stays with the caller, exactly as StatsKernel does it.

    Adding a subcommand¶

    The subcommand seam is four requirements and one array. This is the entire protocol:

    protocol CLICommand: Sendable {
    /// The subcommand token, e.g. `"annotate"` in `fianchetto-cli annotate`.
    static var name: String { get }
    /// One-line description for `fianchetto-cli --help`.
    static var abstract: String { get }
    /// Usage text (flags + stdin/stdout contract) for `<command> --help`.
    static var usage: String { get }
    /// Run with the arguments AFTER the subcommand token.
    static func run(arguments: [String]) async throws
}

var commandRegistry: [any CLICommand.Type] {
    [
        AnnotateCommand.self,
        EstimateCommand.self,
        MaiaCommand.self,
        AccuracyCommand.self,
        ProjectCommand.self,
        TrackCommand.self,
    ]
}

    Adding a command is one new file plus one line in commandRegistry. Main needs no change: it already handles dispatch, --help, and mapping a thrown error to exit code 1.

    The shared I/O helpers are the rest of the skeleton:

    struct ExampleCommand: CLICommand {
    static let name = "example"
    static let abstract = "one line, shown in the global help table"
    static let usage = "USAGE: fianchetto-cli example < in.jsonl > out.jsonl\n…"

    struct Request: Decodable {
        let id: String
        let whitePovEvals: [Double]
        enum CodingKeys: String, CodingKey {
            case id
            case whitePovEvals = "white_pov_evals"   // explicit snake_case
        }
    }

    struct Response: Encodable { let id: String; let value: Double }

    static func run(arguments: [String]) async throws {
        guard arguments.isEmpty else {
            throw CLIError("unknown option '\(arguments[0])' (see: fianchetto-cli example --help)")
        }
        await JSONLines.forEachRequest(Request.self) { result in
            switch result {
            case .failure(let failure):
                JSONLines.emitRawError(id: nil, message: "unparseable request line: \(failure.underlying)")
            case .success(let request):
                JSONLines.emit(Response(id: request.id, value: 0))
            }
        }
    }
}

    Conventions the six existing commands all follow:

    • Codable wire types with explicit snake_case CodingKeys — never rely on a key-decoding strategy, so the contract is readable in one place.
    • An options loop that rejects unknown flags by name, pointing at fianchetto-cli <name> --help.
    • Per-line error isolation through JSONLines.emitRawError; only an unrecoverable process-level failure throws.
    • JSONLines.note for diagnostics — stdout stays machine-readable.
    • A self-test or an always-on sanity oracle wherever the seam permits one: estimate has --self-test (15 golden-parity checks), and maia runs a fail-closed start-position probe on every invocation.
