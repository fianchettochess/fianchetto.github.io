    track¶

    Runs the app's Bayesian StrengthTracker over an ordered sequence of per-game Elo estimates and emits the posterior after each game. It is the smallest of the six commands: a Kalman update, a JSON line, no calibration.

    stdin¶

    One JSON object per line, in game order. The output of estimate is directly pipe-compatible — its extra keys are ignored by the decoder.

    Field Type Required Default Meaning
    id String yes — echoed on the response line
    elo Double yes — this game's point estimate
    ci_low Double yes — must satisfy ci_low <= elo
    ci_high Double yes — must satisfy elo <= ci_high

    Accuracy and move count are not read by the update, so they need not be supplied; the command fills the carrier with zeros for them.

    stdout¶

    One JSON object per line — the posterior after that game.

    Field Type Meaning
    id String the request id
    posterior_mean Double the strength estimate after this game
    posterior_sigma Double the posterior standard deviation
    ci68_low / ci68_high Double mean ± 1σ

    Flags¶

    Flag Meaning Default Where the default comes from
    --prior-mean <x> initial Elo belief 1500 the app's per-pool prior in StatsKernel
    --prior-sigma <x> initial uncertainty 300 the same seeding call
    --process-tau <x> process noise per game 50 StrengthTracker's own default

    Each value must parse as a Double or the command errors. τ = 50 corresponds to roughly 150 Elo of drift over 9 games, which is the app's assumption about how fast real strength moves.

    The update¶

    predVariance      = posteriorSigma² + processTau²
ciHalfWidth       = (ci_high - ci_low) / 2
obsVariance       = max(1.0, ciHalfWidth²)                 // guards a zero-width CI
posteriorVariance = 1 / (1/predVariance + 1/obsVariance)
posteriorMean     = posteriorVariance * (mean/predVariance + elo/obsVariance)
posteriorSigma    = sqrt(posteriorVariance)
ci68              = posteriorMean ± posteriorSigma

    The observation variance is the squared CI half-width, which is why nothing else needs a weighting scheme: everything that widens an interval upstream — few moves, OTB classical, a below-floor estimate — automatically shrinks that game's influence on the posterior. A game with a ±400 interval moves the mean far less than one with a ±100 interval, without either command knowing about the other.

    Errors¶

    A row violating ci_low <= elo <= ci_high emits {"id", "error"} and is skipped without disturbing the posterior. Unparseable lines emit an id-less error and the stream continues.

    Worked example¶

    Two identical games, from the default 1500 / 300 prior:

    printf '%s\n' \
  '{"id":"g1","elo":1600,"ci_low":1500,"ci_high":1700}' \
  '{"id":"g2","elo":1600,"ci_low":1500,"ci_high":1700}' \
  | .build/debug/fianchetto-cli track

    {"ci68_high":1685.2406931421974,"ci68_low":1495.2471117358514,"id":"g1","posterior_mean":1590.2439024390244,"posterior_sigma":94.9967907031729}
{"ci68_high":1668.6391902089251,"ci68_low":1522.2956539837098,"id":"g2","posterior_mean":1595.4674220963175,"posterior_sigma":73.17176811260755}

    Working the first line by hand: predVariance = 300² + 50² = 92 500, obsVariance = 100² = 10 000, so posteriorVariance = 1 / (1/92 500 + 1/10 000) = 9 024.39… and posteriorMean = 9 024.39… × (1500/92 500 + 1600/10 000) = 1590.2439…. The posterior sits far closer to the observation than to the prior because the prior is much more diffuse; the second game moves it only 5 more Elo, while sigma keeps falling.

    The whole point of --prior-mean / --prior-sigma is replaying a pool that is already warm: seed with a previous run's posterior_mean and posterior_sigma and the continuation is identical to having processed the earlier games in the same run.

    Seam provenance¶

    Fully linked to StrengthTracker.updated(with:). The tracker is a value type with pure value semantics — updated(with:) returns a new tracker and leaves the receiver alone — so the command's entire state is one var. The only CLI-original code is constructing the GamePerformance carrier, where accuracy, sampleMoves, and belowCalibrationFloor are inert placeholders because the Kalman update reads only elo and ci.

    var tracker = StrengthTracker(priorMean: 1500, priorSigma: 300, processTau: 50)

for performance in performancesInGameOrder {
    tracker = tracker.updated(with: performance)
    tracker.posteriorMean
    tracker.posteriorSigma
    tracker.ci              // 68%: mean ± 1σ
}
