    maia¶

    Runs the app's Maia backfill inference path headless: for one player in one game, it emits the 11-point Elo-grid log-likelihood vector that the v4.1 ensemble consumes as evidence. Policy and math are linked kit code; only the Core ML transport is mirrored.

    stdin¶

    One JSON object per line.

    Field Type Required Default Meaning
    id String yes — echoed on the response line
    uci_moves [String] one of the two — moves from the standard start position
    pgn String one of the two — a PGN game; headers optional
    color String yes — "white" or "black" — which side is the scored player
    provider String yes — e.g. "lichess", "chesscom"; decides opponent conditioning
    opponent_rating Int or null no null the opponent's provider rating

    Both input kinds are normalized to SAN move text before parsing, so they ride the identical path: uci_moves are replayed through UCIParser.uciToMove + Game.apply and re-emitted as their recorded SAN notations; pgn goes through PGNParser.parse and then parseMainLineSnapshot.

    The parsed start position must equal Position.initial(). Non-standard starts are rejected, matching the kit's SetUp / FEN / variant eligibility gate.

    stdout¶

    Field Type Meaning
    id String the request id
    maia_log_likes [Double] 11 entries, one per grid point — or [] when no owner move qualified
    positions_scored Int qualifying owner positions; 0 in the empty case
    opponent_conditioning String "exact-lichess-opponent" or "neutral-lichess-1500"
    opponent_elo Double the elo_oppo value actually fed to the network

    The terminal empty shape mirrors the app's "no qualifying owner moves" receipt: an empty vector with count 0, not an error. The conditioning fields are still reported, because they are resolved from the provider and rating before any position is scored.

    Flags¶

    Flag Meaning Default
    --model-path <path> the Maia3CoreML.mlpackage to load <repo>/Fianchetto/Resources/Maia3CoreML.mlpackage, located by walking five parents up from #filePath
    --compute-units <u> cpuOnly | cpuAndNeuralEngine | all | gated; any other value is a hard error cpuOnly, chosen for determinism

    gated mirrors the app's MaiaComputeUnitGate: load a candidate model under cpuAndNeuralEngine, run the sanity probe, use the ANE only on a pass and fall back to cpuOnly otherwise, logging the verdict to stderr. Unlike the app, the CLI re-probes fresh on every run instead of caching a verdict in UserDefaults — a CLI process should not write the app's persisted verdict. The app's own default is that gated verdict; the CLI's is cpuOnly so repeated runs are bit-identical.

    Decision rules¶

    Three policy decisions determine the output, and all three are kit calls.

    The grid. MaiaBackfillPolicy.eloGrid is 11 points read at runtime from the v4.1 ensemble calibration artifact, falling back to the literal [600, 800, 1000, 1200, 1400, 1600, 1800, 2000, 2200, 2400, 2600].

    Opponent conditioning. The exact opponent rating is used only under one narrow condition:

    MaiaBackfillPolicy.scoringContext(...)
    normalized provider == "lichess"
      AND opponent rating present
      AND rating in trainedOpponentEloRange = 400...3200
        -> elo_oppo = that rating,  conditioning = exact-lichess-opponent
    every other case
        -> elo_oppo = neutralOpponentElo = 1500,
           conditioning = neutral-lichess-1500

    That is not a provider preference; the v4.1 collector only ever admitted Lichess opponent ratings, so a Chess.com rating would be a number from a different scale. The conditioning label travels with the evidence and decides which serving path estimate reports.

    Which positions count.

    MaiaBackfillPolicy.qualifiesForInference(plyIndex:legalMoveCount:)
    plyIndex >= 8  AND  legalMoveCount > 2

the player-color overload additionally requires the scored side to be to move

    Before any inference, two encoding guards must hold for every qualifying position, or the whole game is rejected: tokens.count == 768 (64 × 12) and policyIndex in 0..<4352.

    The sweep. One batch-1 inference per (grid point × position), accumulated in grid order:

    for eloSelf in eloGrid:                 // 11 outer steps
    for each qualifying position:
        logits = model(tokens, elo_self: eloSelf, elo_oppo: contextElo)
        sums[gridIndex] += logSoftmaxAt(logits, idx: policyIndex)

a single non-finite value aborts the ENTIRE vector — partial evidence is never
emitted

    The whole sweep runs inside a detached userInitiated task, like every Core ML call in the app.

    The always-on sanity oracle¶

    maia has no --self-test, because it does something stronger: a fail-closed probe runs on every invocation, against the resolved model path, before any game is scored.

    one inference on the initial position at elo_self = elo_oppo = 1200
    top decoded move must be e4 or d4          with probability > 0.30
    when a value head is present:              win < 0.85 and loss < 0.85

    Decoding goes through the linked Maia3Encoding.decodeOutput. A missing model file, a failed probe, an invalid encoding, or a missing logits_move output each raise a named error and stop the run — a wrong or silently mis-compiled model can never produce evidence.

    Worked example¶

    printf '%s\n' \
  '{"id":"italian-white-lichess","uci_moves":["e2e4","e7e5","g1f3","b8c6","f1c4","f8c5","c2c3","g8f6","d2d4","e5d4","c3d4","c5b4","b1c3","f6e4"],"color":"white","provider":"lichess","opponent_rating":1650}' \
  '{"id":"italian-black-chesscom","uci_moves":["e2e4","e7e5","g1f3","b8c6","f1c4","f8c5","c2c3","g8f6","d2d4","e5d4","c3d4","c5b4","b1c3","f6e4"],"color":"black","provider":"chesscom","opponent_rating":1650}' \
  '{"id":"too-short-no-qualifying","uci_moves":["e2e4","e7e5","g1f3","b8c6","f1c4","f8c5"],"color":"white","provider":"lichess","opponent_rating":2000}' \
  | .build/debug/fianchetto-cli maia

    {"id":"italian-white-lichess","maia_log_likes":[-15.068658736499842,-13.45112097051431,…,-13.165787875335432],"opponent_conditioning":"exact-lichess-opponent","opponent_elo":1650,"positions_scored":3}
{"id":"italian-black-chesscom","maia_log_likes":[-16.71934077426711,-15.244745311102697,…,-8.88329170726237],"opponent_conditioning":"neutral-lichess-1500","opponent_elo":1500,"positions_scored":3}
{"id":"too-short-no-qualifying","maia_log_likes":[],"opponent_conditioning":"exact-lichess-opponent","opponent_elo":2000,"positions_scored":0}

    Three things to read off that output. The same 14-ply game scores 3 positions for either side, because only plies ≥ 8 with more than two legal moves qualify and only the scored side's moves count. The identical game conditions differently by provider: Lichess keeps the exact 1650, Chess.com falls back to the neutral 1500 prior. And the six-ply game produces the terminal empty shape rather than an error, while still reporting the conditioning it would have used.

    Model load and the probe verdict are written to stderr, so stdout stays a clean JSONL stream:

    maia: loading model at …/Maia3CoreML.mlpackage (compute units: cpuOnly)
maia: model loaded; resolved-path sanity probe passed; grid [600.0, 800.0, …]

    Seam provenance¶

    Linked — every policy and math decision:

    Behavior Kit surface
    the 11-point grid MaiaBackfillPolicy.eloGrid
    owner color, opponent conditioning, SetUp/FEN/variant gate MaiaBackfillPolicy.scoringContext(...)
    qualification and the qualifying walk MaiaBackfillPolicy.qualifiesForInference, qualifyingPositions(from:playerColor:)
    board tokens and policy index Maia3Encoding.encodeTokens(position:), Maia3Encoding.policyIndex(for:activeColor:)
    per-position log-likelihood logSoftmaxAt(_:idx:)
    decoding, in the sanity probe Maia3Encoding.decodeOutput(moveLogits:valueLogits:position:topK:)
    main-line snapshot parsing ChessCore PGNParser.mainLineSnapshot(fromMoveText:)

    Mirrored — the Core ML transport only (MaiaCoreMLSupport.swift), because MaiaCoreMLInputFactory, MaiaMultiArrayReader, and MaiaEngine live in the app target: Float16 [1, 64, 12] tokens plus [1] elo_self / elo_oppo (arm64 writes native Float16 storage, x86_64 falls back to MLMultiArray's indexed NSNumber conversion); a dtype-aware reader for the logits_move output, where only genuine Float32 takes the pointer fast path; the grid-sweep accumulation order; the ANE compute-unit gate; and the sanity oracle itself.

    The app's thermal pacing and 100 ms inter-slice breathers are omitted — a foreground CLI has no UI to protect, and pacing does not change the math. The CLI also names the scored side and provider directly instead of resolving them from collection usernames and PGN tags.
